# 5.3 奖励模型（Reward Model） — 题目与答案
> [⬅ 返回目录](../README_ZH.md) · 第 5 章：强化学习与后训练对齐（RLHF / DPO） · 共 16 题

**1. 为什么需要训练奖励模型？**

<details>
<summary>💡 查看答案</summary>

奖励模型（Reward Model, RM）是 RLHF 中连接"人类偏好"与"策略优化"的关键桥梁，其必要性体现在以下几个方面：

**1. 人类无法实时提供反馈**

RL 训练需要对**每一条生成的回复**（rollout）给出奖励信号。如果每次都要人工标注，仅一轮训练就需要对数十万条回复进行评分——这在时间和人力上完全不可行。奖励模型通过"一次训练、无限推理"，将人类偏好"固化"为可自动调用的评分函数。

**2. 奖励需要可微分以用于梯度优化**

PPO 等基于策略梯度的方法需要奖励信号来计算优势函数，间接影响参数更新。神经网络形式的奖励模型可以输出连续的标量分数，并与整体训练流程无缝集成。

**3. 泛化偏好到未见过的回复**

人类标注数据只覆盖了部分（prompt, response）对，而 RL 训练过程中模型会生成大量**未在标注数据中出现过的新回复**。奖励模型通过在标注数据上学习"偏好的规律"，能够对这些从未见过的回复给出合理评分，实现偏好的泛化。

**4. 稳定奖励信号**

直接用人类偏好投票作为奖励会引入大量噪声（标注者之间的不一致性）。经过训练的奖励模型对同一输入给出稳定的分数，降低了 RL 训练中的方差。

简言之，奖励模型是**人类偏好的可微分、可复用、可泛化的数字代理**，使大规模 RL 训练成为可能。

</details>

**2. 奖励模型是怎么训练的？**

<details>
<summary>💡 查看答案</summary>

奖励模型（RM）的训练流程包括：
1. **收集偏好数据**：使用初始模型生成多个回答，让人类标注者进行比较或打分。
2. **对偶对比训练**：奖励模型输出一个标量评分，通过对比不同回答的评分来训练模型。
3. **模型结构**：通常在预训练语言模型的基础上添加一个“Reward Head”。
4. **使用场景**：在强化学习阶段，奖励模型为生成的回答打分，作为奖励信号优化策略模型。

</details>

**3. 奖励模型的架构选择**

<details>
<summary>💡 查看答案</summary>

奖励模型通常**直接复用与待优化 LLM 相同（或相近）的预训练 Transformer 架构**，常见做法：

- 用 SFT 后的模型（或同规模的预训练基座）作为初始化，**替换/去掉语言模型头（LM head）**，在最后一层接一个**线性层输出标量**，将"预测下一个 token"的任务改为"预测整体回复的标量得分"。
- 通常取序列最后一个 token（或 EOS token）的隐藏状态经过线性投影得到奖励值。

**与最终优化的 LLM 的关系**：
- 二者共享相似的语言理解能力基础（往往使用相同的 tokenizer 和架构），这样 RM 才能准确理解策略模型生成内容的语义。
- RM 在 RL 阶段是**冻结的**，作为环境的一部分提供奖励信号，不参与梯度更新。
- RM 的规模一般不小于策略模型（有时更大），因为判别（区分好坏）的难度有时不亚于生成本身。

</details>

**4. RLHF 中的奖励模型（Reward Model）是如何训练的？**

<details>
<summary>💡 查看答案</summary>

奖励模型基于人类偏好数据训练：
1. 对同一 prompt，让模型生成两个或多个回答
2. 由人工标注员对这些回答进行偏好排序（选出更好的那个）
3. 将排序转化为偏好对 (chosen, rejected)，用 Bradley-Terry 模型建模偏好概率
4. 训练目标：最大化 chosen 回答得分高于 rejected 回答得分的概率
训练完成后，奖励模型可以对任意回答打分，为后续 PPO 训练提供奖励信号。

</details>

**5. RLHF 训练时，Reward Model 和 LLM 是同时训练还是先后训练，InstructGPT 论文里是如何训练 RM 的**

<details>
<summary>💡 查看答案</summary>

**Reward Model 和 LLM（策略模型）的训练顺序**：

整体上是**先后训练**，分为多个阶段：

1. **第一阶段：SFT**：在人工标注的高质量示范数据上对预训练模型进行监督微调，得到 SFT 模型；
2. **第二阶段：训练奖励模型（RM）**：使用人类对模型输出的偏好排序数据，训练一个独立的奖励模型；这一阶段的 RM 训练与策略模型的 RL 训练是**分离**的——RM 先单独训练完成并固定下来；
3. **第三阶段：RL 微调（PPO）**：以 SFT 模型为初始化（同时也作为参考模型），用**已经训练好且参数冻结**的 RM 为 PPO 训练提供奖励信号，对策略模型进行强化学习优化。

在 PPO 训练过程中，**RM 本身不再更新**（保持冻结），只有策略模型（actor）和价值模型（critic）在被训练。因此严格来说，"RM 训练"和"策略模型的 RL 训练"是**先后进行、不重叠**的两个阶段，而不是"同时训练"。

**InstructGPT 中 RM 的训练方式**：

1. **数据收集**：对于同一个 prompt，让模型（SFT 模型）生成**多个（如 4~9 个）候选回复**，由人类标注者对这些候选回复进行**排序**（从最好到最差）；

2. **训练目标——成对比较（Pairwise Comparison）**：将排序结果转换为成对的比较数据，即对于排序中的每一对 ($y_w$, $y_l$)（$y_w$ 排名优于 $y_l$），构造训练样本；

3. **损失函数（基于 Bradley-Terry 模型）**：

\[
loss(\theta) = -E[log \sigma(r_\theta(x, y_w) - r_\theta(x, y_l))]
\]

其中 $r_\theta$(x,y) 是奖励模型对 (prompt x, response y) 输出的标量分数，$\sigma$ 是 sigmoid 函数。该损失鼓励模型给"更受偏好的回复"打出比"较差的回复"更高的分数，差值越大、$\sigma$ 输出越接近1，损失越小。

1. **模型架构**：RM 通常基于与策略模型相同/相近的预训练模型架构，将最后一层的语言模型输出头替换为一个**输出标量的线性层**（在序列末尾的位置输出一个值），经过在偏好数据上的微调得到。

2. **处理同一 prompt 下多个比较对的方式**：由于一个 prompt 下的 K 个回复可以产生 C(K,2) 个比较对，InstructGPT 论文中**将同一个 prompt 下的所有比较对视为一个 batch 中的一个"样本组"**（而不是将每个比较对独立打散到不同 batch），这种做法在计算上更高效，也被发现有助于减轻过拟合。

**总结**：RM 和策略模型是**先后训练**（RM 训练完成并冻结后，再用于 PPO 训练策略模型），不是同时优化；InstructGPT 中 RM 基于"人类对多个候选回复的排序"数据，通过**成对比较的 Bradley-Terry 损失（log-sigmoid of reward difference）**训练得到。

</details>

**6. 在RM训练阶段，我们通常收集的是成对比较数据，而不是让人类标注者直接给回复打一个绝对分数。你认为这样做的主要优势和潜在的劣势分别是什么？**

<details>
<summary>💡 查看答案</summary>

在训练奖励模型（RM）时，采用成对比较（Pairwise Comparison）而非绝对评分（Absolute Scoring）是业界的标准做法，这背后有深刻的认知科学和实践考量。


主要优势：


1. 降低认知负荷，提升标注一致性： 让人在多个选项中选出“哪个更好”远比给一个选项打一个精确的绝对分数（如1到10分）要容易和直观。不同标注者对于“7分”的定义可能天差地别，但对于“A比B更好”的判断则更容易达成共识，这大大提升了数据的标注者间一致性（Inter-rater agreement）。
2. 提供更精细的信号： 比较数据能够捕捉到细微的偏好差异。两个回答可能在绝对分数上都是“好”的（比如都是8分），但比较数据可以明确指出其中一个比另一个“稍微好一点”，这种相对信号对于模型学习更精细的偏好至关重要。
3. 数据分布归一化： 绝对分数很容易受到标注者个人情绪、打分尺度、疲劳度等因素影响，导致分数分布不均或存在偏差。而比较数据天然地将问题转化为一个标准化的二元分类或排序任务，模型只需要学习相对关系，对绝对尺度不敏感。

潜在的劣势：


1. 数据效率可能较低： 每次比较只产生1比特的信息（A>B或B>A）。如果要对K个回答进行完整排序，需要进行 $O(K^2)$ 次比较，而绝对评分只需要K次。这意味着要达到同等的信息量，可能需要更多的标注工作。
2. 可能出现不传递性（Intransitivity）： 人类偏好有时不满足传递性，即可能出现“A比B好，B比C好，但C比A好”的循环偏好。这会给奖励模型带来噪声和矛盾的训练信号。
3. 信息不完整： 比较数据只告诉我们相对好坏，但没有说明“好多少”或“差多少”。两个回答的差距可能微乎其微，也可能天差地别，但成对比较无法直接体现这种差异的幅度。

</details>

**7. 奖励模型的设计至关重要。它的模型架构通常如何选择？它与我们最终要优化的LLM是什么关系？在训练奖励模型时，常用的损失函数是什么？请解释其背后的数学原理（例如，可以结合Bradley-Terry模型来解释）。**

<details>
<summary>💡 查看答案</summary>

模型架构选择： 奖励模型（RM）的架构通常选择与要优化的LLM相同或非常相似的架构，但有两点关键区别：

1. RM的初始化权重通常来自于第一阶段训练好的SFT模型。这样做可以保证RM对指令和语言风格有很好的基础理解。
2. RM的最后一层（通常是预测下一个token的softmax层）被替换为一个回归头（Regression Head），这个头通常是一个线性层，用于输出一个标量（scalar），即奖励分数。

与最终LLM的关系： RM是最终LLM的效用函数代理（proxy for the utility function）。它在RLHF流程中扮演着人类偏好的模拟器的角色。最终的LLM（即策略）的目标就是生成能够让这个RM给出高分数的回答。因此，RM的质量直接决定了最终LLM对齐的天花板。如果RM有缺陷或偏见，LLM在优化过程中就会“奖励作弊”，利用这些缺陷来获得高分，而不是真正生成人类喜欢的回答。


常用的损失函数： RM训练时最常用的损失函数是成对排序损失（Pairwise Ranking Loss）。其目标是，对于任意一个给定的prompt，RM赋予“胜出回答”（ $y_w$ ）的分数 $r(y_w)$ 应该高于赋予“落败回答”（ $y_l$ ）的分数 $r(y_l)$ 。


数学原理解释（结合Bradley-Terry模型）： Bradley-Terry模型是一个用于描述成对比较结果概率的模型。它假设每个个体（在这里是每个回答）都有一个潜在的“实力”分数（即奖励分数 $r$ ）。回答 $y_w$ 优于 $y_l$ 的概率 $P(y_w > y_l)$ 可以用一个logistic函数（即sigmoid函数 $\sigma$ ）来建模：

\[P(y_w > y_l | x) = \sigma(r(y_w | x) - r(y_l | x))\]


其中 $x$ 是prompt， $r(y|x)$ 是RM给出的分数。这个公式的直观意义是，两个回答的奖励分数差距越大，我们越确信其中一个比另一个好。


在训练时，我们的目标是最大化我们观察到的人类偏好数据的对数似然。对于一个偏好数据 $(y_w, y_l)$ ，我们希望最大化 $P(y_w > y_l)$ 的对数。因此，损失函数就是其负对数似然：

\[Loss = -\log(P(y_w > y_l | x)) = -\log(\sigma(r(y_w | x) - r(y_l | x)))\]


这个损失函数会惩罚那些RM给分错误（即 $r(y_l) > r(y_w)$ ）的情况，并驱动RM学习到一个能够准确反映人类偏好排序的打分函数。

</details>

**8. 训练 RM 时，无论是 InstructGPT 还是 DPO，为什么 loss 里有 log 和 sigmoid 函数？直接用 reward 相减不行吗？**

<details>
<summary>💡 查看答案</summary>

**为什么使用 sigmoid 和 log（即 Bradley-Terry 模型）**：

1. **将"分数差异"转化为"偏好概率"——建模人类偏好的随机性**：

人类的偏好判断本身具有一定的随机性/不确定性——给定两个回复 A 和 B，即使 A 客观上略好于 B，标注者也不是 100% 一定会选择 A（可能 90% 的标注者选 A，10% 选 B，尤其当两者质量接近时）。Bradley-Terry 模型假设：

\[
P(A 优于 B) = \sigma(r(A) - r(B)) = 1 / (1 + exp(-(r(A) - r(B))))
\]

即"A 被偏好的概率"是两者奖励差值经过 sigmoid 映射后的结果——**差值越大，A 被偏好的概率越接近 1；差值为 0 时，被偏好的概率为 0.5（完全不确定）；差值为负时，概率小于 0.5**。这种建模方式自然地将"连续的奖励差异"转化为"[0,1] 区间内的概率"，与人类标注数据的本质（一个离散的、带有不确定性的选择）相匹配。

1. **log 用于将"概率的最大化"转化为可优化的损失（最大似然估计）**：

给定标注数据"A 被偏好于 B"，我们希望模型给出的 P(A优于B) 尽可能接近 1（即模型应该"相信"标注者的选择），这是一个标准的**最大似然估计**问题：最大化 log P(A优于B) = log $\sigma$(r(A)-r(B))，对应的损失就是其负数 -log $\sigma$(r(A)-r(B))。这与逻辑回归（logistic regression）的损失函数形式完全一致——本质上是把"哪个回复更好"建模为一个**二分类问题**，分类的"logit"就是两个奖励的差值。

**为什么不能直接用 reward 相减（如最小化 -（r(A)-r(B)) 或类似的 margin loss）**：

1. **缺乏概率解释和合理的"饱和"机制**：如果直接用 -(r(A)-r(B)) 作为损失（即希望差值尽可能大），这个损失**没有上界/没有自然的"满足点"**——模型会被驱使着让 r(A)-r(B) 无限增大，可能导致奖励值的尺度不受控制地增长，训练不稳定；而 sigmoid+log 形式的损失，当 r(A)-r(B) 已经足够大（$\sigma$(·)已经接近1）时，损失已经接近0，**梯度会自然衰减（饱和）**，不会继续无限制地拉大差值，这是更合理、更稳定的优化目标。

2. **与人类标注的"概率性"本质相匹配**：直接用奖励差值作为优化目标，相当于假设"标注者的选择是绝对确定、无噪声的"，但实际标注数据中存在大量"边界案例"（两个回复质量接近，标注存在一定随机性），Bradley-Terry 形式的损失通过 sigmoid 将这种不确定性纳入了模型，使得对于"难以区分"的样本对，模型不会被迫产生一个巨大的奖励差值（因为 sigmoid 在 0 附近的梯度是平滑的）。

3. **数值稳定性与梯度性质**：log-sigmoid 形式的损失（等价于 softplus 函数：-log $\sigma$(x) = log(1+exp(-x)) = softplus(-x)）具有良好的数值稳定性和平滑的梯度特性，是机器学习中广泛使用且经过充分验证的损失形式（与逻辑回归、二分类交叉熵一脉相承）。

4. **理论基础（与 RL 中的最优策略推导一致）**：Bradley-Terry 模型与 RLHF 的理论框架（奖励函数对应于某种"最优策略"下的对数概率比，这正是 DPO 推导的基础）有更紧密的数学联系，使得整个 RLHF/DPO 框架在理论上更加自洽。

**总结**：使用 sigmoid+log（即 Bradley-Terry 损失）的核心原因是**将"两个回复奖励值的差异"转化为符合人类标注数据本质（带有不确定性的概率性选择）的优化目标**，这种形式具有自然的概率解释、良好的梯度饱和特性和数值稳定性；直接用奖励差值相减缺乏这些性质，会导致训练目标"无界"且与标注数据的概率性本质不匹配，是不合适的损失设计。

</details>

**9. 成对比较 vs 绝对打分**

<details>
<summary>💡 查看答案</summary>

**优势**：
- **一致性更高**：人类对"哪个更好"的相对判断比给绝对分数更稳定、可靠，不同标注者间的标准差更小。
- **标注成本和认知负担更低**：比较两个选项比为单个回复打出一个精确的 1-10 分要容易得多。
- **天然适配 Bradley-Terry 模型**：成对偏好数据可以直接套用经典的偏好建模框架，理论基础成熟。

**潜在劣势**：
- **信息密度较低**：一次比较只能获得 1 bit 左右的信息（A 好还是 B 好），需要大量比较才能精确刻画偏好分布。
- **传递性假设可能不成立**：人类偏好可能存在非传递性（A>B, B>C，但 C>A），而 Bradley-Terry 假设的是一个全局一致的潜在分数。
- **难以表达"绝对质量"信息**：例如两个回复都很差，比较结果只能告诉模型"A 比 B 稍好"，但无法告诉模型"两者都不及格"。

</details>

**10. 介绍下 DPO 中的 BT 算法模型？**

<details>
<summary>💡 查看答案</summary>

Bradley-Terry（BT）模型是 DPO 和奖励模型训练的数学基础，是一种专门用于建模**成对比较（pairwise comparison）**中偏好概率的统计学框架。

**核心假设**：每个候选项（这里是每条回复 $y$）都拥有一个潜在的"实力分数"（即奖励 $r(x,y)$），两条回复 $y_w$（偏好）和 $y_l$（非偏好）相比，人类选择 $y_w$ 的概率由下式建模：
\[P(y_w \succ y_l | x) = \sigma(r(x, y_w) - r(x, y_l)) = \frac{e^{r(x,y_w)}}{e^{r(x,y_w)} + e^{r(x,y_l)}}\]
其中 $\sigma$ 是 sigmoid 函数。两个回复的奖励分数差越大，人类越确定地偏好奖励更高的那个。

**在奖励模型训练中的应用**：

最大化观测到的偏好数据的对数似然，损失函数为：
\[\mathcal{L}_{RM} = -\mathbb{E}_{(x,y_w,y_l)}[\log\sigma(r_\phi(x,y_w) - r_\phi(x,y_l))]\]
训练奖励模型 $r_\phi$ 使得 chosen 回复总是比 rejected 回复得分更高。

**在 DPO 中的应用**：

DPO 进一步推导出，RLHF 最优策略可以用 $\pi_\theta$ 和 $\pi_{ref}$ 的对数概率比来表达奖励：$r(x,y) = \beta \log(\pi_\theta(y|x)/\pi_{ref}(y|x)) + const$。将此代入 BT 模型，得到 DPO 的直接损失函数，完全绕开了显式奖励模型。

BT 模型的核心贡献是提供了一个**简洁、可训练的偏好概率模型**，使得"人类偏好哪条回复"这一主观判断被转化为可优化的数学目标。

</details>

**11. BT 模型的优缺点？**

<details>
<summary>💡 查看答案</summary>

**Bradley-Terry 模型的优点**：
- **数学简洁优雅**：通过一个实值"实力分数"完整建模成对比较概率，形式简单，有闭合的对数似然损失，易于用标准梯度下降优化；
- **结果一致性保证（Transitivity）**：BT 模型满足传递性——若 $A > B$ 且 $B > C$，则 $A > C$（由底层分数大小关系保证），与人类偏好逻辑一致；
- **成对数据高效利用**：每对比较数据（chosen, rejected）提供清晰的训练信号，无需绝对分数，降低了标注难度；
- **与 LLM 训练框架自然兼容**：奖励模型直接在预训练语言模型基础上添加线性头，BT 损失梯度可高效反传。

**Bradley-Terry 模型的缺点**：
- **假设偏好是可传递的（Transitivity Assumption）**：实际的人类偏好有时不满足传递性（如循环偏好 A > B，B > C，但 C > A），在这种场景下 BT 模型的假设被违反，产生矛盾训练信号；
- **无法建模偏好幅度**：BT 模型只建模"哪个更好"，而不建模"好多少"；细微差别和天壤之别的回复对，在数据格式上一致，信息量却差异巨大；
- **对噪声标注敏感**：当标注者偏好判断本身含有噪声或不一致时，BT 损失会强制拟合这些噪声；
- **Reward Hacking 的根源之一**：作为神经网络，RM 在分布外的样本上评分不可靠，PPO 训练会找到奖励模型的"漏洞"。

</details>

**12. BT model（DPO，RM 的训练形式）的问题在哪？**

<details>
<summary>💡 查看答案</summary>

1. **偏好不可传递性**：BT 模型假设偏好具有传递性，但人类偏好判断往往不满足这一特性。
2. **独立性假设的局限性**：BT 模型默认每对比较独立，但实际上人类偏好判断通常依赖上下文。
3. **评分尺度问题**：模型将偏好简化为二元比较，难以捕捉程度差异。
4. **模型坍缩**：模型倾向于仅生成正例，负例概率归零。

</details>

**13. Pair RM 相比于原 RM 形式有什么好处？**

<details>
<summary>💡 查看答案</summary>

Pair RM 的核心改进在于其训练目标和数据组织形式。与传统 RM 不同，它不直接预测单个文本的绝对得分，而是学习比较两个文本的相对优劣（pair-wise 评估）。

**优势**：
1. 标注效率高：人类对文本对的相对评判比绝对打分更直观。
2. 抗噪声能力强：仅依赖排序一致性，避免标注者评分标准不统一的问题。
3. 偏好对齐更直接：直接优化文本间的优劣关系。
4. 避免评分偏差：无需预设主观的分数尺度。

</details>

**14. 为什么 RLHF 中，PPO 需要 Critic 模型而不是直接使用 Reward Model？**

<details>
<summary>💡 查看答案</summary>

Reward Model 和 Critic 的职责完全不同，不可相互替代，理解两者的区别是理解 PPO 架构的关键。

**Reward Model 的职责**：评估**完成整条回复后**的最终质量。它接收 (prompt, 完整回复) 作为输入，输出一个标量分数，只在序列生成结束时调用一次，给出"这条回复整体有多好"的信号。

**Critic 的职责**：在**每个 token 生成时**估计"从当前状态出发，按当前策略继续生成，期望获得的未来累积奖励是多少"——即状态价值函数 $V(s_t)$。Critic 需要在序列的每个中间位置给出估计，而不仅仅是序列末尾。

**为什么不能用 Reward Model 替代 Critic**：
- **时序问题**：Reward Model 在序列未完成时无法给出有意义的评分；而 PPO 的 GAE 优势估计需要每个 token 位置 $t$ 的价值 $V(s_t)$，以便计算 TD 误差 $\delta_t = r_t + \gamma V(s_{t+1}) - V(s_t)$；
- **信用分配**：Reward Model 只给出序列末尾的总奖励，无法区分序列中哪些 token 的生成是"关键的好步骤"；Critic 通过逐步估计价值，帮助将最终奖励合理地分配回每个中间时刻；
- **训练目标不同**：Reward Model 用偏好对数据训练，拟合"回复整体好坏"；Critic 用 TD 学习训练，拟合"当前状态的期望未来回报"，两者的输入、输出和训练信号完全不同。

GRPO 通过引入组内归一化来获得优势估计，完全规避了对 Critic 的需求，是 PPO 的一大工程简化。

</details>

**15. Critic Model 和 Reward Model 的区别是什么？**

<details>
<summary>💡 查看答案</summary>

Critic Model 和 Reward Model 是 PPO 训练中两个经常被混淆的组件，但它们的功能、训练方式和使用时机完全不同。

**Reward Model（奖励模型）**：
- **功能**：评估一条**完整 response** 相对于 prompt 的整体质量（有多"好"），给出一个标量分数；
- **调用时机**：在整条 response 生成**结束后**调用一次，给出序列级奖励；
- **训练方式**：用人类偏好数据（chosen/rejected 对）通过 Bradley-Terry 损失训练；
- **训练期间状态**：通常在 PPO 阶段**冻结**，不参与梯度更新；
- **角色**：代表"人类偏好的代理"，是 RLHF 对齐目标的来源。

**Critic Model（评论家模型）**：
- **功能**：在**每个 token 生成时刻**，估计从当前状态出发按当前策略继续生成的期望累积未来奖励（即状态价值函数 $V(s_t)$）；
- **调用时机**：在每个 token 生成**过程中**调用，给出密集的中间价值估计；
- **训练方式**：用 TD 学习（基于 GAE 计算的目标值）进行训练，在 PPO 阶段随 Actor 一起更新；
- **训练期间状态**：在 PPO 阶段持续**更新**，与 Actor 同步训练；
- **角色**：提供每个 token 的"优势信号"，帮助 Actor 判断每个动作（token）对最终奖励的贡献，解决信用分配问题。

**简单类比**：Reward Model 是"最终考官"（只在作文写完后打分），Critic 是"实时辅导老师"（在写作过程中每句话都给出指导）。GRPO 通过去除 Critic，用组内奖励归一化来替代逐步的价值估计，是对这一设计的简化。

</details>

**16. PPO 算法中的 critic 和 reward 的区别是啥？**

<details>
<summary>💡 查看答案</summary>

- **来源不同**：reward 是由环境直接给的；critic 则是由模型自己学习到的。
- **时间范围不同**：reward 是瞬时的、局部的；critic（即 V(s)）是对未来所有 reward 的加权期望。
- **数学关系**：reward 是 critic 学习的监督信号。critic 学习的目标是让 $V(s) \approx$ 未来奖励的期望值。
- **在算法中的角色不同**：reward 由环境提供，是原始信号；critic 由模型生成，是估计器。

</details>
