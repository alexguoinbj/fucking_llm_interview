# 4.1 微调基础概念与方法选择 — 题目与答案
> [⬅ 返回目录](../README_ZH.md) · 第 4 章：微调（Fine-Tuning） · 共 8 题

**1. 假设我有一个 LLM 模型如何根据我的需求使用数据对其进行定制？**

<details>
<summary>💡 查看答案</summary>

定制大型语言模型（LLM）以满足特定需求的四种主要架构模式包括：提示工程（Prompt Engineering）、检索增强生成（Retrieval-Augmented Generation, RAG）、微调（Fine-tuning）和预训练（Pre-training）。这些方法并非相互竞争，而是相互补充，通常可以结合使用以获得最佳效果。

- 如果你数据有限且计算资源不足，提示工程是一个很好的起点。
- 如果你需要更全面的回答且有一些相关数据，可以考虑使用 RAG。
- 如果准确性至关重要且你拥有大量数据集，微调是一个强大的选择。
- 如果你的应用场景高度专业化，且拥有大量特定领域的数据和显著的计算资源，预训练是最理想的选择。

![大模型四种定制化模式对比](https://img.pricenode.uk/llm_interview_questions/zhongw/chapter4/fig_customization_modes.png)

</details>

**2. 何时应该使用微调而不是 RAG？**

<details>
<summary>💡 查看答案</summary>

当你需要专注于特定任务时，微调是完美的选择。以下是一些微调优于 RAG 的场景：
- 你的任务是否属于医学或法律等小众领域？微调可以让你将模型定制到该特定领域的词汇和复杂性。
- 是否只有少量特定任务的数据？微调利用预训练 LLM 的知识作为起点，提高效率并防止过拟合。
- 你的任务是否需要精确的输出，例如情感分析或分类？微调擅长识别特定领域的特定模式。

![微调与检索增强生成（RAG）决策矩阵](https://img.pricenode.uk/llm_interview_questions/zhongw/chapter4/fig_sft_vs_rag.png)

</details>

**3. LLM 中特定任务的微调与零样本学习有何不同？**

<details>
<summary>💡 查看答案</summary>

特定任务的微调通过在特定于该任务的数据集上进一步训练 LLM 来使其适应特定任务。这使模型能够：
- **提高准确性**：微调针对狭窄的任务（如情感分析或命名实体识别）优化模型的性能，与零样本学习相比，能够实现更高的准确性。
- **专业化**：通过专注于特定数据，模型在目标任务上变得高度熟练，但可能会失去一些泛化能力。
相比之下，零样本学习利用模型广泛的预训练知识，无需额外的特定任务训练，使其更具通用性，但可能在特定任务上不够精确。

</details>

**4. 零样本学习是什么，它如何应用于 LLM？**

<details>
<summary>💡 查看答案</summary>

零样本学习使 LLM 能够通过利用其对语言和一般概念的广泛知识来执行它们未明确训练过的任务。它不依赖于特定任务的微调，而是允许模型根据提示中的上下文和指令来理解和生成相关的响应。例如：

- **文本分类**：经过一般语言数据训练的模型可以在没有针对该任务进行特定训练的情况下，通过提供适当的提示将文本分类到不同类别中。
- **翻译或总结**：LLM 可以在没有针对这些任务进行微调的情况下进行翻译或总结，仅使用输入中提供的指令。
零样本学习反映了 LLM 在任务之间泛化的能力，使其能够适应广泛的应用场景。

</details>

**5. 想让模型学习某个领域知识，应该选预训练还是微调？**

<details>
<summary>💡 查看答案</summary>

- **选 Continue PreTrain（继续预训练）**：适合目标领域语言分布与通用语料差异大、通用模型对该领域语言建模能力弱的情况，如代码、中文法律、医学文献等
- **选 SFT（指令微调）**：适合通用模型已有领域知识、只需调整输出格式和指令跟随行为的情况
- **选 RAG（检索增强生成）**：适合知识更新频繁、私有数据不宜训练进模型的情况，成本最低
通常推荐路径：通用基座 → Continue PreTrain（可选）→ SFT → RLHF/DPO

![大语言模型训练与定制化推荐路径](https://img.pricenode.uk/llm_interview_questions/zhongw/chapter4/fig_training_pathway.png)

</details>

**6. 如何估算微调 LLM 的基础设施需求？**

<details>
<summary>💡 查看答案</summary>

准确估算微调 LLM 所需的基础设施需要仔细考虑多个因素。主要驱动因素包括你正在处理的模型的大小和复杂性，以及你希望完成训练的速度。

拥有数十亿参数的大型模型自然会需要更多的计算能力和内存。这意味着你需要强大的图形处理单元（GPU）或张量处理单元（TPU），可能还需要多单元配置。另一方面，如果实现更快的训练时间至关重要，你需要进一步扩展资源。这可能涉及使用多个 GPU 或 TPU 并行工作，或者利用提供按需扩展能力的云解决方案。重要的是要记住，所有这些选择都伴随着预算。可以考虑探索量化技术，该技术可以减少模型大小，从而降低计算需求。

</details>

**7. 全参数微调需要多少显存？如何估算？**

<details>
<summary>💡 查看答案</summary>

粗略估算公式（混合精度训练）：
**显存 ≈ 参数量 × 字节数 × 系数**
- 模型权重（FP16）：参数量 × 2 字节
- 梯度（FP16）：参数量 × 2 字节
- 优化器状态（Adam，FP32）：参数量 × 8 字节（一阶矩 + 二阶矩各 4 字节）
- 合计约：参数量 × 16 字节
**示例**：7B 模型全参微调 ≈ 7×10⁹ × 16 ≈ 112 GB，需要多张 A100（80G）。
实际还需加上激活值显存，通常用梯度检查点（Gradient Checkpointing）换时间为空间。

![混合精度全参数微调显存开销组成分析](https://img.pricenode.uk/llm_interview_questions/zhongw/chapter4/fig_memory_breakdown.png)

</details>

**8. 在微调任务中，应该冻结哪些层的权重？微调编码器前几层、编码器后几层、前馈神经网络层有什么区别？**

<details>
<summary>💡 查看答案</summary>

冻结策略的核心依据是 Transformer 各层学到的特征具有"由通用到具体"的层级结构：

- **底层（前几层）**：通常学习的是较为通用、低层次的特征（如词法、局部语法、基础语义模式），这些特征在不同任务和领域之间具有较强的可迁移性，因此通常优先冻结，避免破坏预训练阶段学到的通用表示，同时减少可训练参数量、降低过拟合风险（尤其在数据量较小时）。
- **顶层（后几层）**：更接近输出，学习的是与具体任务高度相关的高层语义/任务特征，对下游任务的适配作用最大，因此通常是微调的重点，需要解冻并训练。
- **前馈神经网络层（FFN）**：FFN 层参数量在 Transformer block 中占比很大（通常远超 Attention 部分），且其作用更接近"特征变换/记忆存储"，研究表明 FFN 中存储了大量与具体知识相关的信息；微调 FFN 层通常对模型适配新知识/新任务的影响更大，但参数量大也意味着更高的过拟合风险和计算开销。

**实践中常见的策略**：
- 数据量很小时：冻结大部分底层，只微调顶部 1~2 层 + 任务头（分类头等），有时配合 PEFT 方法（如 LoRA）只调整极少参数；
- 数据量中等：解冻顶部若干层（如后 1/3），底层继续冻结；
- 数据量充足、领域差异较大：全参数微调，但通常对底层使用更小的学习率（分层学习率，layer-wise learning rate decay），顶层用更大学习率，体现"底层变化要小、顶层变化可以大"的直觉。

总体原则是：**冻结的层越靠近输入，对通用能力的保留越好；解冻的层越靠近输出/FFN，对任务适配能力越强**，需要根据数据量、领域差异和过拟合风险综合权衡。
