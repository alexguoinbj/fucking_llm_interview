# 12.5 多模态训练与对齐 — 题目与答案
> [⬅ 返回目录](../README_ZH.md) · 第 12 章：多模态大模型 · 共 20 题

**1. 多模态预训练常用哪些训练目标？**

<details>
<summary>💡 查看答案</summary>

多模态预训练常见训练目标包括：

1. **图文对比学习（ITC, Image-Text Contrastive）**：拉近配对图文表示，推远非配对表示，学习全局语义对齐（CLIP、ALIGN）。
2. **图文匹配（ITM, Image-Text Matching）**：二分类任务，判断给定图文对是否匹配，学习细粒度图文一致性（BLIP、ALBEF）。
3. **图文生成（ITG / LM, Language Modeling）**：给定图像，自回归生成对应文字描述，训练生成能力（BLIP、Flamingo）。
4. **掩码语言建模（MLM）**：掩盖文本中部分词，结合图像上下文进行预测，强迫模型利用图像信息理解文本。
5. **掩码图像建模（MIM）**：掩盖图像部分 patch，预测被掩盖区域的像素或特征（MAE、BEiT），学习视觉表示。
6. **图像描述生成（Captioning）**：标准的 seq2seq 目标，图像到文字，是生成式多模态模型的核心目标。
7. **视觉问答（VQA）目标**：给定图像和问题，生成答案，可作为有监督微调目标或预训练目标之一。

</details>

**2. 图文对比学习的目标是什么？**

<details>
<summary>💡 查看答案</summary>

图文对比学习的目标是**将语义上对应的图文对在嵌入空间中拉近，同时将不对应的图文对推远**，从而学习跨模态的语义对齐。

**形式化描述：**
对 Batch 内 $N$ 个图文对 $\{(v_i, t_i)\}$，计算图像与文本的相似度矩阵 $S_{ij} = sim(v_i, t_j) / \tau$（$\tau$ 为温度系数），使用对称的 InfoNCE 损失：

$$\mathcal{L} = -\frac{1}{2N}\sum_{i=1}^{N}\left[\log\frac{e^{S_{ii}}}{\sum_j e^{S_{ij}}} + \log\frac{e^{S_{ii}}}{\sum_j e^{S_{ji}}}\right]$$

**关键要素：**
- **大 Batch Size**：负样本数量越多效果越好，CLIP 使用 32768 的超大 batch；
- **温度系数 $\tau$**：可学习参数，控制分布的尖锐程度；
- **难负样本**：同一 Batch 内的负样本可能语义接近（假负例问题），需要进行去噪处理（如 ALBEF 用 Momentum Encoder 过滤）；
- **动量编码器**：用动量更新的编码器维护更大的特征队列，提供更多负样本（MoCo 风格）。

</details>

**3. 图文生成模型的基本原理是什么？**

<details>
<summary>💡 查看答案</summary>

图文生成模型分为两类：

**文本生成（给定图像生成文字）：**
- 图像经过编码器得到视觉 token 序列；
- 视觉 token 与文本 token 拼接后输入自回归语言模型（或通过 Cross-Attention 注入）；
- 语言模型以 Next Token Prediction 方式逐步生成文字输出；
- 代表模型：LLaVA、InstructBLIP、Flamingo、GPT-4V。

**图像生成（给定文字生成图像）：**
- 文本经过文本编码器（如 CLIP 文本编码器）得到条件向量；
- 扩散模型（U-Net 或 DiT）在噪声图像上迭代去噪，以文本条件引导生成方向（Classifier-Free Guidance）；
- 代表模型：Stable Diffusion、DALL-E 3、Imagen。
- 也有基于自回归的图像 token 生成方式（如 VQVAE + GPT，代表：DALL-E 1）。

</details>

**4. 多模态大模型的训练通常分为哪几个阶段？**

<details>
<summary>💡 查看答案</summary>

以经典的两阶段范式为例，多模态大模型的训练通常分为：

1. **模态对齐预训练阶段**：此阶段完全冻结视觉编码器和语言模型这两个已经充分预训练好的模块，只训练随机初始化的连接模块（如线性投影层或 Q-Former）。使用规模较大（可能达到数亿甚至更多）但质量相对粗糙的图文对数据（如网络爬取的图片及其配套的简单描述），目标是让连接模块学会一个基础的、粗略的映射关系，使视觉特征能够对齐到语言模型能够理解的表示空间中，这一阶段可以看作是让模型先"学会翻译"视觉信号。
2. **多模态指令微调阶段**：此阶段在规模小得多但质量高得多的指令格式数据（每条数据包含图像、具体指令、期望的回答）上，对模型进行微调——通常会解冻语言模型（可能配合 LoRA 等参数高效方法控制训练成本），有时也会解冻视觉编码器。这一阶段的目标是让模型学会理解并遵循包含视觉信息的复杂自然语言指令，具备执行描述、问答、推理等具体任务的能力，可以看作是让模型"学会做事"。
更先进的模型（如 InternVL、Qwen-VL）往往会在这两个阶段之间再插入一个"高质量数据继续预训练"的中间阶段，形成前文所述的三阶段训练范式，通过分层次提高数据质量的方式获得更好的最终效果。

</details>

**5. 为什么多模态模型训练时常常需要"冻结"部分模块（如视觉编码器）？**

<details>
<summary>💡 查看答案</summary>

冻结部分模块（尤其是已经充分预训练好的视觉编码器和语言模型）主要出于以下几方面考虑：

- **保护已有能力，避免灾难性遗忘**：视觉编码器和语言模型都是在各自海量的单模态数据上，经过长时间、大算力训练才获得的高质量表示能力。而多模态对齐阶段使用的数据量相对有限，如果任由这些预训练模块的参数随意被更新，很容易在还没学会新的多模态能力之前，就先把原本已经学得很好的单模态能力破坏掉（即灾难性遗忘）；
- **降低训练成本**：冻结意味着这部分参数在训练过程中不需要计算梯度、不需要存储对应的优化器状态（如 Adam 优化器需要为每个可训练参数额外存储一阶和二阶动量），可以大幅减少实际参与训练更新的参数量，从而显著降低训练所需的显存占用和计算开销，使得在有限的算力预算下也能完成多模态对齐训练；
- **让新增模块专注学习"翻译"任务**：冻结两端、只训练中间的连接模块，相当于明确了训练目标——让连接模块专注于学习"如何将视觉特征正确映射到语言模型能理解的空间"这一相对聚焦的任务，训练目标更清晰、更容易收敛。
当然，冻结也并非训练全程都保持不变，如前文渐进式解冻策略所述，实践中通常会在后续训练阶段根据数据规模和效果需要，逐步解冻更多参数以进一步提升模型效果。

</details>

**6. 多模态指令微调（视觉指令微调）如何做？为什么它是关键步骤？**

<details>
<summary>💡 查看答案</summary>

多模态指令微调（Multimodal / Visual Instruction Tuning）旨在让模型理解并遵循包含图像的自然语言指令，是连接 VLM 基础能力与应用能力的桥梁。

**数据构建：**
- 每条数据形如 `<image> + <instruction> → <response>`；
- 通常利用已有的图像标注数据（物体检测框、Caption）结合强大的语言模型（如 GPT-4）自动生成多样化的指令-回答对，再辅以一定比例的人工标注/校验数据保证质量（LLaVA-Instruct）；
- 数据来源还包括：人工标注、多任务混合（VQA、描述、推理等）、学术数据集改写。

**训练流程（以 LLaVA 为例）：**
1. 预训练对齐阶段：冻结图像编码器和语言模型，仅训练投影层，使用大规模图文对做 Caption 预训练；
2. 指令微调阶段：解冻语言模型（图像编码器可选冻结），在指令数据上全量或 LoRA 微调。

**关键技巧：** 对话格式对齐（复用 Vicuna、LLaMA-Chat 等模板）；训练数据中加入拒绝回答不当请求的样本；混合 VQA、OCR、对话、推理等多类型任务数据提升泛化能力。

**为什么关键：** 传统 VQA/描述模型只能执行训练过的特定任务，而指令微调让模型学会理解任意指令意图的泛化能力；它真正教会 LLM 如何利用视觉信息完成推理、遵循复杂指令和多轮对话，把 LLM 固有的常识推理、创意写作等能力与视觉输入结合起来；同时使模型的输出格式和交互方式更符合人类期望，是模型从"可用"到"好用"的决定性一步。

</details>

**7. 多模态对话模型如何设计？**

<details>
<summary>💡 查看答案</summary>

多模态对话模型需要支持多轮图文交叉对话：

**架构设计：**
- 基础架构为带图像输入的自回归语言模型（如 LLaVA、InstructBLIP、Qwen-VL）；
- 图像在对话中某轮出现，后续所有轮次可通过 KV Cache 中缓存的视觉 tokens 复用，无需重新编码；
- 多图输入时，每张图分别编码并按顺序插入对应位置的 token 序列中。

**对话状态管理：**
- 使用标准的多轮对话模板，`[USER]: ... [ASSISTANT]: ...` 交替组织；
- 历史对话全部拼接进上下文窗口，模型自然实现多轮记忆；
- 超出上下文长度时需截断策略（优先保留图像 tokens 和最近轮次）。

**指令对齐：**
- 通过 RLHF 或 DPO 对多模态输出进行偏好对齐，减少幻觉和不当回复；
- 训练数据需覆盖多种对话场景：图像描述、细节提问、推理、比较分析等。

</details>

**8. 什么是 LoRA？在多模态模型微调中如何应用？**

<details>
<summary>💡 查看答案</summary>

LoRA（Low-Rank Adaptation，低秩自适应）是一种参数高效微调技术，其核心思想是：不直接更新模型原有的大型权重矩阵 $W$（保持其完全冻结），而是在其旁路新增一对规模远小于原矩阵的低秩矩阵 $A$ 和 $B$（$W$ 的形状是 $d \times k$，而 $A$ 是 $d \times r$、$B$ 是 $r \times k$，其中秩 $r$ 远小于 $d$ 和 $k$），训练时只更新这两个新增的低秩矩阵，最终模型的实际计算变为 $W + BA$，即在原有输出基础上叠加一个低秩的"修正量"。由于 $r$ 通常很小（如 8、16、64），新增的可训练参数量相比原始权重矩阵可以减少几个数量级，从而大幅降低微调所需的显存（尤其是优化器状态占用）和训练成本。

在多模态模型微调中，LoRA 可以灵活地应用于不同组件：最常见的做法是只对**语言模型**部分的 Attention 层（Query、Key、Value 投影矩阵）插入 LoRA，这也是指令微调阶段最主流的参数高效方案；如果需要提升模型对特定领域图像的适配能力，也可以选择性地对**视觉编码器**部分同样插入 LoRA；甚至可以对连接模块也应用 LoRA。这种"哪里需要适配就在哪里插入"的灵活性，使得 LoRA 成为多模态模型在资源受限场景下进行任务/领域适配的重要工具。

</details>

**9. 如何设计多模态模型的强化学习对齐（如基于人类反馈的偏好优化）？相比纯文本场景有什么特殊之处？**

<details>
<summary>💡 查看答案</summary>

多模态模型强化学习对齐的基本流程与纯文本场景类似：首先收集针对同一输入（在多模态场景下是"图像+问题"）的多个候选回答，由人工标注者（或更强的模型）标注出哪个回答更好，构成偏好对比数据；随后既可以基于这些偏好数据训练一个独立的奖励模型再结合强化学习算法（如 PPO）优化策略模型，也可以采用更简洁的直接偏好优化（DPO）方法跳过显式奖励模型的训练，直接根据偏好对比数据优化模型参数。

相比纯文本场景，多模态强化学习对齐存在以下几方面特殊之处：

- **偏好判断需要同时考虑图文一致性**：标注者在判断"哪个回答更好"时，不能仅从语言流畅度、逻辑性等纯文本维度评判，还必须仔细核对图像的实际内容，判断回答中提到的具体细节（物体、颜色、数量、位置等）是否真实对应图像中的内容，这大大增加了标注的复杂度和成本；
- **幻觉是重要的偏好判断维度**：由于多模态模型幻觉问题较为突出，偏好数据的标注标准中通常需要专门加入"是否存在幻觉内容"这一维度，一个语言表达流畅但捏造了图像中不存在细节的回答，应当被明确标注为劣于一个表达朴实但完全准确的回答；
- **需要专门评估"是否真正利用了视觉信息"**：偏好标注有时还需要额外考察模型是否真的基于图像内容进行了推理和回答，而非依赖语言先验蒙对答案（避免前述的"语言捷径"问题被强化学习进一步固化）。

</details>

**10. 什么是多模态模型的"模态间灾难性遗忘"？在多阶段训练中如何缓解？**

<details>
<summary>💡 查看答案</summary>

模态间灾难性遗忘指：模型在某一训练阶段，如果训练数据过度集中于单一模态或单一任务类型（例如某个阶段的微调数据几乎全部是纯文本对话数据，或者全部是某一类特定的视觉任务数据），随着这部分数据上的持续训练，模型在**其他**此阶段未被重点训练的模态或任务上的能力，可能会出现明显的、意料之外的退化——例如经过一轮纯文本指令微调后，模型忽然在原本表现良好的图像理解任务上表现明显变差。这种现象的本质原因与神经网络训练中普遍存在的灾难性遗忘问题一致：当前阶段的梯度更新方向主要是为了拟合当前阶段的数据分布，这个更新方向未必与此前阶段已经学到的能力方向一致，甚至可能产生冲突。

缓解这一问题的常见方法包括：

- **数据回放（Data Replay）**：在每个训练阶段的数据中，主动保留一定比例此前阶段（或其他模态/任务）的数据一起参与训练，而不是完全切换到全新的单一数据分布，帮助模型在学习新能力的同时"复习"已有能力，防止遗忘；
- **参数高效微调**：采用 LoRA 等只更新少量新增参数的微调方式，相比全量微调对原始预训练权重的整体扰动更小，天然具有一定的抗遗忘特性；
- **持续监控多维度评测指标**：在训练过程中，不能只关注当前阶段重点优化的目标指标，还需要持续在覆盖不同模态、不同任务的细粒度评测集上监控模型表现，一旦发现某些此前表现良好的能力出现明显下滑，就需要及时调整数据配比或训练策略。

</details>

**11. 多模态模型微调有哪些方法？**

<details>
<summary>💡 查看答案</summary>

1. **全量微调（Full Fine-tuning）**：更新所有参数，效果最好，但计算成本高；适合数据量充足的场景。
2. **LoRA / QLoRA**：对语言模型的注意力层插入低秩矩阵，仅更新少量参数；可选择是否对图像编码器也加 LoRA；显存友好，适合消费级 GPU。
3. **投影层微调（Adapter Tuning）**：只微调图像-文本的投影层（如 MLP、Q-Former），冻结图像编码器和语言模型；适合快速领域适配，但效果上限低。
4. **图像编码器微调**：解冻图像编码器参与训练，提升对特定领域图像的特征提取能力（如医学图像、遥感图像）；通常学习率需要设置较小。
5. **指令微调（Instruction Tuning）**：在指令格式数据上做监督微调，提升模型遵循指令的能力；是目前最主流的多模态微调方式。
6. **RLHF / DPO**：基于人类偏好数据进行强化学习或直接偏好优化，减少幻觉、提升回答质量和安全性。
7. **参数高效方法对比**：LoRA < Adapter < 全量微调（参数量递增），但随着数据量增多，全量微调效果逐渐超越参数高效方法。

</details>

**12. 多模态模型如何做分布式训练？**

<details>
<summary>💡 查看答案</summary>

**数据并行（Data Parallelism）：** 每个 GPU 持有完整模型副本，处理不同的数据 Batch，使用 DDP 或 FSDP 实现，适合模型能放入单 GPU 的情况。

**模型并行（Model Parallelism）：** Tensor 并行（将矩阵运算拆分到多个 GPU，如 Megatron-LM）；流水线并行（将模型不同层分配到不同 GPU）。

**ZeRO 优化（DeepSpeed）：** ZeRO-1 分片优化器状态；ZeRO-2 再分片梯度；ZeRO-3 分片模型参数；结合 CPU Offload 可进一步降低显存需求。

**多模态特殊考量：** 图像编码器与语言模型可放在不同 GPU 上做异构并行；图像预处理（解码、Resize）建议在 CPU 侧异步完成，避免成为瓶颈；大 Batch 训练时注意 CPU-GPU 数据传输带宽。

**训练框架选择：** DeepSpeed + HuggingFace Accelerate（工业界最主流）；Megatron-LM（大规模训练效率最优但使用复杂）；PyTorch FSDP（官方原生支持）。

</details>

**13. 多模态训练如何优化显存？**

<details>
<summary>💡 查看答案</summary>

1. **冻结部分模块**：预训练对齐阶段冻结图像编码器和语言模型，仅训练投影层。
2. **梯度检查点（Gradient Checkpointing）**：不缓存中间激活值，反向传播时重新计算，以时间换空间，显存减少约 40-50%。
3. **LoRA 微调**：只训练少量参数，大幅降低优化器状态占用。
4. **混合精度训练（BF16/FP16）**：显存相比 FP32 减少一半，配合 Loss Scaling 保持数值稳定。
5. **图像 token 压缩**：减少每张图像的 token 数量（Pooling、Q-Former），直接减少 Attention 计算和 KV Cache 占用。
6. **ZeRO 分布式优化（DeepSpeed）**：将优化器状态、梯度、模型参数分片到多个 GPU/节点。
7. **FlashAttention**：IO-aware 的高效 Attention 实现，显著降低 Attention 显存峰值占用。

</details>

**14. 什么是多模态训练中的"两阶段"与"三阶段"范式的区别？**

<details>
<summary>💡 查看答案</summary>

**两阶段范式**（以经典 LLaVA 为代表）：
1. **第一阶段——模态对齐预训练**：冻结视觉编码器和语言模型，只训练随机初始化的连接器（线性投影层），使用规模较大但质量相对粗糙的图文对数据（如网络爬取的 Caption 数据），让连接器学习一个基础的、粗略的视觉到语言表示空间的映射；
2. **第二阶段——视觉指令微调**：解冻语言模型（通常搭配 LoRA），使用规模较小但质量更高的指令格式数据（图像+指令+回答），训练模型理解并遵循包含视觉信息的复杂指令。

**三阶段范式**（InternVL、Qwen-VL 等更新的模型普遍采用）在此基础上，于两个阶段之间插入一个中间的"深度预训练/继续预训练"阶段，具体三个阶段变为：（1）大规模粗糙数据对齐（与两阶段范式的第一阶段类似，追求数据规模）；（2）**中等规模高质量数据的继续预训练**——解冻更多参数（如视觉编码器本身），使用经过清洗、质量更高的图文数据进一步加强对齐效果和视觉细节表达能力；（3）小规模、高度精标的指令微调数据做最终的能力对齐。这种"数据质量逐阶段提升、模型解冻范围逐阶段扩大"的设计，本质上是一种课程学习思路，相比两阶段范式能获得更扎实的视觉表示基础，也是当前追求更强性能的先进 VLM 的主流训练范式。

![多模态训练 “两阶段” 与 “三阶段” 课程学习范式对比](https://img.pricenode.uk/llm_interview_questions/zhongw/chapter12/fig_training_stages.png)

</details>

**15. Warm-up 和学习率调度在多模态训练中有哪些特殊考量？**

<details>
<summary>💡 查看答案</summary>

Warm-up 指训练最初的一段步数内，学习率从一个很小的值逐步线性（或其他方式）增长到目标学习率，目的是避免训练刚开始时（模型参数、优化器状态都不稳定）过大的学习率导致梯度爆炸或训练发散。

在多模态训练中，由于模型天然包含多个"预训练程度"迥异的模块，Warm-up 和学习率调度需要更精细的分组设计：

- **连接器（随机初始化）**：由于参数从零开始学习，通常可以使用相对较大的峰值学习率，但仍需要一定长度的 Warm-up 步数，帮助其在训练初期稳定地找到大致正确的优化方向；
- **语言模型 / 视觉编码器（已充分预训练）**：为了避免破坏其已经学到的强大能力，通常使用远小于连接器的学习率（可能相差一个数量级），且部分实践中会为这些模块设置更长的 Warm-up 周期，让优化器更缓慢、更谨慎地开始调整这些"脆弱"的预训练参数；
- **阶段切换处的重新 Warm-up**：当训练从一个阶段（如对齐预训练）切换到下一个阶段（如指令微调）时，由于数据分布、训练目标、甚至解冻的参数范围都发生了变化，梯度的统计特性会与上一阶段末尾显著不同，因此通常需要在新阶段开始时重新设置一个较短的 Warm-up 周期，帮助优化器（尤其是使用了动量的优化器如 AdamW）平稳适应新阶段的梯度分布，避免刚切换阶段时出现损失值剧烈震荡的现象。

</details>

**16. 多模态模型训练中如何选择 Batch Size？对训练稳定性有何影响？**

<details>
<summary>💡 查看答案</summary>

Batch Size 的选择需要综合考虑**训练目标的性质**和**硬件资源限制**两方面因素：

**训练目标对 Batch Size 的要求**：以 CLIP 为代表的对比学习类目标（ITC），其损失函数的负样本直接来自同一 Batch 内的其他样本，Batch Size 越大意味着每一步能提供的负样本越多、越丰富，对比学习的效果通常也越好——这也是 CLIP 原始论文中使用高达 32768 这种超大 Batch Size 的原因；相比之下，指令微调阶段的训练目标更接近标准的有监督学习（预测下一个 Token），对负样本数量没有类似的依赖，因此可以使用相对较小的 Batch Size（如几十到几百）。

**硬件资源的限制**：多模态数据（尤其是包含图像、多图甚至视频的样本）相比纯文本，单个样本占用的显存要大得多（一张图像可能对应几百甚至上千个视觉 Token），这直接限制了单张 GPU 上能同时处理的样本数量。实践中常用的应对方法是**梯度累积**（Gradient Accumulation）：在多个小 Batch 上分别计算梯度并累加，累积到目标的等效 Batch Size 后再统一执行一次参数更新，这样可以在显存受限的情况下，仍然获得大 Batch Size 训练带来的收敛稳定性优势（尤其对需要大 Batch 的对比学习类目标而言）。

**对训练稳定性的影响**：Batch Size 过小会导致每一步计算出的梯度方差较大（梯度噪声较大），训练损失曲线可能出现较大波动，收敛速度变慢；Batch Size 过大虽然梯度更稳定，但通常需要配合相应放大学习率（否则收敛会变慢），且过大的学习率如果调整不当反而可能引发新的不稳定，因此实践中 Batch Size 和学习率往往需要联合调优。

</details>

**17. 什么是渐进式分辨率训练（Progressive Resolution Training）？**

<details>
<summary>💡 查看答案</summary>

渐进式分辨率训练指训练过程按阶段逐步提高输入图像的分辨率，而不是从始至终使用同一个（通常是较高的）目标分辨率训练。典型的分阶段方式为：

1. **早期阶段（低分辨率）**：使用较小的图像分辨率（如 224×224 甚至更小），此时视觉 Token 数量少，单步训练的计算成本低，可以用更快的速度完成大量训练步数，帮助模型快速学习到基础的视觉概念识别和粗粒度的视觉-语言关联；
2. **后期阶段（逐步提高分辨率）**：随着训练推进，将输入分辨率逐步提高（如提升到 448×448、672×672 甚至更高），配合位置编码插值等技术让模型适应更多的视觉 Token 数量，此阶段主要目标是提升模型对图像细节（小目标、文字、精细纹理）的感知能力。

这种策略的核心收益在于**训练成本的分摊**：由于绝大部分训练步数（尤其是模型收敛较慢的训练初期）是在计算成本更低的低分辨率阶段完成的，只有相对较少的训练步数需要承担高分辨率阶段更高的计算开销，因此相比自始至终采用固定高分辨率训练，渐进式分辨率训练能在达到相近（甚至更优，因为分阶段学习本身也是一种有益的课程学习）最终效果的前提下，显著降低总体训练所需的计算资源。

</details>

**18. 视觉编码器和语言模型的学习率是否应该设置不同？为什么？**

<details>
<summary>💡 查看答案</summary>

答案是：通常建议设置不同的学习率，这一策略被称为分层学习率（Layer-wise / Group-wise Learning Rate）。具体考量如下：

- **视觉编码器（如果参与训练）**：由于其大多来自像 CLIP ViT 这样已经在海量数据上充分预训练、质量很高的模型，参数已经处于一个"较优"的状态，如果使用与其他模块相同（较大）的学习率，很容易在训练初期就用较大的梯度更新"破坏"其已经学到的通用视觉表示能力（即导致灾难性遗忘）。因此通常会为视觉编码器设置比语言模型或连接器小得多的学习率（甚至可以额外设置更小的权重衰减），让它在训练过程中只做"温和"的微调；
- **连接器（随机初始化）**：由于是全新初始化、需要从零学起的模块，通常需要相对较大的学习率，才能在有限的训练步数内快速收敛到一个有效的视觉-语言映射；
- **语言模型**：其学习率设置通常介于视觉编码器和连接器之间，具体数值也取决于是采用全量微调还是 LoRA 等参数高效方法——LoRA 微调时新增的低秩矩阵参数同样是随机初始化的，也需要相对更大的学习率。
这种分组设置学习率的做法，本质上是根据每个模块"预训练程度的高低"以及"对该模块的信任程度"来动态调整优化的力度，是多模态训练中被广泛采纳的重要工程细节，如果忽视这一点、对所有模块使用统一的学习率，很容易出现视觉编码器能力被破坏或者连接器收敛过慢的问题。

</details>

**19. 多模态大模型的"涌现能力"通常体现在哪些方面？**

<details>
<summary>💡 查看答案</summary>

涌现能力（Emergent Abilities）指模型在参数规模、数据规模或训练计算量跨越某个临界点之后，突然表现出的、在更小规模模型上完全观察不到（或表现极差）的复杂能力，这类能力并非通过显式的、针对性的监督训练获得，而是模型在大规模预训练过程中自发学习和整合已有知识的结果。在多模态大模型中，涌现能力典型体现在以下几个方面：

1. **跨模态常识推理能力**：模型能够将图像中观察到的视觉线索与预训练阶段学到的海量世界知识相结合，回答需要综合视觉感知和常识/专业知识才能解答的开放式问题（例如识别出图片中的某个特定品种植物，并结合植物学知识回答其生长习性），这种能力并非通过专门针对"结合视觉和知识回答问题"这一任务训练获得，而是大规模预训练带来的自然结果；
2. **上下文学习（In-Context Learning）能力**：在提示中提供少量图文示例后，模型无需任何参数更新，就能"领悟"任务的模式并泛化到结构相似但内容全新的样本上，这种"看示例学任务"的能力在小规模模型上通常表现得非常弱，而在大规模模型上会明显增强；
3. **组合泛化能力**：模型能够将训练数据中分别独立出现过的视觉概念和语言指令进行灵活的、全新的组合，正确处理训练时从未见过的"指令-图像"具体搭配（例如训练时分别见过"识别猫"和"用第一人称视角写一段文字"，模型能够将两者组合完成"以猫的视角写一段第一人称描述"这类全新任务）；
4. **初步的思维链推理**：在没有专门针对多步骤视觉推理进行大规模指令微调的情况下，规模足够大的模型也能自发地展现出一定程度的"先分解问题、再逐步推理"的行为模式。
这些能力通常呈现出一种"非线性"的规律——在模型规模较小时几乎观察不到，一旦跨过某个规模阈值后能力会相对突然地显现，这也是支持"继续扩大模型和数据规模"这一研发路线的重要依据之一。

</details>

**20. 什么是渐进式解冻（Progressive Unfreezing）策略？在多模态训练中如何应用？**

<details>
<summary>💡 查看答案</summary>

渐进式解冻指训练过程中不是一开始就解冻全部参数（或者反过来，一开始就冻结全部参数），而是按照某种顺序，随着训练阶段推进逐步解冻更多模块参与更新。在多模态训练中的典型应用方式为：

1. **第一阶段（对齐预训练）**：完全冻结视觉编码器和语言模型，只训练连接器（如线性投影层或 Q-Former），让连接器先学会一个粗略但合理的视觉到语言的映射，避免连接器随机初始化的巨大梯度扰乱两端已经预训练好的参数。
2. **第二阶段（初步指令微调）**：解冻语言模型（通常配合 LoRA 等参数高效方法），继续冻结视觉编码器，让语言模型在保留连接器已学到的基础映射之上，学习如何结合视觉信息完成指令任务。
3. **第三阶段（深度微调，可选）**：如果数据量和算力允许，进一步解冻视觉编码器（通常使用比语言模型更小的学习率），让视觉表示本身也能针对下游任务的特定视觉分布（如医学影像、工业质检图片）做一定程度的适应性调整。

这种"先训练新增模块、再逐步放开旧模块"的顺序，本质上是为了控制训练过程中的优化稳定性——越晚解冻的模块通常是预训练程度越高、越"脆弱"（容易被破坏能力）的模块，渐进式解冻可以在保护已有能力的同时，逐步扩大模型的可调整自由度，是缓解"模态间灾难性遗忘"的常见工程手段之一。

</details>
