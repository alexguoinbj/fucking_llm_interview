# 12.4 视觉编码与输入处理 — 题目与答案
> [⬅ 返回目录](../README_ZH.md) · 第 12 章：多模态大模型 · 共 17 题

**1. 图像输入为什么要做 patch 化处理？**

<details>
<summary>💡 查看答案</summary>

Transformer 的 Self-Attention 计算复杂度为序列长度的平方，直接将像素级别的图像（如 224×224=50176 个像素）作为 token 序列计算量极大。

**Patch 化的核心原因：**
1. **降低序列长度**：将图像划分为 N×N 的 patch（如 16×16 像素），224×224 图像变为 196 个 patch tokens，计算可行；
2. **构建局部特征**：每个 patch 捕获局部视觉语义，与文本中的词（token）形成类比，适合 Transformer 建模；
3. **统一输入格式**：patch 线性投影后维度与文本 embedding 一致，便于统一的多模态建模；
4. **灵活处理分辨率**：可通过调整 patch 大小或图像分辨率控制序列长度与细节精度之间的权衡。

</details>

**2. 图像模态中位置编码如何应用？**

<details>
<summary>💡 查看答案</summary>

图像 patch 是二维排列的，位置编码需要体现空间结构：

1. **一维可学习位置编码**（ViT 原始方案）：将所有 patch 按光栅顺序排列，每个位置分配一个可学习向量。实践表明效果与 2D 编码相当，且实现简单。
2. **二维正弦位置编码**：分别对行坐标和列坐标用正弦/余弦编码，再拼接或相加，更明确地表达空间位置关系。
3. **相对位置编码**（RoPE 2D 扩展）：将 RoPE 扩展到二维，在 Attention 计算中直接编码两个 patch 之间的相对位置，对图像分辨率变化更鲁棒。
4. **动态分辨率位置插值**：当推理分辨率与训练分辨率不同时，对预训练的位置编码做双线性插值，使模型适应更高分辨率输入（如 ViT 的位置插值微调）。
5. **无位置编码方案**：部分模型（如 MAE 的某些变体）探索去掉显式位置编码，依靠注意力机制自适应学习位置关系。

</details>

**3. 为什么说"视觉编码器的选择"对最终多模态模型的能力上限有重要影响？**

<details>
<summary>💡 查看答案</summary>

视觉编码器是整个多模态系统获取视觉信息的**唯一入口**，它决定了模型能够从图像中提取到的信息粒度和语义层次的"天花板"——如果视觉编码器本身在预训练阶段就没有充分学习到对某类视觉信息（如细粒度纹理、微小文字、精确的空间位置关系）的良好表征能力，那么无论后续的连接模块设计得多精巧、语言模型的推理能力多强，都无法凭空"生成"出原本就不存在于视觉特征中的信息——这是一个典型的"下游无法弥补上游瓶颈"的问题，类似于"巧妇难为无米之炊"。因此，视觉编码器的预训练数据规模与多样性（是否见过足够丰富的场景和物体）、支持的输入分辨率（决定能捕捉多细的细节）、以及具体的预训练目标（对比学习偏语义、掩码重建偏细节，如前文所述）这几个因素，会直接决定并限制整个多模态大模型在下游各类视觉理解任务上能够达到的能力上限，这也是为什么近年来越来越多先进 VLM（如 InternVL）选择训练规模更大、能力更强的专用视觉编码器（而非直接复用现成的 CLIP）的重要原因。

</details>

**4. 多模态处理高分辨率/多分辨率输入有哪些方法？会带来哪些挑战？**

<details>
<summary>💡 查看答案</summary>

标准的视觉编码器（如 ViT）通常被设计用于处理低分辨率的固定尺寸输入（如 224×224 或 336×336），处理高分辨率图像会带来三方面挑战：

1. **计算量爆炸**：图块数量与边长的平方成正比，而 Self-Attention 复杂度又与图块数量的平方成正比，分辨率翻倍会导致计算量变为原来的 16 倍。
2. **位置编码失效**：预训练好的 ViT 位置编码是针对特定图块数量学习的，图块数量增加会超出现有位置编码的范围。
3. **显存占用剧增**：更长的序列意味着 Transformer 每一层都需要存储更大的激活值。

目前主要有以下几种应对策略：

1. **切片（Tiling）-编码-拼接**：确定一个基准分辨率（"切片单元"），将图像切割成多个与切片单元形状匹配的子块，分别独立编码后拼接特征，同时保留原始图像的低分辨率全局视图。优点是可直接复用预训练的低分辨率模型，缺点是可能破坏跨切片物体的全局结构。
2. **组合（Packing）方法**：将不同分辨率图像 patch 化后的特征直接在序列维度上拼接，通过引入块对角掩码（block diagonal mask）避免不同图像 token 之间相互注意力计算，从而支持批量并行处理不同分辨率的输入。
3. **可变分辨率图块**：保持图块数量不变，根据输入分辨率动态调整每个图块的尺寸，避免计算量爆炸，但大图块会丢失局部细节。
4. **多尺度特征融合**：使用可处理高分辨率的视觉主干（如 Swin Transformer），从不同层级提取多尺度特征，通过特征金字塔网络（FPN）融合后再送入适配器（如 Fuyu-8B、Monkey）。

</details>

**5. 视觉编码器分辨率提升后，如何在不显著增加 Token 数量的前提下保留更多信息？**

<details>
<summary>💡 查看答案</summary>

这一问题的核心矛盾在于：提高分辨率本身就意味着更多的图像细节，但如果不加控制地按比例增加视觉 Token 数量，很快会让计算和显存开销变得难以承受，因此需要在"分辨率提升带来的信息增益"和"Token 数量增长带来的成本"之间寻求更优的平衡点。常见思路包括：

- **动态分块策略**：将高分辨率图像切分为多个子图，分别用相对较低分辨率的编码器独立处理（而非用一个编码器直接处理超大分辨率），再通过位置标记将各子图的特征重新组织拼接，这样既能捕捉高分辨率细节，又不需要视觉编码器本身支持超大的序列长度；
- **分层特征融合**：同时提取低分辨率下的全局特征（提供整体场景上下文）和高分辨率下的局部特征（提供细节信息），将两者融合后再输入语言模型，而不是简单粗暴地把所有分辨率级别的 Token 都原样保留；
- **高效的视觉 Token 压缩模块**：如前述的 Q-Former（通过可学习 Query 提炼关键信息）、Token Pooling（对空间相邻的 Token 做池化合并）、Pixel Shuffle（将空间维度信息折叠进通道维度）等技术，本质上都是在"总 Token 预算不变或小幅增加"的约束下，尽可能保留更多有效信息，是当前应对这一问题最主流的技术方向。

</details>

**6. 如何处理长宽差异巨大（长图/宽图）的图像？**

<details>
<summary>💡 查看答案</summary>

对于长宽比极端（如一张很窄的长图，或者一张很宽的全景图）的图像，如果简单粗暴地将其裁剪或压缩为标准的正方形输入，会导致大量原始内容被裁掉或产生严重的形变失真，因此需要专门的处理策略：

1. **自适应分块**：根据图像的实际长宽比，动态决定切分子图块的方式——例如一张很宽的横向长图，切分时应该在水平方向切分出更多列的子图块，而竖直方向的长图则相应地切分出更多行，这样才能保证每个子图块本身接近正方形（符合视觉编码器的预训练假设），同时又不会因为强行统一裁剪成正方形而丢失大量原图信息；
2. **保持原始比例并做 Padding**：将图像按原始长宽比等比例缩放到目标尺寸范围内，在较短的一边用空白像素填充（Padding）到目标的正方形或标准比例，这样可以完整保留原图中所有内容的相对空间关系，不产生任何形变，代价是会引入一部分"无效"的填充区域；
3. **多尺度编码**：对图像中不同重要程度的区域采用不同的编码分辨率——例如对画面主体或用户明确关注的区域采用更高分辨率编码，对背景等次要区域采用较低分辨率编码，从而在总 Token 预算有限的情况下，把"分辨率预算"更合理地分配给真正重要的内容。

</details>

**7. 什么是 AnyRes（任意分辨率）动态切图策略？（如 LLaVA-NeXT、InternVL 的实现）**

<details>
<summary>💡 查看答案</summary>

AnyRes（也称动态高分辨率策略）的核心思路是：预先定义一组**候选的网格划分方式**（例如 1×1、1×2、2×1、2×2、1×3、3×1 等多种行列组合），在推理时，系统会根据输入图像的实际长宽比，从这些预定义的候选网格中，自动选择一种**最接近**原始图像长宽比的网格划分方案，然后将图像按照选定的网格切分为对应数量的子图块，每个子图块分别独立通过视觉编码器进行编码。与此同时，为了避免切分导致的全局上下文信息丢失（例如一个跨越多个子图块边界的大物体，可能在切分后被割裂），系统还会**额外保留一张整图的低分辨率缩略图**一并编码。最终，所有子图块的特征与这张全局缩略图的特征会被拼接在一起，共同输入语言模型。这种"预定义候选网格 + 缩略图补充全局信息"的设计，相比完全自由的动态分辨率处理，工程实现和训练过程都更加可控（因为候选网格数量有限），同时又比固定单一分辨率的方案更能适应真实世界中长宽比差异巨大的各类图像输入，是 LLaVA-NeXT、InternVL 等当前主流高分辨率 VLM 普遍采用的实用方案。

</details>

**8. 视觉编码器的预训练目标（对比学习 vs 掩码重建）如何影响下游多模态任务表现？**

<details>
<summary>💡 查看答案</summary>

不同的预训练目标会让视觉编码器学习到风格迥异的特征表示，进而影响其在下游多模态任务中的表现特点：

**基于对比学习训练的编码器**（如 CLIP、SigLIP，通过图文对比目标训练）：由于其训练目标直接要求图像特征与对应的文本描述在语义空间中相互靠近，这类编码器学习到的特征天然带有较强的**语义抽象**属性，与自然语言的对齐质量很高，因此在图文检索、零样本分类等需要"理解图像整体在说什么"的任务上表现出色；但由于训练目标关注的是全局语义匹配而非像素级细节重建，这类编码器对局部细节（如精确的纹理、边界形状、微小文字）的保留能力相对较弱。

**基于掩码图像建模训练的编码器**（如 MAE、BEiT，通过随机遮盖部分图像 Patch 再要求模型重建被遮盖内容进行训练）：由于其训练目标是精确重建原始像素或底层视觉特征，这类编码器更擅长捕捉图像的**局部纹理和精细结构**信息，但由于训练过程中完全没有涉及文本监督信号，其学习到的特征与语言语义的对齐能力相对较弱，直接用于图文对齐类任务效果通常不如 CLIP 类编码器。

正因为两类编码器各有所长、优劣互补，不少追求极致性能的工作会尝试同时使用两种（甚至更多种）不同预训练目标训练出的编码器（例如同时使用 CLIP 和 DINOv2 分别提取语义特征和细节特征），将它们的输出特征融合后再输入连接模块，以期兼顾语义对齐能力和细节保真能力。

</details>

**9. 什么是 2D-RoPE？为什么在多模态大模型中逐渐被采用？**

<details>
<summary>💡 查看答案</summary>

RoPE（Rotary Position Embedding，旋转位置编码）最初是为一维文本序列设计的相对位置编码方案，其核心思想是通过对 Query 和 Key 向量施加一个与位置相关的旋转变换，使得 Attention 计算中自然地蕴含了两个 Token 之间的相对位置信息，且这种编码方式具有良好的长度外推特性。

2D-RoPE 是将这一思想从一维序列扩展到二维网格结构：对于图像的每一个 Patch，不再只用一个单一的位置索引表示其位置，而是分别计算其在图像网格中的**行坐标**和**列坐标**，并对这两个坐标分量分别应用旋转位置编码，最终在 Attention 计算过程中，模型能够隐式地感知任意两个 Patch 之间在行方向和列方向上各自的相对位置关系。

相比传统的、需要针对固定 Patch 数量学习的可学习绝对位置编码，2D-RoPE 的优势在于：由于其编码方式是基于相对位置关系的数学变换（而非查表得到的固定向量），不需要像绝对位置编码那样，在推理时遇到与训练时不同的分辨率（对应不同的 Patch 数量）时，还要额外做插值处理来"凑"出一套新的位置编码——2D-RoPE 天然就能够更自然、更平滑地泛化到训练时从未见过的分辨率和长宽比组合，这一特性使其非常契合当前高分辨率、动态分辨率处理已成为主流需求的多模态大模型架构，因此被 Qwen2-VL 等新一代模型广泛采用（并进一步扩展为同时支持视频时间维度的 M-RoPE）。

</details>

**10. 如何处理"多图输入"（一次对话中包含多张图片）的场景？**

<details>
<summary>💡 查看答案</summary>

处理多图输入场景需要在多个层面做专门设计：

- **独立编码**：每张图像分别、独立地通过视觉编码器提取特征，生成各自的视觉 Token 序列，图像之间在编码阶段互不干扰；
- **图像分隔标记**：在最终拼接成的完整 Token 序列中，需要在不同图像对应的视觉 Token 序列之间，插入明确的分隔标记（如 `<image_1>`、`<image_2>` 这类特殊 Token），帮助模型清楚地识别出"这部分 Token 属于第几张图"的边界，避免多张图像的视觉信息在序列中混淆在一起；
- **独立的位置编码**：在设计位置编码时，需要为不同图像的 Patch Token 分配相互独立的空间位置索引（例如每张图像内部的行列坐标都从零开始重新计算），避免出现"第一张图的第 5 行"和"第二张图的第 5 行"被编码为完全相同的位置信息，从而产生位置混淆；
- **专项训练数据**：仅仅在架构层面支持多图输入还不够，还需要在指令微调数据中专门构造涉及多图对比、多图关联推理的样本（例如"比较这两张图片的不同之处""这三张图按时间先后顺序应该如何排列"），才能真正训练模型学会**跨图推理**的能力，而不是把每张图当作孤立的、互不相关的信息孤岛分别处理。

</details>

**11. 什么是 Token Merging / Token Pruning？如何在推理阶段减少视觉 Token 数量？**

<details>
<summary>💡 查看答案</summary>

**Token Merging（Token 合并）**：核心思路是在 Transformer 的某些层之间，计算所有视觉 Token 两两之间的相似度（通常基于 Key 向量而非原始特征，计算成本更低），找出相似度最高的若干 Token 对，将它们按加权平均的方式合并为一个新的代表性 Token（合并权重可以考虑被合并 Token 原本代表的"大小"，避免信息被稀释）。由于图像中大面积的背景、纯色区域等本身就包含大量高度相似的 Patch，合并这些冗余 Token 通常只会损失极少的信息量，却能显著减少序列长度。

**Token Pruning（Token 剪枝）**：与合并不同，剪枝是直接根据某种重要性评分（最常见的是该 Token 在 Attention 计算中获得的注意力权重总和，或者是否被 CLS Token/文本 Query 显著关注）对视觉 Token 排序，直接丢弃评分最低的一部分 Token，而不做任何信息保留处理。

两者的共同点是：都可以作为一种"即插即用"的技巧应用在**推理阶段**（部分方法甚至不需要重新训练模型，只需在推理时的中间层插入合并/剪枝操作），根据实际的延迟或显存预算动态决定压缩比例，因此在对推理成本敏感的部署场景（如需要处理大量并发请求的在线服务、需要处理多图或视频的场景）中被广泛使用；区别在于 Merging 通常能更好地保留信息（代价是需要额外的相似度计算开销），而 Pruning 实现更简单直接（但直接丢弃信息，压缩比过大时容易损失关键细节）。

</details>

**12. ViT 的 Patch Size 大小如何选择？对模型效果和效率有何影响？**

<details>
<summary>💡 查看答案</summary>

Patch Size 决定了将图像切分为多少个"视觉词元"：对于固定分辨率的图像（如 224×224），Patch Size 越小，切分出的 Patch 数量越多（例如 Patch Size=14 时约产生 256 个 Patch，Patch Size=32 时仅产生约 49 个 Patch）。

**对效果的影响**：更小的 Patch Size 意味着每个 Patch 覆盖的原始像素区域更小，模型能够捕捉到更精细的局部视觉细节（如小物体的边缘、文字的笔画），这对于需要细粒度感知的任务（OCR、细粒度分类、图表理解）尤为重要；更大的 Patch Size 则会把更大范围的像素"打包"进同一个 Patch，细节容易被平均/模糊化，尤其容易在处理小目标或密集文字时丢失关键信息。

**对效率的影响**：由于 Self-Attention 的计算复杂度与序列长度的平方成正比，Patch 数量翻倍会导致计算量变为原来的 4 倍，因此更小的 Patch Size 在提升细节捕捉能力的同时，会显著增加计算量和显存占用，也会拉长推理延迟。

**实践权衡**：主流预训练视觉编码器通常提供多个 Patch Size 版本（如 CLIP 提供 ViT-B/32、ViT-B/16、ViT-L/14 等），偏向通用理解、对延迟敏感的应用可以选择较大 Patch Size（如 /32、/16）；偏向细粒度理解（文档、图表、密集小目标检测）的应用则倾向于选择更小的 Patch Size（如 /14），或者干脆通过提高输入分辨率而非减小 Patch Size 来间接增加细节信息（两者都会增加 Patch 数量，但提高分辨率通常对预训练权重的影响更容易通过位置编码插值来适配）。

</details>

**13. 为什么有些模型（如 Fuyu-8B）尝试去掉独立的视觉编码器，直接将图像 patch 输入语言模型？**

<details>
<summary>💡 查看答案</summary>

绝大多数主流 VLM 的架构是"预训练视觉编码器（如 CLIP ViT）+ 连接器 + 语言模型"，这种设计虽然复用了强大的预训练视觉表示，但也带来了一些固有限制：视觉编码器通常是在固定的、相对较低的分辨率上预训练的，处理超出该分辨率范围的图像需要额外的切图、插值等工程处理；同时视觉编码器的预训练目标（如 CLIP 的图文对比）与最终多模态任务的目标未必完全一致，可能存在"表示不匹配"的问题。

Fuyu-8B 这类模型选择了一条不同的路线：**完全去掉独立的视觉编码器**，直接将图像切分出的原始像素 Patch（经过简单的线性投影）当作特殊的"图像 Token"，与文本 Token 一起原样输入到语言模型（本身是一个纯粹的 Decoder-only Transformer）中，让语言模型自己从头学习如何理解这些像素信息。这样设计的动机包括：

- **架构极致简化**：不需要单独训练或维护一个视觉编码器，也不需要设计专门的连接模块，整个模型就是一个统一的 Transformer；
- **天然支持任意分辨率**：由于没有预训练视觉编码器对输入尺寸的固有限制，理论上可以直接处理任意分辨率、任意长宽比的图像，不需要 Resize 或复杂的动态切图策略；
- **更彻底的端到端统一建模**：视觉理解能力完全由语言模型的自回归训练过程中"涌现"出来，而非依赖外部预训练模块提供，更符合"一个模型学会一切"的统一建模哲学。
但这种方式的代价是：失去了预训练视觉编码器已经学到的、经过海量数据验证的通用视觉先验知识，模型需要依靠更大规模的多模态训练数据，从零开始学习基本的视觉模式识别能力，训练难度和数据需求量通常更高。

</details>

**14. 视觉编码器中的"CLS Token"和"Patch Tokens"在多模态任务中分别扮演什么角色？**

<details>
<summary>💡 查看答案</summary>

在 ViT 的输入序列中，除了由图像切分出的各个 Patch 对应的 Token（Patch Tokens）之外，通常还会额外拼接一个特殊的、随机初始化的可学习向量，即 **CLS Token**（Class Token）。这个设计沿袭自 BERT 等文本 Transformer 模型的做法。

**CLS Token 的角色**：由于它与所有 Patch Token 一起经过多层 Self-Attention 计算，会不断"吸收"来自各个 Patch 的信息，因此在最后一层，CLS Token 对应的输出向量通常被视为对整张图像的**全局语义摘要**，适合直接用于需要"整体判断"的任务，例如零样本图像分类（判断整张图属于哪个类别）、图文检索中的全局相似度计算（CLIP 就是用 CLS Token 的输出作为整张图像的表示向量）。

**Patch Tokens 的角色**：每个 Patch Token 在编码过程中主要保留了其对应的局部图像区域的细粒度特征（同时也通过 Self-Attention 融合了一定的全局上下文），适合需要**空间定位和局部细节**的任务，例如视觉定位（需要知道某个物体具体在图像的哪个位置）、细粒度视觉问答（需要关注图像中某个具体局部区域的细节）。

在多模态大模型的实践中，多数 VLM（如 LLaVA）在将视觉特征接入语言模型时，会选择保留**全部（或大部分）Patch Tokens**而非仅使用单一的 CLS Token 向量，因为语言模型需要基于图像的丰富局部细节来回答各种具体问题（而不只是对图像做一个笼统的全局判断），舍弃 Patch Tokens 只用 CLS Token 会造成大量细节信息的损失。

</details>

**15. 如何通过位置编码插值处理输入图像分辨率与训练时预设分辨率不一致的问题？**

<details>
<summary>💡 查看答案</summary>

ViT 在预训练阶段通常固定在某个特定分辨率（例如 224×224）上进行，此时图像会被切分为固定数量的 Patch（如 16×16 个），对应地，模型也学习了一套与该 Patch 数量完全匹配的位置编码（无论是可学习的绝对位置编码矩阵，还是某些相对位置编码方案）。当推理阶段需要处理更高分辨率的图像（对应更多数量的 Patch，例如切分出 32×32 个 Patch）时，预训练好的位置编码矩阵的"尺寸"（对应 16×16 网格）就无法直接覆盖新的、更大的 Patch 网格（32×32）。

常见的解决方法是对位置编码矩阵做**插值**处理：将原始的位置编码矩阵在概念上还原为一个二维网格（如 16×16 个位置向量），然后使用图像处理中常见的插值算法（双线性插值 Bilinear 或双三次插值 Bicubic）将这个二维网格"拉伸"或"压缩"到目标的、更大（或更小）的网格尺寸（如 32×32），插值后的每个位置都能获得一个合理的、由周围原始位置编码平滑过渡而来的新位置向量。这一技巧最早在 ViT 论文中被提出用于处理下游任务的分辨率适配问题，后来也被广泛应用在各类支持动态/高分辨率输入的 VLM 中，使得模型可以在不重新训练位置编码的前提下，较为平滑地泛化到训练时未见过的分辨率。

</details>

**16. 多帧图像（视频）输入时，如何设计位置编码以同时区分空间和时间维度？**

<details>
<summary>💡 查看答案</summary>

处理视频这类同时具有空间（同一帧内的行列位置）和时间（不同帧之间的先后顺序）两个维度的数据时，单纯的二维空间位置编码不足以让模型区分"同一位置不同帧"和"同一帧不同位置"这两种完全不同的关系，因此需要专门设计能同时表达这两个维度的位置编码方案，常见做法包括：

- **分离叠加式**：每个视觉 Patch Token 除了拥有描述其在当前帧内行列位置的二维空间位置编码外，再额外附加一个专门表示其所属帧序号的时间位置编码，两者通过相加或拼接的方式组合成该 Token 最终的完整位置表示，使模型能够同时感知"空间结构"（同一帧内哪些 Patch 相邻）和"时序结构"（不同帧之间的先后顺序）；
- **统一的多维旋转位置编码**：如 Qwen2-VL 的 M-RoPE 方案，将位置编码显式拆分为时间、高度、宽度三个独立分量，对视频的每个 Patch，分别根据其所属帧号、在帧内的行坐标、列坐标为三个分量分别赋值，用同一套旋转位置编码框架自然统一地处理图像（时间分量恒定）、视频（三个分量都变化）乃至纯文本（三个分量退化为一致，等同于一维 RoPE）。
这类设计的核心目标都是让模型在计算 Attention 时，能够根据两个 Token 之间的"空间距离"和"时间距离"分别施加合理的相对位置偏置，从而正确建模视频中物体的空间关系和时序动态变化。

</details>

**17. 什么是 Pixel Shuffle 操作？它在 Qwen2-VL / InternVL 等模型中如何用于压缩视觉 Token？**

<details>
<summary>💡 查看答案</summary>

Pixel Shuffle 最初是图像超分辨率任务中的一种上采样操作：它将一个通道数较多、空间分辨率较低的特征图，通过重新排列（Reshape）的方式，把"通道维度"的信息转移到"空间维度"上，从而在不引入额外参数、不做插值的情况下提升特征图的空间分辨率（即通道数变少、长宽变大）。

在多模态大模型的视觉 Token 压缩场景中，做法正好相反——是把 Pixel Shuffle 的操作**反向使用**：将空间分辨率较高（Patch 数量多）、通道数较少的视觉特征，通过同样的重排方式，把"空间维度"的信息转移到"通道维度"上，使得空间分辨率降低（Patch/Token 数量减少）而每个 Token 的特征维度相应增大。例如将相邻的 2×2 个 Patch Token 在空间上"折叠"进 1 个 Token 中，同时该 Token 的特征维度扩大为原来的 4 倍，这样就将视觉 Token 数量直接压缩为原来的四分之一，而不需要像简单平均池化那样直接丢弃信息——理论上原始的全部特征信息都被保留下来，只是被重新排列进了更少数量、更高维度的 Token 中，再通过后续的线性层将维度投影回语言模型所需要的大小。

这种操作被 Qwen2-VL、InternVL 等模型广泛采用，是应对"高分辨率/多图输入导致视觉 Token 数量爆炸"问题的一种高效、几乎无损、且不需要额外注意力计算开销的压缩手段，相比 Q-Former 这种需要额外训练 Cross-Attention 模块的压缩方式更加轻量。

</details>
