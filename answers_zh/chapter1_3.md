**1. 大模型 LLM 的训练目标是什么？**

<details>
<summary>💡 查看答案</summary>

根据已有词预测下一个词，训练目标为最大似然函数：

**训练效率**：
- Prefix Decoder $<$ Causal Decoder
- Causal Decoder 结构会在所有 token 上计算损失，而 Prefix Decoder 只会在输出上计算损失。

随机替换掉一些文本段，训练语言模型去恢复被打乱的文本段。目标函数为：

$$
    \mathcal{L} = -\sum_{i} \log P(w_i | w_{<i})
$$


**去噪自编码器**：
- 实现难度更高
- 采用去噪自编码器作为训练目标的任务有 GLM-130B、T5

**2. LLM 通常是通过什么方式训练的？**

<details>
<summary>💡 查看答案</summary>

LLM 训练的核心是一个基于 Transformer 的神经网络，拥有数十亿参数。这些参数连接各层的节点，使模型能够学习复杂的关联关系。LLM 在大规模的高质量文本和代码数据集上进行训练。这些数据为模型提供了学习语言模式的原材料。在训练过程中，模型会根据前面的词预测序列中的下一个词。然后，它会调整内部参数以改进预测，本质上是通过大量的示例进行自我学习。训练完成后，LLM 可以针对特定任务进行微调。

</details>

**3. L1和L2正则化分别是什么，什么场景适合使用呢？**

<details>
<summary>💡 查看答案</summary>

L1和L2正则化都是在机器学习和深度学习中用于防止模型过拟合的常用技术。它们通过在模型的损失函数（Loss Function）中添加一个代表模型复杂度的惩罚项来实现这一目标。


	**L1 正则化**

- 定义： L1正则化添加的惩罚项是模型所有权重参数 $w_i$ 的绝对值之和，乘以一个正则化系数 $\lambda$。

\[Loss_{L1} = Original Loss + \lambda \sum_{i} |w_i|\]


- 核心作用：产生稀疏性 (Sparsity)。

在梯度下降优化过程中，L1惩罚项会驱使那些对模型贡献不大的特征的权重最终变为精确的0。这相当于从模型中完全移除了这些特征。

- 适用场景：特征选择 (Feature Selection)。

当你的数据集中包含大量特征，但你怀疑其中许多特征是冗余或无用的时，L1正则化非常有用。它能够自动地“筛选”出最重要的特征，简化模型，提高解释性。


	**L2 正则化**

- 定义： L2正则化添加的惩罚项是模型所有权重参数 $w_i$ 的平方和，乘以一个正则化系数 $\lambda$。

\[Loss_{L2} = Original Loss + \lambda \sum_{i} w_i^2\]


- 核心作用：权重衰减 (Weight Decay)。

L2正则化会惩罚大的权重值，它会促使模型的权重参数尽可能小，趋近于0但通常不会等于0。这使得模型的权重分布更加平滑和分散，避免模型过度依赖少数几个高权重的特征。

- 适用场景：通用性的过拟合防治。

L2是更常用、更通用的正则化方法。当特征之间可能存在相关性（共线性），或者你认为绝大多数特征都对预测有或多或少的贡献时，L2是首选。它能有效地提高模型的泛化能力，使其在未见过的数据上表现更好。在深度学习中，“权重衰减”通常就是指L2正则化。


总结对比： | 对比项       | L1 正则化                              | L2 正则化                | | :----------- | :------------------------------------- | :----------------------- | | 惩罚项   | 权重的绝对值之和 (L1范数)              | 权重的平方和 (L2范数)    | | 效果     | 权重稀疏化，部分权重为0                | 权重平滑化，权重趋近于0  | | 主要用途 | 特征选择，简化模型                     | 防止过拟合，提升泛化能力 | | 解的特性 | 不稳定，数据微小变动可能导致特征集变化 | 稳定，解是唯一的         |

</details>

**4. 在训练一个百或千亿参数级别的 LLM 时，你会面临哪些主要的工程和算法挑战？（例如：显存、通信、训练不稳定性等）**

<details>
<summary>💡 查看答案</summary>

训练百亿或千亿参数级别的LLM是一个巨大的系统工程，涉及硬件、软件和算法的深度协同。其挑战主要体现在以下三个方面：


1. 显存挑战 (Memory Wall):

- 问题： 一个千亿参数的模型，其模型参数、梯度、优化器状态（如Adam中的动量和方差）加起来需要数TB的存储空间，远远超出了任何单张GPU的显存（目前最先进的H100也只有80GB）。
- 解决方案（3D并行）：
- 数据并行 (Data Parallelism, DP): 最基础的并行方式。在每张卡上都保留一份完整的模型副本，但将数据切分成多个batch，每张卡处理一个batch。计算完成后通过All-Reduce操作同步梯度。这种方式不能解决单卡显存不足的问题。
- 流水线并行 (Pipeline Parallelism, PP): 将模型的层（layers）进行垂直切分，不同的GPU负责模型的一部分（例如，GPU-1负责1-16层，GPU-2负责17-32层）。这可以有效降低单卡显存，但会引入“流水线气泡”（pipeline bubbles），即部分GPU在等待上下游数据时会处于空闲状态。
- 张量并行 (Tensor Parallelism, TP): 将模型中的单个大算子（如大的权重矩阵）进行水平切分，放到不同的GPU上协同计算。例如，将一个大的矩阵乘法分解到多张卡上。这也能降低单卡显存，但会引入非常高的通信开销。
- ZeRO (Zero Redundancy Optimizer): 由微软DeepSpeed提出的显存优化技术。它在数据并行的基础上，将优化器状态、梯度、甚至模型参数也进行切分，分布到所有GPU上。每个GPU只保留自己需要计算的那一部分，极大地降低了单卡的显存冗余，是目前大规模训练的标配。

1. 通信挑战 (Communication Bottleneck):

- 问题： 上述所有并行策略都引入了大量的GPU间通信。例如，DP需要同步梯度，PP需要传递激活值，TP需要在每次前向和后向传播中交换计算结果。当GPU数量巨大时，通信所需的时间可能超过计算本身，成为整个训练的瓶颈。
- 解决方案：
- 硬件层面： 使用高速互联技术，如单机内的NVLink和跨节点的InfiniBand网络。
- 软件层面： 开发高效的通信算法（如Ring All-Reduce），并设计调度策略来将计算和通信操作重叠（overlap），以隐藏通信延迟。

1. 训练不稳定性挑战 (Training Instability):

- 问题： 训练如此巨大的模型在数值上非常脆弱。由于计算层数极深、数据量极大，训练过程中很容易出现梯度爆炸或消失，导致损失（Loss）突然飙升为NaN（Not a Number），使得数小时甚至数天的训练成果毁于一旦。
- 解决方案：
- 数值精度： 普遍采用 BF16 (BFloat16) 混合精度训练。BF16相比FP16有更大的动态范围，能有效避免梯度下溢，同时保持FP32的稳定性。同时，关键部分（如优化器的master weights）仍保留FP32以保证精度。
- 稳定的模型架构： 采用更稳定的架构设计，如Pre-LayerNorm（在自注意力和FFN之前进行层归一化），以及使用更平滑的激活函数如GeLU/SwiGLU。
- 梯度裁剪 (Gradient Clipping): 设定一个梯度的范数上限，如果计算出的梯度超过这个阈值，就将其缩放到阈值以内，这是防止梯度爆炸最直接有效的方法。
- 学习率调度与预热 (Learning Rate Scheduling & Warmup): 采用精心设计的学习率调度策略，如在训练初期使用一个较小的学习率并逐渐增大的“预热”阶段，有助于模型在训练早期稳定下来。

**5. LLaMA 模型输入句子理论上可以无限长吗？为什么？**

<details>
<summary>💡 查看答案</summary>

**理论上不能无限长**，主要受以下限制：

1. **位置编码的外推能力有限**：当推理时的序列长度远超训练时见过的长度，模型对超出训练分布的位置编码组合仍会表现退化，除非配合长度外推技术。
2. **自注意力的计算/显存复杂度为 O($n^2$)**：序列长度 $n$ 增加时，注意力矩阵的计算量和显存占用按平方增长，KV cache 按线性增长，实际硬件资源会成为硬性瓶颈。
3. **训练时上下文窗口是固定的**：模型在训练阶段只见过特定最大长度的序列，超出该长度的位置组合是"分布外"的。

实际可处理的长度受**架构（位置编码外推性）、硬件资源（显存/计算）、训练时设定的上下文窗口**三方面共同制约。

</details>

**6. 如何让大模型处理更长的文本？**

<details>
<summary>💡 查看答案</summary>

1. **改进位置编码/外推方法**：位置插值（Position Interpolation）/ NTK-aware scaling、YaRN、ALiBi 等。
2. **继续训练/微调以适配长上下文**：在更长的序列数据上做继续预训练或微调。
3. **优化注意力计算**：Flash Attention 降低显存占用；稀疏注意力/滑动窗口注意力将复杂度从 O($n^2$) 降到接近 O($n$)。
4. **KV Cache 优化**：使用 MQA/GQA/MLA 等结构减少 KV cache 的显存占用。
5. **分块处理 + 检索/摘要**：将超长文本切分，结合 RAG 或滚动摘要。
6. **架构层面的创新**：如状态空间模型（Mamba）、线性注意力等理论上具有线性复杂度的架构。

</details>

**7. 在LLM的推理阶段有哪些常见的解码策略？**

<details>
<summary>💡 查看答案</summary>

在LLM的推理（或称解码）阶段，模型会生成一个词元概率分布，解码策略决定了如何从这个分布中选择下一个词元。常见的策略可以分为确定性和随机性两类。


	extbf{1. Greedy Search}

- 原理： 在每个时间步，总是选择当前概率分布中概率最高的那个词元作为输出。
- 优点：
- 速度快： 计算开销最小，实现最简单。
- 缺点：
- 局部最优： 每一步的“贪心”选择可能导致整个序列不是全局最优的。一个高概率的词后面可能跟着一系列低概率的词，最终序列的总概率反而不高。
- 缺乏多样性： 输出是完全确定的，对于同一个输入，每次生成的结果都一样，内容往往比较呆板、重复。

	extbf{2. Beam Search}

- 原理： 这是对贪心搜索的改进。它在每个时间步会保留 $k$ 个（ $k$ 称为 "beam width" 或 "beam size"）最有可能的候选序列。在下一步，它会从这 $k$ 个候选序列出发，生成所有可能的下一个词元，然后从所有这些扩展出的新序列中，再次选出累计概率最高的 $k$ 个。最后，从最终的 $k$ 个完整序列中选择最优的一个。
- 优点：
- 质量更高： 通过探索更广的搜索空间，通常能找到比贪心搜索概率更高、质量更好的序列。
- 缺点：
- 计算成本高： 需要维护 $k$ 个候选序列，计算和内存开销是贪心搜索的 $k$ 倍。
- 仍然倾向于安全和高频： 优化目标是全局概率，这使得它还是倾向于生成常见、安全的句子，可能缺乏创造性，并且在长文本生成中容易出现重复。

	extbf{3. Top-K Sampling}

- 原理： 这是一种随机采样策略。在每个时间步，不再是选择最优的，而是：

1. 从整个词汇表的概率分布中，筛选出概率最高的 $K$ 个词元。
2. 将这 $K$ 个词元的概率进行归一化（使它们的和为1）。
3. 在这 $K$ 个词元中，根据新的概率分布进行随机采样。

- 优点：
- 增加多样性： 引入了随机性，使得生成内容更加丰富、有趣和不可预测。
- 避免低概率词： 通过限制在Top-K范围内，过滤掉了那些概率极低、可能不通顺或奇怪的词元。
- 缺点：
- K值固定： $K$ 是一个固定的超参数。当概率分布很尖锐时（模型非常确定下一个词），一个大的K可能会引入不相关的词；当概率分布很平坦时（模型不确定），一个小的K可能会限制模型的选择。

	extbf{4. Nucleus Sampling / Top-P Sampling}

- 原理： 这是对Top-K采样的改进，它使用一个动态的候选词元集。

1. 将所有词元按概率从高到低排序。
2. 从概率最高的词元开始，逐个累加它们的概率，直到总概率之和超过一个预设的阈值 $p$（例如 $p=0.95$）。
3. 这个累加过程中包含的所有词元构成了“核心（Nucleus）”候选集。
4. 然后，在这个动态大小的候选集中，根据它们的原始概率进行归一化和随机采样。

- 优点：
- 自适应候选集： 候选集的大小会根据上下文动态变化。当模型对下一个词非常确定时，概率分布尖锐，可能只有一两个词的概率和就超过了 $p$，候选集就很小，生成更精确；当模型不确定时，概率分布平坦，需要包含更多词才能达到 $p$，候选集就变大，允许更多探索。
- 兼顾质量与多样性： 相比Top-K，它是一种更原则性和鲁棒性的方法，是目前大多数LLM应用默认的采样策略。

**8. 解释 LLM 文本生成中的温度概念**

<details>
<summary>💡 查看答案</summary>

温度是一个参数，通过调整标记的概率分布来控制语言模型输出的随机性。
- **低温度（$<1$）**：使输出更具确定性和专注性。模型优先选择高概率标记，减少多样性。
- **高温度（$>1$）**：通过使标记概率更均匀来增加变异性。适用于创造性和多样化的输出。

</details>

**11. 混合精度训练（FP16/BF16）是什么？它的优缺点是什么？**

<details>
<summary>💡 查看答案</summary>

**原理**：将模型前向/反向计算中的大部分操作使用半精度（FP16 或 BF16）进行，同时在优化器中保留一份 FP32 的主权重（Master Weights）用于参数更新，兼顾速度和精度。
    **优点**：
    - 显存占用减少约一半
    - GPU 半精度计算速度更快（Tensor Core 加速）
    - 通信量减少，分布式训练更高效
    **缺点**：
    - FP16 数值范围小，容易出现梯度下溢/上溢，需配合损失缩放（Loss Scaling）
    - BF16 数值范围大（与 FP32 相同），更稳定，但精度略低，现代大模型更倾向于使用 BF16

</details>

**12. 梯度累积和梯度检查点分别是什么，解决什么问题？**

<details>
<summary>💡 查看答案</summary>

**梯度累积（Gradient Accumulation）**：
    - 问题：显存不足时无法使用大 batch size
    - 方法：将 N 个小 batch 的梯度累加后再做一次参数更新，等效于更大的 batch size
    - 代价：训练时间增加，但不增加显存
    **梯度检查点（Gradient Checkpointing / Activation Recomputation）**：
    - 问题：前向传播的中间激活值需要保存用于反向传播，层数多时占用大量显存
    - 方法：只保存关键节点的激活值，反向传播时重新计算其余节点
    - 代价：增加约 30%~40% 的计算量，但显存占用大幅降低

</details>

**13. 大模型推理时显存为什么会持续占用且增长？**

<details>
<summary>💡 查看答案</summary>

推理显存由以下几部分构成：
    - **模型权重**：固定占用，加载后不释放
    - **KV Cache**：随生成序列长度线性增长，是推理显存增长的主要原因。每生成一个新 token，所有层的 K、V 向量都要追加到 Cache 中
    - **激活值**：当前 token 前向计算的中间结果，每步都会产生但相对较小
    - **批处理**：batch size 越大，KV Cache 和激活值占用越多
    因此，长序列推理时显存持续增长主要是 KV Cache 膨胀导致的。

</details>

**14. 大模型在 GPU 和 CPU 上的推理速度差异如何？**

<details>
<summary>💡 查看答案</summary>

- **GPU 推理**：GPU 拥有数千个并行计算单元，擅长大规模矩阵乘法（Attention、FFN），推理速度快。7B 模型在 A100 上可达 50~100 tokens/s
    - **CPU 推理**：CPU 核心数少，缺乏矩阵并行计算优势，推理速度慢数十倍。7B 模型量化后在现代 CPU 上约 5~20 tokens/s
    - **适用场景**：GPU 适合高并发在线推理；CPU 推理配合量化（如 llama.cpp）适合本地轻量部署，无 GPU 资源时的备选方案

</details>

**15. 推理速度上，INT8 量化和 FP16 相比怎么样？**

<details>
<summary>💡 查看答案</summary>

- **INT8 量化**：将权重和/或激活值从 FP16（2字节）量化为 INT8（1字节），显存减少约 50%，在支持 INT8 Tensor Core 的显卡（如 A100、RTX 3090）上速度提升 1.5~2 倍
    - **FP16**：精度更高，数值稳定，是目前大模型推理的主流精度
    - **精度损失**：INT8 量化通常有轻微精度损失，需要校准（Calibration）；使用 SmoothQuant、GPTQ 等方法可将损失控制在可接受范围内
    - **实践建议**：吞吐量敏感场景选 INT8；精度敏感场景（如数学推理）选 FP16

</details>

**16. 什么是模型量化？常见的量化方法有哪些？**

<details>
<summary>💡 查看答案</summary>

**模型量化**：将模型权重或激活值从高精度浮点数（FP32/FP16）转换为低比特整数（INT8、INT4 等），以减少显存占用和加速推理。
    **常见方法**：
    \begin{table}[h]



| **方法** | **量化对象** | **特点** |
| --- | --- | --- |
| **GPTQ** | 权重（INT4） | 逐层量化，精度损失小，适合大模型 |
| **AWQ** | 权重（INT4） | 关注激活值大小保护重要权重，精度优于 GPTQ |
| **SmoothQuant** | 权重+激活（INT8） | 将激活值的量化难度迁移到权重上 |
| **BitsAndBytes** | 权重（INT8/NF4） | 与 Transformers 深度集成，易用 |
| **GGUF/llama.cpp** | 权重（2~8bit） | 专为 CPU 推理设计，多种精度可选 |


    \end{table}

**17. 有哪些省内存的大语言模型推理优化方法？**

<details>
<summary>💡 查看答案</summary>

- **KV Cache 优化**：MQA、GQA 减少 KV 头数，PagedAttention（vLLM）动态管理 KV Cache 显存
    - **模型量化**：INT8/INT4 量化，显存减少 50%~75%
    - **Flash Attention**：减少 Attention 计算的 HBM 读写
    - **连续批处理（Continuous Batching）**：动态调度不同长度请求，提高 GPU 利用率
    - **投机采样（Speculative Decoding）**：用小模型预测多个 token，大模型并行验证，减少串行生成步骤
    - **模型并行推理**：将模型分布在多卡上，突破单卡显存限制

</details>

**18. 如何让大模型输出更合规、可控？**

<details>
<summary>💡 查看答案</summary>

- **Prompt 约束**：在系统提示中明确输出格式、内容范围和禁止行为
    - **输出过滤**：在模型输出后接入内容审核模块，过滤违规内容
    - **RLHF / DPO 对齐**：在训练阶段引导模型拒绝有害请求
    - **格式控制**：使用结构化输出（如 JSON Schema 约束）或 Logits 约束强制输出特定格式
    - **温度和采样参数**：降低 temperature 使输出更确定，Top-P 控制词汇多样性
    - **RAG 事实约束**：结合检索结果限制模型只能基于给定文档回答，减少幻觉
    - **人工审核兜底**：高风险场景引入人工审核环节

</details>
