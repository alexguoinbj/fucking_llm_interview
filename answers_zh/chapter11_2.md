# 11.2 高效训练与模型压缩 — 题目与答案
> [⬅ 返回目录](../README_ZH.md) · 第 11 章：前沿话题与综合设计 · 共 15 题

**1. 小模型高效训练的技术路线有哪些？**

<details>
<summary>💡 查看答案</summary>

小模型高效训练的主要技术路线：

1. **知识蒸馏（Knowledge Distillation）**：用大模型（教师）指导小模型（学生）训练，传递软标签、中间层特征、推理路径（如 Distil-BERT、TinyLLaMA）；
2. **数据高效训练**：精心筛选高质量小数据集（如 Phi 系列用"教科书级别"合成数据），证明数据质量远比数量重要；
3. **架构搜索（NAS）**：针对特定部署约束自动搜索最优小模型架构（如 MobileNet、EfficientNet 思路在 LLM 上的迁移）；
4. **结构化剪枝**：在训练后对大模型的注意力头、层、神经元进行重要性评估后剪枝，再微调恢复性能；
5. **量化感知训练（QAT）**：在训练阶段模拟低比特量化，使模型对量化误差鲁棒，部署时可用 INT4/INT8 推理；
6. **预训练课程设计**：从简单到复杂的数据课程学习（Curriculum Learning），提高小模型的训练效率；
7. **任务特化**：放弃通用能力，专注特定领域（如代码、对话、翻译），以专换精。

</details>

**2. 模型压缩未来有哪些新方向？**

<details>
<summary>💡 查看答案</summary>

模型压缩的前沿方向：

1. **超低比特量化（1-2 bit）**：BitNet b1.58 探索 1.58 bit 量化训练，将权重限制在 {-1, 0, +1}，在保持性能的同时极大降低存储和推理成本；
2. **量化感知训练（QAT）的规模化**：将 QAT 扩展到百亿参数模型，使量化误差在训练阶段被充分补偿；
3. **结构化稀疏（Structured Sparsity）**：硬件友好的 N:M 稀疏（如 2:4 稀疏），可被 Ampere 架构 GPU 硬件加速；
4. **知识蒸馏 + 数据合成**：用大模型生成高质量合成数据蒸馏小模型，减少对真实标注数据的依赖（Phi 系列的成功验证了这条路线）；
5. **层剪枝与宽度剪枝的联合优化**：同时优化层数和隐藏维度，找到 Pareto 最优的体积-性能边界；
6. **动态计算图（Early Exit）**：根据输入难度自适应决定计算深度，简单输入早退出，复杂输入完整计算；
7. **神经架构搜索（NAS）与压缩联合设计**：从架构设计阶段就融入压缩约束，而非事后压缩。

</details>

**3. 无监督微调是否可行？**

<details>
<summary>💡 查看答案</summary>

无监督微调（无标注数据的微调）是一个活跃的研究方向：

**已有的可行方案：**
1. **自监督目标继续预训练**：用 MLM、Next Token Prediction 等自监督目标在领域数据上继续训练，无需标注（Domain-Adaptive Pretraining）；
2. **对比学习微调**：用无标注数据做对比学习，学习更好的表示（SimCSE 用 Dropout 制造正样本）；
3. **Self-Play 和 Self-Instruct**：模型自己生成指令-回答对，再微调自身；
4. **无监督奖励建模**：用人类行为数据（点击、停留时长）作为隐式反馈，替代显式标注。

**挑战：**
- 无监督信号可能与下游任务目标不对齐；
- 质量控制困难：自生成数据可能引入噪声和偏差；
- 能力提升有上限：无法突破模型的知识边界。

**结论：** 无监督微调在领域适配（Domain Adaptation）和表示学习方面是可行的，但在任务特化和对齐方面仍需有监督信号的辅助。

</details>

**4. 知识蒸馏在大模型训练中如何应用？**

<details>
<summary>💡 查看答案</summary>

知识蒸馏（Knowledge Distillation）的基本思路是：用大模型（Teacher）的输出（软标签/logits 分布，或中间层特征）指导小模型（Student）训练，使 Student 在更小参数量下逼近 Teacher 的能力。

**在大模型场景下的常见形式：**
1. **输出层蒸馏**：让 Student 学习匹配 Teacher 的输出概率分布（如最小化两者的 KL 散度），相比单纯的 one-hot 标签包含更多"暗知识"（不同类别/token 间的相对关系）；
2. **数据蒸馏**：用 Teacher 模型生成大量高质量训练数据（含详细推理过程），再用这些数据对 Student 做 SFT，这是当前大模型蒸馏中最常用、工程上最简单直接的方式；
3. **中间层/注意力蒸馏**：对齐 Teacher 和 Student 的隐藏状态或注意力分布，常见于同架构、逐层对应关系明确的压缩场景。

**挑战：** Student 容量有限时无法完全复现 Teacher 的全部能力，蒸馏数据的领域覆盖度和多样性直接决定了 Student 的能力上限。

</details>

**5. 什么是 LoRA / QLoRA？它们如何降低微调成本？**

<details>
<summary>💡 查看答案</summary>

**LoRA（Low-Rank Adaptation）：** 冻结预训练权重 $W$，在旁路引入低秩分解矩阵 $\Delta W = BA$（$B \in \mathbb{R}^{d\times r}$，$A \in \mathbb{R}^{r\times k}$，$r \ll d, k$），训练时只更新 $A, B$，大幅减少可训练参数量（通常降低至原参数量的 0.1%–1%）。

**优势：**
- 显存占用大幅下降，无需存储原始权重对应的梯度和优化器状态；
- 推理时可将 $BA$ 合并回原权重，不引入额外推理延迟；
- 可为不同任务训练多套独立的 LoRA 权重，按需加载切换，便于多任务/多租户场景。

**QLoRA：** 在 LoRA 基础上进一步将底座模型量化为 4-bit（如 NF4 数据类型），并结合双重量化（Double Quantization）和分页优化器（Paged Optimizer）进一步降低显存占用，使得在单张消费级 GPU 上微调数十亿参数模型成为可能。

**局限：** 秩 $r$ 的选择影响效果上限；任务差异较大或需要改变模型底层能力时，LoRA 的表达能力可能不足，仍需全参数微调。

</details>

**6. 结构化剪枝与非结构化剪枝有什么区别？**

<details>
<summary>💡 查看答案</summary>

**非结构化剪枝（Unstructured Pruning）：** 按权重重要性（如绝对值大小）独立地将部分权重置零，剪枝粒度细、理论压缩率高，但产生的稀疏矩阵不规则，难以在通用硬件（GPU）上获得实际加速，需要专门的稀疏计算库支持才能发挥收益。

**结构化剪枝（Structured Pruning）：** 按照通道（channel）、注意力头（head）、层（layer）等结构化单元整体移除，剪枝后模型仍是稠密矩阵，可以直接获得推理加速和显存节省，工程落地更容易。

**权衡：**
- 结构化剪枝粒度较粗，同等压缩率下精度损失通常大于非结构化剪枝；
- 实践中常结合两者，或剪枝后配合少量继续训练（fine-tune / 知识蒸馏）恢复精度；
- 大模型场景下更倾向结构化剪枝（如剪注意力头、剪 MLP 中间维度、甚至剪整层），因为其对推理硬件更友好，能直接转化为实际的延迟和显存收益。

</details>

**7. 当前主流的量化方案（GPTQ / AWQ / FP4 等）各自的核心思路是什么？**

<details>
<summary>💡 查看答案</summary>

模型量化是把权重（有时也包括激活值）从 FP16/BF16 压缩到更低比特（INT8/INT4/FP4）表示，以降低显存占用和访存量。

- **GPTQ**：基于二阶信息（近似 Hessian）的逐层量化方法，在量化某一层的权重时，利用未量化权重的梯度信息去补偿已量化权重引入的误差，实现训练后量化（PTQ）下较小的精度损失，且量化过程不需要重新训练；
- **AWQ（Activation-aware Weight Quantization）**：观察到并非所有权重对精度同等重要，而是与之相乘的激活值幅度较大的权重通道更重要；因此 AWQ 通过分析激活值分布，对少量"显著权重通道"做保护性缩放，再统一量化，从而在几乎不增加计算开销的前提下保留关键精度；
- **FP4 / MXFP4 等新型低精度格式**：相比传统 INT4 使用统一的整数量化步长，浮点格式在小范围内保留了指数位，能更好地表示数值分布中的长尾，配合硬件对应的 Tensor Core 支持（如 Blackwell 架构），在相近比特数下精度损失更小。

**共同的权衡：** 量化比特数越低，显存和带宽收益越大，但对模型能力（尤其是复杂推理、长链条任务）的损伤也越明显，通常需要结合校准数据集和逐层敏感度分析来决定哪些层可以量化到更低精度、哪些层需要保留较高精度。

</details>

**8. FP8 混合精度训练相比 BF16 训练有什么优势和风险？**

<details>
<summary>💡 查看答案</summary>

**优势：** FP8 相比 BF16 进一步减少了每个数值的存储位宽，理论上可以带来接近2倍的计算吞吐提升和显存节省，在千卡甚至万卡规模的预训练中，这种效率提升会直接转化为可观的成本降低（DeepSeek-V3 等模型的训练成本大幅降低即与此类技术相关）。

**风险与应对：**
- FP8 的动态范围远小于 FP32/BF16，训练中容易出现数值溢出或下溢，尤其是梯度和优化器状态对精度更敏感；
- 常见的应对方案包括：对不同张量（权重、激活、梯度）使用细粒度的、逐 tensor 或逐 block 的动态缩放因子；关键路径（如优化器状态、归一化层、损失计算）仍保留更高精度；
- 训练稳定性需要额外的监控机制（如溢出检测、自动回退到高精度重算）来兜底，工程复杂度显著高于纯 BF16 训练。

</details>

**9. ZeRO 系列优化器状态分片相比传统数据并行有什么优势？**

<details>
<summary>💡 查看答案</summary>

传统数据并行（DP）中每张卡都保存完整的模型参数、梯度和优化器状态副本，显存冗余度高，模型规模越大冗余浪费越明显（尤其是 Adam 类优化器的动量和方差状态往往是参数量的 2 倍以上）。

**ZeRO 的核心思路：** 将优化器状态、梯度、参数按阶段逐步切分到不同 GPU 上：
1. **ZeRO-1**：只切分优化器状态，每张卡只保存并更新自己负责的那部分状态；
2. **ZeRO-2**：在 ZeRO-1 基础上进一步切分梯度；
3. **ZeRO-3**：连参数本身也切分，每张卡在前向/反向传播需要某层参数时通过 All-Gather 临时拉取，用完即释放。

**代价：** 切分程度越高，显存节省越大，但通信开销（All-Gather / Reduce-Scatter）也越大，因此 ZeRO-3 通常需要较高带宽的互联（如 NVLink）才能避免通信成为新瓶颈；实践中常与张量并行、流水线并行组合使用，根据集群拓扑选择合适的切分组合。

</details>

**10. 训练阶段的激活重计算（Activation Checkpointing）如何权衡显存与计算量？**

<details>
<summary>💡 查看答案</summary>

前向传播过程中保存所有中间激活值以供反向传播使用会占用大量显存，尤其是层数很深、序列很长时。激活重计算的思路是：只保存少数关键"检查点"处的激活值，其余激活值在反向传播需要时**重新执行一次前向计算**得到，以计算量换显存。

- **选择性重计算**：并非所有子层都值得重算，通常优先对计算量小但显存占用大的操作（如 Attention 中的中间张量）做重计算，而对计算量本身很大的操作（如大矩阵乘法）保留激活值，从而在增加的计算开销和节省的显存之间取得更优权衡；
- **典型代价**：全量重计算通常带来约 20%-30% 的训练时间增加，换取数倍的显存节省，这一权衡使得在给定硬件下可以训练更大的模型或使用更大的 batch size。

</details>

**11. 课程学习（Curriculum Learning）在大模型训练中的价值是什么？**

<details>
<summary>💡 查看答案</summary>

课程学习指按照由易到难、由简单到复杂的顺序组织训练数据或任务，而非随机打乱训练。

**在大模型训练中的应用：**
- **数据难度课程**：如前面提到的"用小型验证模型评估数据难度与价值"的方法，在预训练阶段优先安排高质量、适中难度的数据，在训练后期逐步引入更难、更长尾的数据；
- **长度课程**：长上下文训练通常采用"先短后长"的渐进式策略，先在较短序列上训练打好基础能力，再逐步扩展到目标长度，既能提升训练效率（短序列训练更快），也有助于长序列训练的稳定性；
- **任务难度课程**：在推理能力训练（RL 阶段）中，从简单题目逐步过渡到高难度题目，有助于避免模型在训练初期因奖励信号过于稀疏（几乎全部失败）而无法有效学习。

**注意事项：** 课程设计需要可靠的难度评估手段，如果难度评估本身有偏差，课程学习可能起到反效果（如让模型过早接触超出当前能力的样本，导致训练不稳定）。

</details>

**12. 合成数据训练大模型存在什么风险？什么是"模型崩溃"（Model Collapse）？**

<details>
<summary>💡 查看答案</summary>

随着高质量真实数据逐渐稀缺，越来越多训练流程引入模型自己（或其他模型）生成的合成数据。

**模型崩溃的机制：** 如果一代模型的输出被大量用作下一代模型的训练数据，且这个过程反复迭代，模型会逐渐"忘记"真实数据分布中的低概率尾部信息，只保留和强化分布中概率较高的部分，多轮迭代后生成内容的多样性坍缩、错误被不断放大和固化，这种现象被称为模型崩溃。

**缓解方法：**
- 保持合成数据与真实数据混合训练，而非完全替代真实数据；
- 对合成数据做严格的质量过滤和多样性控制（如前述用小型验证模型评估价值），而非无差别使用；
- 引入外部验证信号（如可执行代码的运行结果、数学题的答案校验）来保证合成数据本身的正确性，而不是纯粹依赖模型自我生成再自我训练的闭环。

</details>

**13. 什么是测试时训练（Test-Time Training, TTT）？它与 Test-Time Compute 有什么不同？**

<details>
<summary>💡 查看答案</summary>

Test-Time Compute（如多次采样 + verifier 选择）在推理时只做**前向推理**，不更新任何模型参数；而 **Test-Time Training** 在推理阶段针对当前输入样本，用少量梯度更新步骤临时调整模型（或部分模型参数，如 LoRA 适配器），使模型更好地拟合当前样本的分布特征，推理完成后这些临时更新通常会被丢弃或重置。

**适用场景：** 对于分布偏移明显、每个样本内部有较强局部规律性的任务（如某些长文本的上下文内特定模式、结构化数据推理）中，TTT 能够比纯粹的上下文学习获得更好的样本内适配效果。

**代价：** 每个样本都需要额外的前向 + 反向传播开销，推理延迟和成本显著高于普通推理，目前更多用于对延迟不敏感、对精度要求高的场景，而非低延迟在线服务。

</details>

**14. 什么是模型合并（Model Merging）？相比集成学习（Ensemble）有什么优势？**

<details>
<summary>💡 查看答案</summary>

模型合并是指将多个基于同一基座训练出的、具有不同能力侧重的模型（如分别在代码、数学、对话上微调的版本）的参数直接进行加权平均或更复杂的插值组合，得到一个融合了多种能力的单一模型，而不需要重新训练。

- **简单加权平均（Model Soup）**：直接对多个模型的参数取（加权）平均，代价几乎为零，在很多场景下能取得比单一模型更好的泛化效果；
- **任务向量（Task Vectors）加减法**：将"微调后模型参数 - 基座模型参数"视为一个可操作的向量，通过加减不同任务的向量组合出具备多任务能力或消除某种不良行为的模型；
- **相比 Ensemble 的优势**：Ensemble 需要在推理时同时运行多个模型、成本随模型数量线性增长；而模型合并只产出一个模型，推理成本与单模型相同，代价是合并效果依赖于各模型参数空间的相容性（通常要求它们从同一基座微调而来，且没有发生过大的参数漂移）。

</details>

**15. 除 LoRA 外，还有哪些主流的参数高效微调（PEFT）方法？各自的思路是什么？**

<details>
<summary>💡 查看答案</summary>

- **Prefix Tuning**：在每一层 Attention 的 Key/Value 前额外拼接一段可训练的"虚拟前缀"向量，模型主体参数冻结，只训练这部分前缀参数，相当于给模型注入一段可学习的软提示；
- **Adapter**：在 Transformer 每个子层之后插入小型瓶颈结构（先降维再升维的两层 MLP），只训练这些新增的 Adapter 模块，原始参数保持冻结；
- **Prompt Tuning**：只在输入嵌入层增加一段可训练的软提示 token，是几种方法中参数量最小、但对模型规模依赖较强的方案（在超大模型上效果才能接近全参数微调）；
- **BitFit**：只微调模型中的偏置（bias）参数，其余全部冻结，参数量极小，效果上限相对有限，但胜在极其轻量；
- **对比 LoRA**：LoRA 通过低秩矩阵分解近似权重更新量，不引入额外的推理时延（可以将低秩矩阵直接合并回原权重），这是它相比 Adapter/Prefix Tuning（会引入额外的前向计算路径）的一大优势，也是目前工业界最广泛采用 PEFT 方法的原因。

</details>
