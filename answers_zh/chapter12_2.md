# 12.2 视觉语言模型（VLM）架构 — 题目与答案
> [⬅ 返回目录](../README_ZH.md) · 第 12 章：多模态大模型 · 共 17 题

**1. 多模态大模型有哪些典型架构类型？**

<details>
<summary>💡 查看答案</summary>

多模态大模型的典型架构类型主要有以下几种：

1. **双塔对比架构（Dual-Encoder / Contrastive）**：代表模型为 CLIP、ALIGN。图像和文本分别通过独立编码器映射到同一语义空间，通过对比学习对齐。适合检索、零样本分类任务，推理效率高，但两模态交互较弱。
2. **融合编码器架构（Fusion Encoder）**：代表模型为 ViLBERT、ALBEF。图文特征在中间层进行跨模态交互（Cross-Attention），对理解类任务效果较好，但生成能力有限。
3. **编码器-解码器架构（Encoder-Decoder）**：代表模型为 Flamingo、BLIP-2、CogVLM。图像编码器提取视觉特征后，通过适配层（如 Q-Former、线性投影）注入语言模型解码器，支持图文生成、VQA、多轮对话等任务。
4. **统一 Transformer 架构（Unified Transformer）**：代表模型为 GPT-4o、Gemini、LLaVA 系列。将图像 patch tokens 与文本 tokens 拼接后一起输入自回归 Transformer，实现图文统一建模，灵活性最高。
5. **扩散模型架构（Diffusion-based）**：代表模型为 Stable Diffusion、DALL-E 3。主要用于图像生成，以文本为条件控制生成过程。

</details>

**2. 多模态 Transformer 结构一般如何设计？早融合、晚融合与交叉注意力融合的权衡是什么？**

<details>
<summary>💡 查看答案</summary>

多模态 Transformer 的设计重点在于如何处理不同模态的 token 序列，主要有三种融合范式：

1. **Early Fusion（早融合）**：图像 patch tokens 与文本 tokens 直接拼接，一同输入统一的 Transformer，模态间可通过 Self-Attention 自由交互（如 LLaVA、GPT-4V）。优点是能在浅层就学习细粒度跨模态交互，缺点是实现和训练相对复杂，对模态对齐要求更高。
2. **Late Fusion（晚融合）**：各模态分别经过独立 Transformer 编码后再融合，保留模态特异性（如早期 ViLBERT 的双流结构）。优点是更模块化、可复用预训练单模态模型，缺点是跨模态细粒度交互能力较弱。
3. **Cross-Attention Fusion（交叉注意力融合）**：在某些层用 Cross-Attention 进行跨模态交互，文本作为 Query、图像作为 Key/Value（或反之），比纯拼接更节省计算量（如 Flamingo）。

此外还需要考虑两个工程细节：

- **注意力掩码设计**：需要控制图文 token 之间的注意力可见性，例如图像 tokens 之间互相可见，文本 tokens 只看到之前的 token（因果掩码）。
- **位置编码设计**：图像 tokens 使用二维位置编码，文本 tokens 使用一维位置编码，拼接后统一处理。

当前主流 VLM（视觉编码器 + 连接器 + LLM）在 LLM 的输入层将视觉 Token 与文本 Token 拼接后统一处理，更接近一种"中间融合"，是效率和融合深度之间的折中方案。

![多模态 Transformer 融合的三种典型范式](https://img.pricenode.uk/llm_interview_questions/zhongw/chapter12/fig_fusion_paradigms.png)

</details>

**3. VLM 架构范式对比：基于连接器 vs 基于跨模态注意力**

<details>
<summary>💡 查看答案</summary>

当前主流的 VLM 架构范式，根据视觉和语言信息融合方式的不同，主要可以分为两大类：

\begin{table}[h]

\caption{VLM 架构范式对比}


| **维度** | **基于连接器** | **基于跨模态注意力** |
| --- | --- | --- |
| 代表模型 | LLaVA, MiniGPT-4 | Flamingo, BLIP-2 |
| 核心思想 | 前期对齐，后期融合 | 边生成边融合 |
| 优势 | 训练效率高、架构简洁 | 融合更深入、少样本能力强 |
| 劣势 | 信息瓶颈、融合深度较浅 | 架构复杂、训练成本高 |


\end{table}

**基于连接器**：视觉编码器提特征 $\to$ 连接器（线性层/Q-Former）将视觉特征转为定长的 Visual Tokens $\to$ 与文本 Tokens 拼接后送入 LLM。只需训练轻量级连接器，可复用强大的预训练视觉和语言模型，成本低、实现简单，在视觉指令跟随任务上表现出色；但视觉信息被压缩成固定数量的视觉词元，存在信息瓶颈。

**基于跨模态注意力**：视觉编码器提特征后，LLM 在生成文本的每一步，通过内部的 Cross-Attention 让文本 Query 动态查询视觉特征的 Key/Value，实现"边生成边融合"。融合更深入、在少样本上下文学习上表现优秀（Flamingo 已验证），但需要修改 LLM 内部结构，训练和推理成本更高。

总结：基于连接器的架构是当前高性价比、高性能 VLM 的主流方案，追求效率和简洁；基于跨模态注意力的架构则代表追求极致融合深度的方向，但成本更高。

</details>

**4. 什么是 Native Multimodal（原生多模态）模型，与"拼接式"多模态模型有什么区别？**

<details>
<summary>💡 查看答案</summary>

**拼接式多模态模型**（如 LLaVA、Qwen-VL 等主流开源 VLM）的构建思路是：分别取一个已经在海量单模态数据上充分预训练好的视觉编码器（如 CLIP ViT）和一个已经充分预训练好的大语言模型，两者本身在预训练阶段完全没有"见过"彼此，随后通过额外训练一个连接模块（如线性投影层或 Q-Former）把两者"缝合"起来，再辅以一定规模的多模态微调，使整个系统具备跨模态理解能力。这种方式的优点是可以复用已有的、成熟的强大单模态模型，大幅降低训练成本；但模态融合发生的时机相对较晚（是在两个已经"定型"的模型之间做事后对齐），融合的深度也受限于连接模块的表达能力。

**原生多模态模型**则完全不同：它从最初的预训练阶段开始，就将文本、图像（甚至语音、视频）等多种模态的数据混合在一起，用同一套目标函数、同一套模型架构联合训练，模态之间的融合从训练一开始就发生在模型的最深层次。理论上，由于视觉和语言的表示是"从零"在同一个共享空间中一起学习出来的，而非事后被强行"翻译"对齐的，原生多模态模型能够获得更紧密、更自然的跨模态表示能力（如 GPT-4o 展现出的更自然的实时语音交互体验）。但这种方式的代价是训练成本和数据规模要求都远高于拼接式架构，也是目前多数开源模型仍然选择拼接式路线的现实原因。

</details>

**5. 什么是 Unified Multimodal Model 中的"统一表示空间"？构建这一空间面临哪些核心难题？**

<details>
<summary>💡 查看答案</summary>

统一表示空间指的是：来自不同模态（文本、图像、音频、视频等）的原始数据，在经过各自专门的编码/Tokenization 处理之后，最终都被映射到**同一个**语义向量空间中（这个共享空间通常就是语言模型内部使用的 Token 嵌入空间），使得模型可以在同一套统一的 Transformer 计算框架下，不加区分地对来自任意模态的信息进行处理、交互甚至生成——理想情况下，模型在这个统一空间中"看不出"某个具体 Token 到底原本来自图像还是文本，而只是根据其语义内容做统一的推理运算。

构建这样一个真正统一的表示空间面临以下几个核心难题：

1. **信息密度的巨大差异**：同样长度（如 100 个 Token）的序列，如果来自文本，几乎每个 Token 都承载着独立、明确的语义信息；但如果来自图像或视频，其信息密度和冗余度要低得多，如何在压缩视觉信息为有限数量的 Token 时，尽量不损失与语言语义相关的关键内容，是一大难题；
    2. **位置编码/注意力机制的统一设计**：文本序列是天然的一维顺序结构，图像是二维空间结构，视频还额外叠加了时间维度，如何设计一套能够同时合理表达这几种截然不同结构关系的统一位置编码方案（如前述的 M-RoPE），本身就是一项复杂的架构设计工作；
2. **不同模态表示能力的相互干扰**：如果不同模态的 Token 共享同一套模型参数（尤其是前馈网络参数），由于各模态数据的统计特性差异巨大，很容易出现模型优化过程中"顾此失彼"的现象——为了更好地拟合某一模态的数据分布，反而损害了对另一模态原本已经学到的表示能力，如何平衡好这种此消彼长的关系，也是构建统一表示空间时需要重点考虑的问题。

</details>

**6. 什么是 MoE（混合专家）架构在多模态大模型中的应用？**

<details>
<summary>💡 查看答案</summary>

MoE（Mixture-of-Experts，混合专家）的核心思想是：在网络的某些层（通常是前馈网络 FFN 层）设置多个结构相同但参数独立的"专家"子网络，并额外引入一个轻量级的路由（Router）模块，该模块根据当前输入 Token 的特征，动态决定应该激活哪一个（或哪几个）专家来处理这个 Token，而不是让所有 Token 都流经全部专家。这样设计的好处是：模型的**总参数量**可以随专家数量的增加而大幅扩展（意味着模型能够存储更多的知识和能力），但由于每个 Token 实际只激活其中少数几个专家，模型推理时实际消耗的计算量（激活参数量）并不会随总参数量的增长而等比例上升，实现了"参数容量"和"推理成本"的解耦。

在多模态大模型中，MoE 架构可以应用在语言模型主干部分——由于不同专家在训练过程中会自发地对不同类型的输入产生偏好（隐式地专精于某些特定的模态、任务或语义领域），这有助于模型在有限的推理成本下容纳更多样化的多模态知识；部分工作还会进一步设计"模态感知"的路由机制，例如显式地为视觉 Token 和文本 Token 设置不同的专家分配倾向（甚至专门的模态专属专家），从而在扩大模型整体容量、更好地容纳多模态知识的同时，控制推理阶段的实际计算开销。

</details>

**7. CogVLM 提出的"视觉专家"（Vision Expert）模块是什么？解决了什么问题？**

<details>
<summary>💡 查看答案</summary>

CogVLM 的研究者认为，主流 VLM（如 LLaVA）采用的"视觉编码器输出 $\to$ 简单线性投影 $\to$ 直接拼接进语言模型输入"这种做法存在一个内在的表达能力瓶颈：线性投影本质上是一个相对简单的映射操作，会让原本维度更高、信息更丰富的视觉特征在"降维"适配语言模型的表示空间时损失掉不少细节信息，且这种映射**只发生在输入层一次**，视觉信息一旦进入语言模型内部，就完全按照语言模型原有的参数进行处理，无法针对视觉信息的特殊性做进一步的专门加工。

为了解决这一问题，CogVLM 提出了"视觉专家"模块：在语言模型的**每一层**，都额外插入一份独立的、参数完全不与原语言模型共享的前馈网络（FFN）和 QKV 投影矩阵，专门用于处理视觉 Token——视觉 Token 流经每一层时，走的是这份独立的"视觉专家"参数；而文本 Token 依然走原有语言模型的参数；两种 Token 只在 Self-Attention 的计算过程中相互交互（即注意力计算本身是共享和交互的），但各自的前馈网络更新是完全独立解耦的。这种"深度融合（每一层都交互）但参数解耦（各自有独立的前馈参数）"的设计，使得视觉特征可以在整个语言模型的所有层次中都保持较高的、针对视觉信息定制化的表达能力，而不是像标准做法那样仅仅在输入层做一次性的、可能有损的投影转换，实践证明这种设计能够显著提升模型对视觉细节的理解能力，代价是模型的总参数量会因为额外复制了一套接近语言模型规模的视觉专家参数而显著增加。

![CogVLM “视觉专家 (Vision Expert)” 架构](https://img.pricenode.uk/llm_interview_questions/zhongw/chapter12/fig_cogvlm_vision_expert.png)

</details>

**8. 多模态大模型的参数量通常如何在视觉编码器、连接器、语言模型三部分之间分配？**

<details>
<summary>💡 查看答案</summary>

在典型的拼接式 VLM 架构中，三个组件的参数规模差异非常悬殊：

- **语言模型**：通常占据整个模型绝大部分的参数量，主流开源 VLM 使用的语言模型骨干规模从 7B 到 70B 不等，这是因为语言模型承担着整个系统最核心、最复杂的知识存储和推理生成任务，需要足够的参数容量才能支撑这些能力；
- **视觉编码器**：规模相对小得多，主流选择（如 CLIP ViT-L/14）参数量通常在几百 M 到 1-2B 左右（InternVL 使用的 InternViT 是个例外，规模可达 6B），因为视觉编码器承担的任务相对单一（提取通用的视觉语义特征），不需要像语言模型那样存储和运用海量的世界知识；
- **连接器**：参数量最小，无论是简单的线性投影层还是相对复杂的 Q-Former，通常只有几 M 到几十 M 参数，因为它承担的仅仅是"空间转换/信息压缩"这一相对简单的功能，而不需要承担复杂的推理任务。
这种"头重脚轻"的参数分配格局，本质上体现了当前主流架构"最大程度复用已经充分预训练好的强大单模态模型（尤其是语言模型），只需要额外训练一个轻量级的桥接模块"这一设计哲学，也是在有限训练资源下，能够以最低成本快速构建出高性能多模态模型的现实考量。

</details>

**9. Perceiver Resampler（如 Flamingo 中使用）与 Q-Former 有什么异同？**

<details>
<summary>💡 查看答案</summary>

**相同点**：Perceiver Resampler 和 Q-Former 在核心思路上高度相似——两者都引入一组数量固定的、随机初始化后可学习的 Query 向量，通过 Cross-Attention 机制，让这些 Query 向量从数量庞大（且随输入图像分辨率变化而变化）的原始视觉特征中"提炼"出信息，最终输出一个数量固定、不随输入图像分辨率变化的压缩表示，从根本上解决了"视觉 Token 数量过多、且随分辨率变化不固定"这一问题，使得下游的语言模型（或 Cross-Attention 层）可以用统一、固定长度的方式处理任意分辨率的视觉输入。

**不同点**：Q-Former（BLIP-2 提出）在预训练阶段通常还会**联合训练多个额外的预训练目标**（如图文对比 ITC、图文匹配 ITM、图文生成 LM），使其学习到的压缩表示不仅仅是"信息压缩"，还内嵌了较强的图文语义对齐能力，训练流程相对复杂，但通常能带来更好的对齐质量；Perceiver Resampler（Flamingo 提出）的结构设计更加简洁，通常只承担纯粹的"信息压缩"这一单一职责，本身不联合额外的对比学习等预训练目标，压缩后的视觉 Token 需要配合 Flamingo 特有的 Gated Cross-Attention 层，在语言模型内部逐层被动态注入和利用（而不是像 Q-Former 那样，压缩完成后一次性把视觉 Token 与文本 Token 拼接在一起送入语言模型），两者在"何时、如何"将压缩后的视觉信息交给语言模型使用这一点上，存在架构设计上的差异。

</details>

**10. Flamingo 的 Gated Cross-Attention 具体是如何设计的？**

<details>
<summary>💡 查看答案</summary>

Flamingo 采用"冻结骨干网络 + 插入新模块"的思路：图像/视频先经过冻结的视觉编码器提取特征，再经过 Perceiver Resampler 压缩为固定数量（如 64 个）的视觉 Token；这些视觉 Token 不会像 LLaVA 那样直接与文本拼接输入语言模型，而是通过在预训练语言模型的每隔几层（例如每 4 层）插入一个新的 **Gated Cross-Attention Dense（GATED XATTN-DENSE）**模块来注入：

- **Cross-Attention 计算**：以当前层的文本隐藏状态作为 Query，视觉 Token 作为 Key/Value，计算文本对视觉信息的交叉注意力，使得文本在生成过程中的每一步都能"回看"图像内容；
- **门控机制（Gating）**：Cross-Attention 层和随后的前馈层的输出，分别乘以一个初始化为 0 的可学习标量（通过 $\tanh$ 函数处理，保证输出范围在 $[-1, 1]$），再与原始语言模型该层的输出相加。由于门控初始值为 0，训练刚开始时新插入的模块完全不影响原语言模型的行为（相当于恒等映射），保证了训练的稳定性；随着训练推进，门控数值逐渐偏离 0，模型才逐步学会真正利用视觉信息；
- **冻结原语言模型参数**：Flamingo 训练时通常只更新新插入的 Gated Cross-Attention 层和 Perceiver Resampler，原始语言模型的参数保持冻结，从而最大程度保留其预训练阶段学到的语言能力。
这种设计使得 Flamingo 可以将任意强大的纯文本语言模型无缝"改造"为多模态模型，且不需要对语言模型本身做任何微调。

![Flamingo 门控交叉注意力 (Gated Cross-Attention) 机制](https://img.pricenode.uk/llm_interview_questions/zhongw/chapter12/fig_flamingo_gated_attention.png)

</details>

**11. 什么是 decoder-only 统一多模态架构？相比传统 encoder-decoder 架构有何优势？**

<details>
<summary>💡 查看答案</summary>

decoder-only 统一多模态架构将所有模态的 Token（图像 Patch Token、文本 Token，甚至音频/视频 Token）拼接成一个统一的一维序列，全部交给单一的自回归 Transformer 解码器处理，不再像 encoder-decoder 架构（如早期的 T5 类模型或专门的编码器-解码器式 VLM）那样区分独立的"编码器"和"解码器"模块。

其优势体现在：

1. **架构极简、复用成熟基础设施**：只需要一套 Transformer Decoder 结构，可以直接复用纯文本 LLM 已经高度成熟的训练与推理基础设施（KV Cache 加速、张量并行、FlashAttention 等）；
2. **易于扩展（Scaling）**：架构统一使得增大模型规模、增加训练数据的工程实现更简单，Scaling Law 的经验也更容易从纯文本领域迁移过来；
3. **天然支持任意位置的模态生成**：由于所有模态共享同一个自回归生成过程，模型理论上可以在序列的任意位置生成任意模态的内容（如生成"一段文字 + 一张配图 + 又一段文字"的图文交错内容），而不需要像 encoder-decoder 架构那样为每种模态设计单独的输出头。
这也是当前 GPT-4o、Gemini、Chameleon 等追求"原生统一"的多模态大模型普遍采用的架构选择。

</details>

**12. 为什么 GPT-4o、Gemini 这类"原生多模态"模型被认为是下一代架构方向？**

<details>
<summary>💡 查看答案</summary>

拼接式架构（预训练视觉编码器 + 连接器 + 预训练 LLM，如 LLaVA、Qwen-VL）本质上是"后期缝合"：视觉编码器和语言模型分别在各自的单模态数据上完成预训练，模态融合发生在训练的较晚阶段，且融合深度受限于连接器的表达能力（视觉信息需要先被压缩为有限数量的 Token，才能"翻译"给语言模型理解），这种压缩瓶颈会不可避免地损失部分细节信息。

而原生多模态模型从预训练最初阶段起，就将文本、图像（乃至语音、视频）数据混合在同一套目标函数下联合训练，模态融合发生得更早、更深。这带来的潜在优势包括：

- **更紧密的跨模态推理**：由于视觉和语言表示是在同一个共享空间中"从零"学习出来的，而非事后对齐拼接的，理论上可以支持更细粒度、更自然的跨模态交互（例如 GPT-4o 演示中展现的实时语音对话可以被用户随时打断，并能感知语气、停顿等副语言信息）；
- **统一的多模态生成能力**：原生多模态模型更容易同时支持"看图说话"和"按文字画图/生成语音"两个方向的能力，而不需要分别接入独立的理解模型和生成模型；
- **避免了预训练单模态模型之间可能存在的表示空间不匹配问题**：拼接式架构需要通过连接器强行"翻译"两个原本独立训练的表示空间，而原生多模态从一开始就在同一表示空间中学习，理论上能减少信息在"翻译"过程中的损耗。
当然，原生多模态模型的训练成本和数据要求也远高于拼接式架构，这是当前多数开源模型仍采用拼接式架构的现实原因。

</details>

**13. 多模态大模型的 Scaling Law 是否与纯文本 LLM 一致？有何不同？**

<details>
<summary>💡 查看答案</summary>

纯文本 LLM 的 Scaling Law 揭示了模型损失（Loss）会随参数量、训练数据量、计算量的增长呈现出可预测的幂律下降关系，这一规律在多模态场景下也大致成立——更大的视觉编码器、更多的图文训练数据、更大的语言模型骨干，总体上仍然带来更好的多模态任务表现。

但多模态 Scaling 存在额外的复杂度，使其规律不如纯文本场景清晰统一：

1. **多个可扩展维度相互耦合**：性能提升不仅取决于语言模型的规模，还高度依赖视觉编码器的规模、图像分辨率（决定视觉 Token 数量）、图文数据的配比等多个维度，单纯扩大语言模型规模而不同步提升视觉侧的能力，效果提升会很快遇到瓶颈；
2. **数据量和质量的模态不对等**：纯文本数据的规模和质量远高于高质量图文对数据，这导致多模态训练中往往是"视觉-语言对齐数据"而非"语言模型参数量"率先成为性能瓶颈，即所谓的"数据瓶颈"（Data Bottleneck）；
3. **任务多样性带来的评测复杂度**：纯文本 LLM 的 Scaling Law 通常以困惑度（Perplexity）等单一、连续的指标衡量；而多模态任务种类繁多（分类、检索、生成、推理），不同任务对 Scaling 的敏感程度也不同，很难用单一指标干净地刻画整体的 Scaling 曲线。

</details>

**14. 什么是 Mixture-of-Transformers（MoT）在多模态大模型中的思路？**

<details>
<summary>💡 查看答案</summary>

MoT 可以理解为 MoE（混合专家）思想在"模态"这一维度上的特化应用：标准 MoE 通常按 Token 内容动态路由到不同专家，而 MoT 则更直接地**按模态类型**为不同的 Token 分配完全独立的 Transformer 子模块——例如为文本 Token 和图像 Token 分别配备各自独立的前馈网络（FFN）参数，甚至各自独立的部分注意力投影参数（Q/K/V 权重），只在 Attention 计算本身（即不同模态 Token 之间如何交互）这一环节保留共享或交互机制。

这样设计的动机在于：不同模态数据的统计特性差异巨大，让它们共用同一套 FFN 参数可能导致两种模态的优化目标相互干扰（一种模态的梯度更新可能损害另一种模态已经学到的表示）；而 MoT 通过"参数解耦、注意力交互"的方式，让每种模态的处理路径可以专精优化自己的特性，同时仍能通过共享的 Attention 层实现跨模态的信息融合，是"专精"与"融合"之间的一种工程折中，思路上与 CogVLM 的视觉专家模块（在每一层为视觉 Token 单独设置 FFN 和 QKV 投影）高度相似。

</details>

**15. 视觉 Token 和文本 Token 在同一个 Transformer 中共享参数 vs 分离参数，各有什么优缺点？**

<details>
<summary>💡 查看答案</summary>

**共享参数**（如标准 LLaVA、Qwen-VL 等主流做法：视觉 Token 经连接器映射后，与文本 Token 使用完全相同的 Transformer 参数处理）：

- **优点**：实现简单，不需要额外设计模态专属的网络结构；模型在同一个统一的表示空间中自然地学习跨模态关联，参数量不会因为模态数量增加而额外膨胀；
- **缺点**：视觉 Token（信息密度低、局部冗余度高）和文本 Token（信息密度高、语义抽象）的统计特性差异巨大，共用同一套 FFN 参数可能导致两种模态在优化过程中产生冲突，模型需要在两者之间做出妥协，理论上难以让每种模态都达到各自的能力上限。

**分离参数**（如 CogVLM 的视觉专家、MoT 思路：视觉 Token 和文本 Token 使用各自独立的 FFN/QKV 参数）：

- **优点**：每种模态可以使用更适合自身特性的参数空间，减少跨模态优化冲突，理论上能让视觉表示的精细度不因为要迁就语言模型的参数分布而受损；
- **缺点**：会显著增加模型的总参数量和实现复杂度（相当于为视觉部分复制了一份接近语言模型规模的参数），且仍然需要在 Attention 层精心设计跨模态信息交互的方式，否则容易退化为"各自独立处理、缺乏真正融合"的松散拼接。
实践中，多数开源 VLM 出于工程简洁性和训练成本考虑仍选择共享参数方案，而分离参数方案更多出现在追求更强视觉细节保留能力的模型（如 CogVLM）中。

</details>

**16. Qwen2-VL 的 M-RoPE（多模态旋转位置编码）是如何设计的？相比 Qwen-VL 有什么改进？**

<details>
<summary>💡 查看答案</summary>

**背景**：第一代 Qwen-VL 和多数早期 VLM 一样，需要将输入图像预处理为固定或有限几种分辨率，视觉编码器输出的 Patch 数量相对固定，位置编码设计相对简单。Qwen2-VL 提出了"朴素动态分辨率"（Naive Dynamic Resolution），允许模型直接处理任意分辨率的图像，将其动态转换为数量可变的视觉 Token，而不再需要将图像强制缩放/裁剪到固定尺寸。

**M-RoPE 的设计**：为了让旋转位置编码（RoPE）能够同时处理一维的文本序列和多维（二维图像、三维视频）的视觉信号，Qwen2-VL 将位置编码拆分为三个独立的分量：**时间（Temporal）**、**高度（Height）**、**宽度（Width）**。对纯文本 Token，三个分量的位置索引保持一致（退化为普通的一维 RoPE）；对图像 Token，时间分量保持恒定（因为静态图像没有时间维度），高度和宽度分量则根据 Patch 在图像网格中的实际二维坐标分别递增；对视频 Token，时间分量随帧序号递增，高度和宽度分量则在每一帧内部按二维网格递增。这样设计使得同一套位置编码框架可以自然地统一处理文本、图像、视频三种不同结构的序列，且各分量之间相对独立、互不干扰。

**与 Qwen-VL 相比的改进**：一是支持任意分辨率输入（不再需要固定尺寸的预处理），推理阶段会将不同分辨率的图像打包进同一个序列并控制打包长度以限制显存占用；二是为进一步压缩视觉 Token 数量，视觉编码器后接一个 MLP，将相邻的 2×2 视觉 Token 融合为 1 个 Token（例如对 224×224 图像使用 patch size=14 的 ViT 编码后，压缩后的序列长度可缩减到 64 个左右，加上起止标记后约 66 个 Token），显著降低了长序列带来的计算开销。

</details>

**17. InternVL 系列的"动态高分辨率"（Dynamic High Resolution）策略具体是如何实现的？**

<details>
<summary>💡 查看答案</summary>

InternVL（如 InternVL 1.5/2.0/2.5）为了在保留细节的同时避免直接缩放导致的信息损失，设计了一套"动态切图 + 缩略图"的高分辨率处理方案：

1. **预定义长宽比集合**：预先定义一组（如 35 种）候选的长宽比组合，推理时根据输入图像的原始长宽比，从中选择最接近的一种，将图像 Resize 到与该长宽比匹配的目标尺寸（例如一张 800×1300 的图像可能被调整为 896×1344），尽量避免因为长宽比失配而产生的形变。
2. **切分为固定尺寸的图块**：调整后的图像被均匀切分为多个 448×448 像素的图块（Tile），每个图块独立通过视觉编码器（如 InternViT-6B）编码，训练阶段单张图最多切分为 12 个图块左右，推理阶段可以放宽到上百个图块，从而支持最高约 4K 分辨率的输入。
3. **额外保留一张全局缩略图**：除了局部图块外，还会额外将整张原图缩放为一个 448×448 的缩略图一并编码，以提供图块之间可能丢失的全局上下文信息，缩略图通常被放在所有局部图块特征之后。
4. **Pixel Shuffle 压缩 Token**：由于切分成多个图块后视觉 Token 总量会显著增加，InternVL 引入 Pixel Shuffle（一种借鉴自图像超分辨率领域的操作，这里反过来用于下采样）操作，通过重排通道和空间维度，将相邻的多个 Patch 特征"压缩"进更少数量的 Token 中，在几乎不损失信息的前提下降低最终序列长度。

训练时通常采用渐进式策略：预训练阶段视觉编码器（InternViT）和连接层（MLP）参与训练、语言模型冻结；指令微调阶段则解冻全部参数一起训练，逐步从较低分辨率过渡到高分辨率，兼顾训练效率和最终效果。

</details>
