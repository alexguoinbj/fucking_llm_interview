# 4.6 多任务与持续学习微调 — 题目与答案
> [⬅ 返回目录](../README_ZH.md) · 第 4 章：微调（Fine-Tuning） · 共 6 题

**1. 如何缓解 LLM 中的灾难性遗忘？**

<details>
<summary>💡 查看答案</summary>

灾难性遗忘是指 LLM 在学习新信息时完全忘记或显著削弱对之前学习任务的掌握。有几种技术可以解决这一挑战：
- **基于复习的方法**：在训练过程中让 LLM 同时复习旧数据和新数据的子集。
- **弹性权重巩固（EWC）**：为 LLM 网络中的不同权重分配重要性分数，惩罚对旧任务重要参数的变化。
- **模块化方法**：为新任务引入独立模块，允许 LLM 扩展其知识库而不完全重写现有连接。

</details>

**2. 微调后模型能力劣化，灾难性遗忘是怎么回事？**

<details>
<summary>💡 查看答案</summary>

灾难性遗忘（Catastrophic Forgetting）是指在微调过程中，模型在新任务上训练时，可能会忘记之前学习的知识，导致在旧任务上的性能下降。其原因包括：
1. **数据分布差异**：新任务的数据分布与预训练数据或旧任务数据差异较大，导致模型过度调整，忘记旧任务知识。
2. **参数更新冲突**：新任务的梯度更新可能与旧任务的梯度更新冲突，导致旧任务知识被覆盖。

解决灾难性遗忘的方法包括：重播缓冲区、弹性权重共享、增量学习、多任务学习、知识蒸馏、正则化技术等。

</details>

**3. 增量微调时如何避免灾难性遗忘？**

<details>
<summary>💡 查看答案</summary>

增量微调（在已经微调过的模型基础上，针对新任务/新数据继续微调）中避免灾难性遗忘的方法：

**1. 数据回放（Rehearsal/Replay）**：在新任务的训练数据中混入一部分旧任务的数据，是缓解遗忘最直接有效的方法之一。

**2. 参数高效微调（PEFT）与模块化**：使用 LoRA 等方法为新任务训练独立的新增模块，原模型参数保持冻结不受影响；可以为不同任务维护独立的 LoRA 模块，部署时根据任务动态加载/切换。

**3. 正则化约束参数变化**：EWC（Elastic Weight Consolidation）对重要参数施加惩罚，限制其在新任务训练中偏离原值过多；L2 正则化/参数距离约束。

**4. 知识蒸馏约束**：让增量微调后的模型在旧任务相关的输入上，输出分布尽量接近增量微调前的模型。

**5. 较小的学习率和较少的训练步数**：减少参数更新幅度，降低对已有能力的破坏程度。

**6. 多任务联合训练**：将新任务数据与旧任务数据一起进行多任务训练，从根本上避免"先后顺序"导致的遗忘问题。

**7. 评估与监控**：增量微调过程中定期在旧任务的评测集上评估，一旦发现明显下降及时调整策略。

</details>

**4. 多任务微调如何平衡不同任务的梯度？**

<details>
<summary>💡 查看答案</summary>

在多任务微调（Multi-Task Fine-tuning）中，不同任务的损失尺度、难度和数据量可能差异很大，常见的平衡策略包括：

**1. 损失加权（Loss Weighting）**：固定权重（根据任务重要性人工设定）；不确定性加权（动态学习各任务的相对权重）。

**2. 数据采样比例的控制**：按任务数据量的某种"温度"调整采样比例（如按数据量的平方根成比例采样），使小数据量的任务也能获得足够的训练信号。

**3. 梯度归一化/梯度平衡方法**：GradNorm（动态调整各任务损失的权重，使各任务的梯度范数趋于一致）；PCGrad（将冲突的梯度投影到与另一个梯度正交的方向上，消除直接冲突）。

**4. 分阶段/课程式训练**：按某种顺序逐步引入任务，或采用"先单任务预热，再多任务联合"的两阶段策略。

**5. 共享与任务特定参数的设计**：在模型结构上区分"共享参数"和"任务特定参数"，减少任务间的直接梯度冲突。

**6. 监控各任务的独立指标**：分别监控各任务在其验证集上的 loss/指标变化，发现任务干扰现象时及时调整策略。

</details>

**5. 混合指令数据与对话数据微调要注意什么？**

<details>
<summary>💡 查看答案</summary>

将"单轮指令数据"与"多轮对话数据"混合进行微调时，需要注意以下问题：

**1. 格式统一**：将所有数据统一转换为同一种格式（通常是多轮对话的 messages 格式），并应用统一的 chat template。

**2. System Prompt 的一致性**：为所有样本统一添加默认 system prompt，避免不同 system prompt 之间的冲突。

**3. 多轮对话中的上下文依赖**：混合训练时需要确保模型既能处理"无历史上下文的单次指令"，也能处理"依赖多轮历史的对话"。

**4. 损失计算的一致性**：所有类型的数据都只对 assistant 角色的内容计算损失，保证训练目标的一致性。

**5. 数据比例与任务能力平衡**：根据目标应用场景的实际需求确定两类数据的混合比例。

**6. 长度分布差异**：多轮对话数据的序列长度通常显著长于单轮指令数据，需要注意 batching 策略，避免因长度差异过大导致 padding 浪费。

</details>

**6. 多轮对话微调有哪些技巧？**

<details>
<summary>💡 查看答案</summary>

多轮对话微调的实用技巧包括：

1. **全轮次损失计算**：对多轮对话中每一轮 assistant 的回复都计算损失，显著提高数据利用效率。
2. **上下文窗口与截断策略**：优先保留 system prompt 和最近的若干轮对话；对特别长的对话截取若干轮的连续片段作为独立的训练样本。
3. **角色一致性与人称处理**：确保训练数据中 assistant 角色的回复风格、人称使用保持一致。
4. **覆盖指代消解与上下文依赖**：有意识地包含需要依赖前文才能正确理解的回复，训练模型的上下文追踪能力。
5. **话题切换与错误恢复**：包含用户切换话题、用户纠正模型错误、模型主动询问澄清等场景的样本。
6. **训练-推理一致性**：确保训练时使用的对话模板与推理部署时完全一致。
