# 4.7 微调超参、显存与过拟合处理 — 题目与答案
> [⬅ 返回目录](../README_ZH.md) · 第 4 章：微调（Fine-Tuning） · 共 6 题

**1. 在微调过程中，为什么模型对学习率等超参数通常比预训练阶段更敏感？**

<details>
<summary>💡 查看答案</summary>

微调阶段对超参数更敏感的原因主要包括：
1. **模型已处于一个"较好"的参数区域**：预训练后的模型参数对应着一个在大规模通用数据上损失较低的"盆地"。微调时如果学习率过大，参数更新可能"跳出"这个良好区域，导致模型迅速偏离预训练学到的有用表示（即灾难性遗忘）。
2. **微调数据量通常远小于预训练数据量**：每个 batch 的梯度估计噪声更大，如果学习率过大，少量样本产生的较大梯度更新可能导致参数大幅震荡或过拟合。
3. **微调通常训练的 step 数很少**：一旦初期由于学习率不当导致参数偏离较远，后续没有足够的步数"纠正"，最终效果会受到明显影响。
4. **过拟合风险更高**：数据量小、训练步数少的情况下，学习率的"安全区间"通常比预训练阶段窄，需要更精细的调优。

</details>

**2. 微调阶段学习率应该如何设置？**

<details>
<summary>💡 查看答案</summary>

- 微调学习率通常比预训练阶段小 1~2 个数量级；
- 全参数微调的学习率常见范围在 **1e-5 到 5e-5**；
- PEFT 方法（如 LoRA），常见范围在 **1e-4 到 5e-4**；
- 配合 warmup（前 3%~10% 的训练步数）和衰减策略（线性衰减或余弦衰减）；
- 模型规模越大，适合的学习率越小；
- 通常通过小范围网格搜索，结合验证集上的 loss 曲线和下游任务指标确定最终值。

</details>

**3. 微调模型时，学习率、LoRA alpha、LoRA rank 等超参数通常应该如何设置？应该如何决定模型何时停止训练，是不是验证集损失函数越低效果就越好？**

<details>
<summary>💡 查看答案</summary>

**超参数设置**：
- **学习率**：全参数微调常用 1e-5~5e-5，LoRA 微调常用 1e-4~5e-4，配合 warmup 和衰减调度；
- **LoRA rank (r)**：常用范围 4~64，多数任务 8~16 即可；
- **LoRA alpha**：常见的经验设置是 alpha = 2×r（即缩放系数为 2）或 alpha = r（缩放系数为 1）。

**何时停止训练——验证集损失越低越好吗？**

**不是的**，验证集损失（loss）最低并不等价于下游任务效果最好：
1. Loss 衡量的是"预测下一个 token 的准确程度"，而下游任务效果衡量的是"生成内容的整体质量/有用性/正确性"，两者并非严格单调对应；
2. 模型可能在 token 级别的预测损失上持续下降，但可能对训练数据特定模式过拟合，导致在更广泛未见过的输入上，实际生成质量反而下降；
3. 指令遵循/生成质量等"软"目标难以完全用 loss 捕捉。

**实践中决定何时停止训练的方法**：同时监控验证集 loss 和下游任务指标，选择下游任务指标最优的 checkpoint；定期保存 checkpoint 对多个 checkpoint 进行综合评估；观察 loss 曲线的"拐点"；结合训练集与验证集 loss 的差距判断过拟合风险。

</details>

**4. 如何判断微调过拟合？出现过拟合怎么解决？**

<details>
<summary>💡 查看答案</summary>

**判断微调过拟合的方法**：
- 训练集 loss 持续下降，但验证集 loss 不再下降甚至开始上升，两者差距持续扩大；
- 下游任务指标在验证集上不再提升甚至变差；
- 生成内容的多样性下降/重复训练数据中的特定模式；
- 对训练数据中特定措辞/格式过度敏感，泛化能力差。

**解决过拟合的方法**：
- 早停（Early Stopping）；
- 减少训练 epoch 数 / 降低学习率；
- 增加数据量与多样性，对训练数据进行去重；
- 正则化技术（Dropout、权重衰减，或降低 LoRA 秩 r）；
- 混合通用数据，避免模型过度拟合到狭窄的数据分布；
- PEFT 方法本身的正则作用（可训练参数少，具有隐式正则化效果）。

**5. 如何在控制成本的同时获得 LLM 系统的最佳性能和功能？**

<details>
<summary>💡 查看答案</summary>

- LLM 按标记（单词、标点等）收费，需要专注于清晰、具体的提示，避免不必要的信息；
- 如果使用 LLM API，考虑将类似的请求批量处理，减少所需的调用次数，从而降低成本；
- 使用像 LLM Lingua 这样的技术从输入和输出中去除不必要的单词；
- 对于聊天机器人或交互式系统，限制存储在内存中的对话历史记录；
- 不同的 LLM 在成本和能力上各不相同，选择专门为你的任务设计的 LLM，以在预算内获得最佳性能。

</details>

**6. 微调中有哪些实用的数据增强方法？**

<details>
<summary>💡 查看答案</summary>

微调中常用的数据增强方法包括：

**1. 文本层面的扰动方法**：同义词替换；随机插入/删除/交换（EDA）；回译（Back Translation）。

**2. 基于大模型的生成式增强**：改写/扩写；指令扩展（基于少量种子指令生成更多变体）；困难样本生成（增加干扰信息、改变问题表述）。

**3. 模板/格式层面的增强**：指令措辞多样化（同一任务使用多种不同的指令表述方式）；few-shot 示例的随机组合。

**4. 注意事项**：数据增强生成的样本需要经过质量检查，避免引入语义偏移；增强数据的比例需要适当控制，过多的增强数据可能引入"合成数据特有的模式"，通常建议与原始真实数据按一定比例混合。
