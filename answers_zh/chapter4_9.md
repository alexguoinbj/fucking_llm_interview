# 4.9 微调评估与模型选择 — 题目与答案
> [⬅ 返回目录](../README_ZH.md) · 第 4 章：微调（Fine-Tuning） · 共 8 题

**1. 进行 SFT 操作时，基座模型选用 Chat 还是 Base？**

<details>
<summary>💡 查看答案</summary>

在进行监督微调（SFT）时，基座模型的选择应根据任务性质和数据集特点决定：
- 如果任务是对话生成相关，选择 Chat 模型可能更合适，因为它在对话交互方面经过专门优化。
- 如果任务是单轮文本生成或非对话任务，选择 Base 模型可能更合适，因为它在单轮文本生成任务上表现良好。

</details>

**2. 如何评估微调后的模型性能？**

<details>
<summary>💡 查看答案</summary>

评估微调后的模型性能是确保模型能够满足任务需求的重要步骤：
1. **使用测试集进行评估**：将测试集输入模型，获取模型的预测结果，并与真实标签进行比较。
2. **选择合适的评估指标**：分类任务使用准确率、召回率、F1 分数等；生成任务使用 BLEU 分数、ROUGE 分数等；多轮对话任务还可以评估对话的连贯性、一致性及用户满意度等。
3. **进行对比分析**：将微调后的模型与基线模型进行对比，分析性能提升的具体方面。
4. **用户反馈和实际测试**：在实际应用场景中收集用户反馈，进行 A/B 测试。
5. **错误分析**：对模型预测错误的样本进行详细分析，找出模型的弱点和不足之处。

</details>

**3. 微调后模型效果常用哪些评估指标？**

<details>
<summary>💡 查看答案</summary>

微调后模型效果的评估指标因任务类型而异，常见的包括：

**1. 分类/序列标注任务**：Accuracy、Precision、Recall、F1（以及宏平均/微平均）；混淆矩阵。

**2. 生成任务（翻译、摘要等，有参考答案）**：BLEU、ROUGE、METEOR（基于 n-gram 重叠度）；BERTScore（基于嵌入相似度的语义级评估）。

**3. 开放式生成任务（对话、创作等，无固定参考答案）**：LLM-as-Judge；人工评估；Win Rate / 偏好胜率。

**4. 指令遵循能力**：格式/约束遵循率（自动化检查）；多步骤指令完成度。

**5. 通用能力评测基准**：MMLU、C-Eval 等，监控微调是否对模型的通用能力产生负面影响。

**6. 任务特定的业务指标**：客服场景的"问题解决率"，代码生成场景的"代码可执行通过率/单元测试通过率"等。

**7. 安全性与合规性指标**：通过专门的安全评测集评估微调是否引入了安全风险。

</details>

**4. 如何构建领域评测集？**

<details>
<summary>💡 查看答案</summary>

构建领域评测集的步骤如下：
1. **收集数据**：从互联网、公开数据集或领域专家处获取与目标领域相关的数据，确保数据具有代表性和多样性。
2. **标注数据**：根据任务类型对数据进行标注，可以人工完成或借助自动化工具。
3. **划分数据集**：将标注好的数据划分为训练集、验证集和测试集。
4. **设计评测指标**：根据任务类型选择合适的指标。
5. **进行评测**：使用评测集对微调后的模型进行评估，计算指标。
6. **分析和改进**：根据评测结果分析模型表现，并根据需要调整超参数或模型架构。

</details>

**5. 如何选择合适的预训练模型进行微调？**

<details>
<summary>💡 查看答案</summary>

选择合适的预训练模型是微调成功的关键：
1. **任务相关性**：根据任务类型选择与任务最相关的预训练模型。
2. **模型规模与资源**：考虑模型的大小和计算资源。较大的模型通常具有更强的性能，但也需要更多的显存和计算资源。
3. **预训练数据的质量和多样性**：选择在大规模、高质量语料上预训练的模型。
4. **社区支持和文档**：选择有良好社区支持和详细文档的预训练模型。
5. **实验验证**：如果条件允许，可以尝试多个预训练模型进行微调实验，比较它们在特定任务上的性能。

</details>

**6. 如何用极少的数据做高效微调？**

<details>
<summary>💡 查看答案</summary>

在标注数据极少（如几十到几百条）的情况下进行高效微调，常见策略包括：
1. **优先使用 PEFT 方法**：LoRA 等参数高效方法在小数据集上更不容易过拟合，是少样本微调的首选。
2. **SetFit 类方法（针对分类任务）**：通过对比学习"组合"少量标注样本生成大量训练对，再训练简单分类器。
3. **数据增强与合成数据**：利用 LLM 对少量种子样本进行改写、扩写、生成相似变体。
4. **充分利用预训练/通用模型的能力**：选择已经在相关任务/领域上有较好基础能力的预训练模型；考虑使用 In-Context Learning 作为微调的替代或补充。
5. **迁移学习**：先在相关但数据量较大的任务上微调，再在目标小数据集上进行第二阶段的微调。
6. **精细的超参数和早停策略**：使用较小的学习率、较少的训练 epoch、较强的早停策略。
7. **交叉验证**：数据量极少时，采用 k 折交叉验证可以更稳健地评估模型效果。

</details>

**7. 如果有标注的训练数据很少，如何扩增训练数据的数量？（提示：SetFit）**

<details>
<summary>💡 查看答案</summary>

当标注数据极少（如每类只有几十个样本）时，常见的数据扩增和高效利用策略包括：

**1. 数据增强（Data Augmentation）**：文本层面的扰动（同义词替换、EDA、回译）；基于 LLM 的生成式增强；Mixup / 嵌入空间插值。

**2. SetFit 方法（Sentence Transformer Fine-Tuning）**

SetFit 是专门针对"少样本文本分类"设计的高效方法，核心思路分两步：
- **第一步：对比学习微调嵌入模型**：利用极少量标注样本，构造大量的句子对（同类别正例对、不同类别负例对），用对比学习损失微调一个 Sentence Transformer，使其嵌入空间更好地适配当前分类任务的语义边界。
- **第二步：训练轻量分类头**：用微调后的嵌入模型对所有标注样本提取嵌入向量，作为特征训练一个简单的分类器（如逻辑回归）。
SetFit 的核心价值在于："组合"标注样本生成大量句子对，把"少样本分类"问题转化为"对比学习微调+简单分类器"的两步流程。

![SetFit 极少样本分类微调二阶段工作流](https://img.pricenode.uk/llm_interview_questions/zhongw/chapter4/fig_setfit_workflow.png)

**3. 半监督/弱监督方法**：用少量标注数据训练初始模型，对大量未标注数据打"伪标签"，筛选高置信度的伪标签样本加入训练集（自训练，Self-training）。

</details>

**8. 有人声称一篇文章是用 DeepSeek-R1 生成的，并给了你生成所用的完整提示词，你应该如何证实或证伪这个说法？如何量化计算这个提示词生成这篇文章的概率？**

<details>
<summary>💡 查看答案</summary>

**验证思路**：
1. **直接复现**：使用提供的完整提示词，多次调用 DeepSeek-R1 模型生成内容，比较生成结果与待验证文章在内容、结构、用词风格上的相似程度。关注核心信息点、论证结构是否高度吻合，以及 R1 模型特有的"思维链"痕迹。
2. **风格特征分析**：分析待验证文章是否具有 DeepSeek-R1 的统计特征（某些短语的使用频率、句子长度分布等）。
3. **使用 AI 文本检测工具**：可作为辅助参考但不能作为决定性证据。
4. **检查内容的时效性与知识边界**：如果文章包含的信息超出了 DeepSeek-R1 训练数据的知识截止时间，可能说明文章并非完全由该模型生成。

**量化计算"该提示词生成这篇文章的概率"**：

从语言模型的角度，给定提示词 P 和模型 M，生成文章 T 的概率可以表示为：

$P(T | P, M) = \prod_{i} P(t_i | P, t_1, ..., t_{i-1}, M)$

如果可以访问模型的 API 并获取 token 级别的 log 概率，可以将文章 T 逐 token 输入模型，获取模型对每个真实 token 的预测概率，将所有 token 的 log 概率相加，得到 $\log P(T | P, M)$。困惑度（Perplexity）可以作为代理指标：$PPL = \exp(-\frac{1}{N} \sum \log P(t_i | ...))$，困惑度越低，说明在该提示词下生成这段文本的"可能性"越高。

**重要局限性**：这个数值本身并不能直接证明文章是否由该模型生成，需要通过大量已知"由该模型生成"和"非该模型生成"的文本样本统计两类样本的概率分布，才能确定一个具有统计意义的判别阈值。

</details>
