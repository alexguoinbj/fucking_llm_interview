# 9.1 AI Coding 工具评测（Cursor、Claude Code） — 题目与答案
> [⬅ 返回目录](../README_ZH.md) · 第 9 章：AI Coding · 共 22 题

**1. 为什么 Cursor 这类 AI 编程工具能受到广泛欢迎？**

<details>
<summary>💡 查看答案</summary>

它将 AI 能力深度集成到了开发者已有的工作流（编辑器）中，减少了上下文切换成本，同时支持基于整个代码库上下文的代码理解和生成，体验上比独立的对话式工具更贴近实际开发场景。

</details>

**2. Cursor 最大的优势体现在哪里？**

<details>
<summary>💡 查看答案</summary>

深度集成于编辑器内的交互体验，结合对整个项目上下文的理解能力，使开发者在日常编码流程中可以低摩擦地获得 AI 辅助。

</details>

**3. Cursor 的 Tab 自动补全和 Chat 模式分别解决什么问题？**

<details>
<summary>💡 查看答案</summary>

Tab 补全面向"顺手完成当前这一段代码"的高频小粒度任务，强调低延迟和光标处上下文的精准预测；Chat 模式面向需要跨文件、跨模块推理的复杂任务，强调对话式的意图澄清和多步骤规划，两者互补覆盖了从"写一行"到"改一个功能"的不同粒度需求。

</details>

**4. Cursor 的 Composer/多文件编辑功能解决了什么痛点？**

<details>
<summary>💡 查看答案</summary>

解决了传统 Chat 模式下开发者需要手动把 AI 建议逐个复制粘贴到多个文件的问题，Composer 能够一次性规划并应用跨多个文件的修改，同时保持文件间的一致性，更接近真实的多文件协同开发场景。

</details>

**5. Claude Code 这类工具的体验为什么受到好评？**

<details>
<summary>💡 查看答案</summary>

体现在对代码库结构的理解能力、多文件协同修改的连贯性，以及作为命令行 Agent 能够自主执行编译、测试等操作并根据反馈迭代，减少了开发者手动来回粘贴代码的负担。

</details>

**6. Claude Code 最大的优势体现在哪里？**

<details>
<summary>💡 查看答案</summary>

作为命令行 Agent，能够自主执行多步操作（运行命令、读写文件、执行测试）并根据真实反馈迭代，适合处理需要探索和验证的复杂编码任务。

</details>

**7. Claude Code 的"计划模式"（Plan Mode）解决了什么问题？**

<details>
<summary>💡 查看答案</summary>

在执行有风险或范围较大的修改前，先让模型输出一份可供人工审阅的执行计划而不直接改动代码，避免了 Agent 在理解偏差的情况下"一头扎进"错误的修改方向，把纠错成本从"改完再回滚"提前到了"改之前确认"。

</details>

**8. GitHub Copilot 与 Cursor 相比，核心差异是什么？**

<details>
<summary>💡 查看答案</summary>

Copilot 更偏向"轻量级、嵌入式"的补全增强，作为插件依附于已有 IDE（如 VS Code、JetBrains），改动主流编辑器工作流的幅度较小；Cursor 本身是一个独立的编辑器产品，可以对整个交互界面和上下文管理机制做更深度的定制，天花板更高但迁移成本也更高。

</details>

**9. Windsurf（Codeium）这类产品的定位是什么？**

<details>
<summary>💡 查看答案</summary>

同样走"AI 原生编辑器"路线，与 Cursor 类似强调对项目整体上下文的理解和自动化的多步骤执行（如其 Cascade 功能），差异化点更多在细节交互设计和执行自主程度上的取舍，整体属于同一赛道内的竞品关系。

</details>

**10. Devin 这类"全自主 Agent"和 Cursor 有什么本质区别？**

<details>
<summary>💡 查看答案</summary>

Cursor 的核心假设是"人始终在环内"，每一步修改都便于开发者实时查看和干预；Devin 的核心假设是尽可能让 Agent 独立完成从任务理解到验收的完整闭环，人只在任务开始和结束时介入，对模型的规划能力和自我纠错能力要求更高，出错的容错空间也更小。

</details>

**11. Aider 这类命令行开源工具的特点是什么？**

<details>
<summary>💡 查看答案</summary>

轻量、开源、可自由更换底层模型，专注于"代码修改+Git 集成"这一核心闭环，没有复杂的图形界面和生态绑定，适合追求灵活性、希望自建工作流或对成本敏感的开发者和团队。

</details>

**12. Amazon Q Developer / 云厂商自研工具的优势在哪？**

<details>
<summary>💡 查看答案</summary>

优势主要体现在与云厂商自身生态（云服务 API、内部权限体系、企业级安全合规）的深度打通，对已经深度使用该云生态的企业客户而言，集成成本和信任成本更低，但通用编程体验上不一定领先独立创业公司的产品。

</details>

**13. 为什么有些团队更倾向于开源工具而非商业产品？**

<details>
<summary>💡 查看答案</summary>

主要考虑数据隐私（代码不出内网、可私有化部署）、成本可控（不受制于订阅定价变化）、以及可定制性（可以自由更换或微调底层模型、按团队习惯二次开发），代价是需要自行承担运维和迭代成本。

</details>

**14. 全自主 Agent 路线与人机协作路线，哪种更适合当前阶段？**

<details>
<summary>💡 查看答案</summary>

从当前模型能力看，人机协作路线（关键节点保留人工确认）在实际生产环境中风险更可控、落地更快；全自主路线更适合边界清晰、可验证性强的任务（如有完善测试覆盖的场景），随着模型规划和自我验证能力提升，全自主的适用范围会逐步扩大。

</details>

**15. IDE 插件式产品和独立编辑器式产品各自的优劣势？**

<details>
<summary>💡 查看答案</summary>

插件式产品迁移成本低、可以复用开发者已有的编辑器配置和插件生态，但受限于宿主 IDE 的扩展接口，深度交互设计的自由度较低；独立编辑器产品可以对整个界面和上下文管理机制做深度定制，体验上限更高，但需要开发者迁移工作环境，存在一定采用门槛。

</details>

**16. AI Coding 工具与传统 IDE 智能提示（如 IntelliSense）的本质区别是什么？**

<details>
<summary>💡 查看答案</summary>

传统智能提示基于静态类型推断和符号表，覆盖的是语法层面"合法"的补全；AI Coding 工具基于大模型对语义和意图的理解，能够生成整段逻辑、跨文件的修改甚至理解自然语言描述的需求，覆盖范围从"语法正确"扩展到了"语义合理"。

</details>

**17. 评测 AI Coding 工具应该看哪些维度？**

<details>
<summary>💡 查看答案</summary>

主要包括代码生成的正确性和可维护性、对项目上下文的理解深度、多文件协同修改的连贯性、执行反馈闭环（能否自主运行测试并迭代）、以及响应速度、易用性和定价等工程与体验维度。

</details>

**18. 上下文窗口大小对产品体验的影响有多大？**

<details>
<summary>💡 查看答案</summary>

上下文窗口决定了单次交互能纳入多少代码库信息，窗口过小容易导致模型"看不到"关键的依赖代码而生成局部正确但整体不一致的结果；但窗口并非越大越好，还需要配合检索和上下文筛选机制，否则大窗口下无关信息过多同样会稀释模型的注意力、拉低生成质量。

</details>

**19. 响应速度和生成质量之间如何权衡？**

<details>
<summary>💡 查看答案</summary>

高频、低粒度的场景（如行内补全）需要优先保证响应速度，即使牺牲一定质量也要维持交互的流畅性；低频、高价值的场景（如跨文件重构）用户对等待时间的容忍度更高，此时应优先保证生成质量和正确性，两类场景通常需要用不同规模的模型分别支撑。

</details>

**20. 多语言/多框架支持能力如何评估？**

<details>
<summary>💡 查看答案</summary>

可以通过在不同语言和框架的真实项目上构建统一的任务集（同类任务、不同技术栈）进行横向对比，同时关注工具是否针对小众语言/框架专门做了适配，而不是仅在主流语言（如 Python、JavaScript）上表现良好。

</details>

**21. 产品定价模式（订阅制 vs 按量计费）对用户选择的影响？**

<details>
<summary>💡 查看答案</summary>

订阅制对使用量大、用量可预期的用户更友好，成本可控性强；按量计费更适合用量波动大或轻度使用的用户，避免为不常用的能力付费，企业采购时还需要额外考虑团队规模下批量授权和用量审计的便利性。

</details>

**22. 企业选型 AI Coding 工具时最看重什么？**

<details>
<summary>💡 查看答案</summary>

除了生成质量本身，企业通常更看重数据安全与合规（代码是否会被用于训练、能否私有化部署）、与现有研发流程（CI/CD、代码审查规范）的集成成本、以及团队层面的可管理性（权限控制、使用审计），单纯的模型能力往往不是决定性因素。

</details>
