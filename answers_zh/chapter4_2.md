# 4.2 LoRA / QLoRA 与 PEFT 方法全景 — 题目与答案
> [⬅ 返回目录](../README_ZH.md) · 第 4 章：微调（Fine-Tuning） · 共 34 题

**1. 大模型中常见的微调方法有哪些？**

<details>
<summary>💡 查看答案</summary>

参数微调的方法主要有以下几种：

**Adapter**：在预训练模型每一层（或某些层）中添加 Adapter 模块，微调时冻结预训练模型主体，由 Adapter 模块学习特定下游任务的知识。每个 Adapter 模块由两个前馈子层组成。

![Adapter 微调方法结构图](https://img.pricenode.uk/llm_interview_questions/zhongw/chapter4/adapter_structure.jpg)

**Prefix-tuning**：前缀微调将一个连续的特定于任务的向量序列添加到输入，称之为前缀。与提示（prompt）不同的是，前缀完全由自由参数组成，与真正的 token 不对应。相比于传统的微调，前缀微调只优化了前缀，因此只需要存储一个大型 Transformer 和已知任务特定前缀的副本。

**P-tuning/P-tuning V2**：P-tuning V1 直接对 embedding 层进行优化存在两个挑战：embedding 层已经经过预训练，如果直接对输入的 prompt embedding 进行随机初始化训练，容易陷入局部最优；没法捕捉到 prompt embedding 之间的相关性。P-Tuning V2 是升级版本，在每一层上都加了一个残差连接，每一层都加上 prompts，使特征更充分。

**LoRA**：采用低秩矩阵近似的思想，冻结一个预训练模型的矩阵参数，并选择用 $A$ 和 $B$ 矩阵来替代，在下游任务时只更新 $A$ 和 $B$。

![LoRA 结构示意图](https://img.pricenode.uk/llm_interview_questions/zhongw/chapter4/lora_structure.jpg)

</details>

**2. 有哪几种 SFT 方法？**

<details>
<summary>💡 查看答案</summary>

1. **全量微调（Full Fine-tuning）**：更新模型的所有参数，效果通常最好但计算和存储成本最高，且容易过拟合小数据集或遗忘原有能力。

2. **参数高效微调（PEFT）**：只训练一小部分参数，大幅降低成本：
    - **LoRA**：在权重矩阵旁插入低秩分解的可训练矩阵 A、B，原始权重冻结，推理时可合并。
    - **QLoRA**：在量化后的模型基础上做 LoRA 微调，进一步降低显存需求。
    - **Prefix/Prompt Tuning**：在输入前添加一段可训练的"软提示"向量，冻结模型主体。
    - **Adapter**：在 Transformer 层之间插入小型可训练模块。
    - **(IA)$^3$、BitFit** 等只训练激活的缩放因子或 bias 项的极轻量方法。

3. **指令微调（Instruction Tuning）**：使用大量"指令-回复"对训练，让模型学会遵循各种自然语言指令。

4. **多任务/多轮对话微调**：针对多轮对话场景设计带有角色标记（system/user/assistant）的训练样本，使模型适应对话格式。

</details>

**3. 什么是 LoRA？它的核心思路是什么？**

<details>
<summary>💡 查看答案</summary>

**LoRA（Low-Rank Adaptation）** 是一种参数高效微调方法（PEFT），核心思路是：

预训练模型的权重矩阵在微调过程中的更新量 $\Delta W$ 具有低秩特性，因此可以将 $\Delta W$ 分解为两个小矩阵的乘积：$\Delta W = A \times B$，其中 $A \in R^{d \times r}$，$B \in R^{r \times k}$，$r$ 远小于 $d$ 和 $k$。

训练时冻结原始权重，只训练 $A$ 和 $B$，大幅减少可训练参数量（通常减少 90% 以上）。推理时将 $\Delta W$ 合回原始权重，无额外推理延迟。

</details>

**4. 什么是低秩矩阵？什么是低秩分解？为什么大模型的权重更新可以被假设为低秩的？**

<details>
<summary>💡 查看答案</summary>

**低秩矩阵**：一个 m$\times$n 的矩阵，其秩 r $\ll$ min(m, n)，即矩阵的列（或行）大多线性相关，只有少数几个方向承载了矩阵的主要信息。

**低秩分解**：将原矩阵 W 近似表示为两个小矩阵之积，如 W $\approx$ A $\times$ B，其中 A $\in$ $\mathbb{R}^{m \times r}$，B $\in$ $\mathbb{R}^{r \times n}$，存储和计算量从 O(mn) 降至 O((m+n)$\times$r)。

**为什么权重更新是低秩的？** Aghajanyan et al. 2020（Intrinsic Dimensionality）发现大型预训练模型在微调时具有极低的「内在维度」——即微调实际上只改变了参数空间中一个非常低维的子空间。LoRA 原论文也实验验证：微调前后权重差 $\Delta$W 的有效秩很低，用秩为 4 或 8 的矩阵即可近似表示绝大部分更新。

直觉理解：预训练已建立了丰富的表征，下游任务的适应只需在少数关键方向上「微调」，不需要大规模重塑整个权重空间。

</details>

**5. 请解释 LoRA 的原理与实现方式。**

<details>
<summary>💡 查看答案</summary>

**LoRA（Low-Rank Adaptation）** 是一种参数高效微调（PEFT）方法，其核心思想是：**在微调过程中，权重矩阵的更新量 ΔW 通常具有低秩特性**，因此可以用两个低秩矩阵的乘积来近似 ΔW，而不需要直接训练完整的 ΔW。

**原理**：

对于预训练模型中的某个权重矩阵 W₀（维度为 d×k），全参数微调相当于学习一个更新量 ΔW，使新权重为 W = W₀ + ΔW。LoRA 假设 ΔW 可以分解为两个低秩矩阵的乘积：

ΔW = B·A

其中 A 的维度为 r×k，B 的维度为 d×r，r 是预先设定的秩（rank），且 r << min(d, k)。这样，ΔW 的参数量从 d×k 降低到 r×(d+k)，当 r 很小（如 4、8、16）时，参数量大幅减少。

**前向计算**：

对于原本的线性变换 h = W₀·x，LoRA 改为：

h = W₀·x + B·A·x = W₀·x + (B·A)·x

即原始权重 W₀ **保持冻结不变**，只训练新增的 A 和 B 两个低秩矩阵。

**初始化方式**：
- A 通常用高斯分布随机初始化；
- B 通常初始化为全零矩阵；
- 这样在训练开始时 ΔW = B·A = 0，模型的初始行为与原始预训练模型完全一致，保证训练的稳定起点。

**实现方式**：

1. 选定需要应用 LoRA 的权重矩阵（通常是 Attention 模块中的 Q、V 投影矩阵）；
2. 为每个选定的权重矩阵添加一对低秩矩阵 A、B（作为新增的可训练参数模块），原始权重矩阵设置为不可训练（冻结）；
3. 训练时，只有 A、B 参与梯度更新；
4. 训练完成后：
- **推理时合并**：可以将 ΔW = B·A 计算出来，直接加到原始权重 W₀ 上得到新的权重 W = W₀ + B·A，合并后模型结构与原始模型完全一致，推理时不引入额外的计算开销和延迟；
- **也可以不合并**，保留原始权重和 LoRA 模块独立存在，便于在多个 LoRA 模块之间灵活切换。

</details>

**6. 为何 LoRA 初始化 $B=0$ 而 $A$ 为高斯分布初始化？**

<details>
<summary>💡 查看答案</summary>

首先肯定不能 $A$ 和 $B$ 全部都为 0，全部为 0 的话梯度是没有的。因此需要一部分为 0 初始化，一部分正常初始化，目的是保证模型初始化的时候和原模型一样的输出。如果 $A$ 不为 0 且 $B$ 也不为 0，会导致模型初始化就相对于原先的模型产生了扰动，引入噪声会导致后续训练收敛性没有一个初始化为 0 的好。

理论上证明，$A$ 初始化为高斯分布、$B$ 初始化为 0 的效果更好，原因如下：
1. Init$[A]$ 允许使用比 Init$[B]$ 更大的学习率。
2. Init$[A]$ 可能导致一种“内部不稳定性”，在这种情况下，对于某些输入 $z$，特征 $Az$ 很大，但 LoRA 输出 $BAz$ 很小。这种不稳定性允许更有效的特征学习。
3. Init$[B]$ 不会引起任何不稳定性，但在这种情况下训练是次优的（矩阵 $B$ 训练不足）。
4. 实证结果证实了理论，并表明 Init$[A]$ 通常比 Init$[B]$ 带来更好的性能。

</details>

**7. LoRA 公式中通常有一个缩放因子（$\alpha$/r），它的作用是什么？**

<details>
<summary>💡 查看答案</summary>

LoRA 的前向计算为：**h = W$_0$x + ($\alpha$/r) $\cdot$ BAx**

缩放因子 $\alpha$/r 的作用：

- **幅度控制**：直接决定 LoRA 适配增量 $\Delta$W = BA 对输出的贡献比例，防止小秩矩阵的更新幅度过大或过小影响训练稳定性；
- **与学习率解耦**：固定 $\alpha$ 后，改变 r 时不需要同步调整学习率——r 增大，$\alpha$/r 减小，更新幅度自动缩放；
- **实践意义**：通常设 $\alpha$ = r（缩放因子为 1）或 $\alpha$ = 2r（缩放因子为 2）。原论文发现将 $\alpha$ 设为 r 的常数倍后，调 r 时不再需要专门 tune 学习率，简化超参搜索；
- **本质**：类似 LayerNorm 中增益参数的机制，用于稳定训练动态。

</details>

**8. LoRA 中的秩 r 应该如何选择？**

<details>
<summary>💡 查看答案</summary>

秩 r 是 LoRA 中最核心的超参数，决定了低秩更新矩阵 ΔW = B·A 的表达能力，选择时需要考虑以下因素：

**1. r 的本质含义**

r 决定了 ΔW 这个"更新量"矩阵的秩上限，也就是模型在微调过程中能够学习到的"新增信息"的复杂度上限。r 越大，ΔW 能表达的变化模式越丰富，但同时可训练参数量也线性增加（参数量 ∝ r×(d+k)）。

**2. 任务复杂度与数据量的影响**

- **任务与预训练目标差异较小、数据量较小**：通常较小的 r（如 4、8）就足够，因为模型只需要做较小幅度的"微调整"；过大的 r 在小数据集上容易过拟合，且浪费计算资源。
- **任务与预训练目标差异较大（如领域迁移幅度大、需要学习较多新知识）、数据量较大**：可能需要较大的 r（如 32、64 甚至更大），以提供足够的表达能力捕捉更复杂的更新模式。

**3. 经验取值范围**

- 实践中常见的 r 取值范围为 **4 到 64**，对于大多数下游任务，**r=8 或 r=16** 往往就能取得接近全参数微调的效果，是较常用的默认起点；
- 对于复杂的生成任务、或需要注入大量新知识的场景，可以尝试更大的 r（如 32、64），但收益通常会逐渐递减。

**4. 与 alpha（缩放系数）的配合**

LoRA 通常还有一个缩放系数 alpha，最终的更新量为 (alpha/r)·B·A。实践中常见做法是固定 alpha/r 的比值（如 alpha = 2r 或 alpha = r），调整 r 的同时保持这一比例。

**5. 实验调参建议**

推荐通过小范围实验（如 r ∈ \{4, 8, 16, 32\}）在验证集上比较效果，选择在效果和训练成本之间取得较好平衡的值。

**总结**：r 的选择本质上是在"模型表达能力"和"参数效率/过拟合风险"之间的权衡，**r=8~16 是大多数任务的合理起点**。

</details>

**9. LoRA 一般加在模型的哪些位置？为什么？**

<details>
<summary>💡 查看答案</summary>

**1. 最常见的位置：Attention 模块中的 Q 和 V 投影矩阵**

LoRA 原始论文的实验中发现，**只对 Attention 模块中的 Wq（Query 投影）和 Wv（Value 投影）应用 LoRA**，就能在大多数任务上取得接近全参数微调的效果。原因可能在于：
- Query 投影影响"模型关注什么信息"（注意力的分布模式），Value 投影影响"模型从被关注的位置提取什么信息"，这两者的调整对模型行为的影响相对直接和显著；
- 相比之下，Key 投影（Wk）和输出投影（Wo）对 LoRA 的增量响应相对较小。

**2. 扩展到更多位置**

实践中也常见对以下位置应用 LoRA：
- **Wq、Wk、Wv、Wo（全部 Attention 投影矩阵）**：提供更全面的注意力模式调整能力；
- **FFN 层（如 up_proj、down_proj、gate_proj）**：FFN 层参数量占比更大，包含了模型大部分的"知识存储"，对需要注入较多新知识的任务，在 FFN 层应用 LoRA 往往能带来更明显的效果提升；
- **Embedding 层和输出层（lm_head）**：如果任务涉及词表的变化或输出分布需要较大调整，可以考虑对这部分也应用 LoRA。

**3. 选择位置的考量因素**

- 偏"行为/风格调整"类任务（如对话风格、指令遵循格式）：Attention 相关的 LoRA 通常已足够；
- 偏"知识注入"类任务（如领域知识、新事实）：在 FFN 层增加 LoRA 往往收益更大，因为 FFN 被认为承载了更多的"事实性知识"。

</details>

**10. LoRA 通常作用于 Transformer 的哪些模块？只微调 Attention 和同时微调 MLP 有什么区别？**

<details>
<summary>💡 查看答案</summary>

**常见 target_modules 选择**：

- 仅 Attention：q_proj、v_proj（原论文默认），或加上 k_proj、o_proj；
- Attention + MLP：再加 gate_proj、up_proj、down_proj；
- 全部线性层：包括 embed_tokens、lm_head（较少见，成本高）。

**区别分析**：

\begin{table}[h]

	\caption{LoRA 作用模块对比}


| **策略** | **参数量** | **适用场景** | **说明** |
| --- | --- | --- | --- |
| 仅 Attention | 少 | 语义理解、对话 SFT | Attention 控制词间关系和信息路由，多数任务已足够 |
| 加入 MLP | 多（约 2~3 倍） | 领域知识注入、事实性输出修改 | MLP 是知识存储的关键，注入新知识效果更明显 |

实践建议：指令微调（SFT）中仅 q/v 通常已足够；领域知识注入任务中同时微调 MLP 可获更好效果，但需权衡显存和过拟合风险。

</details>

**12. LoRA 在推理阶段会增加延迟吗？为什么？**

<details>
<summary>💡 查看答案</summary>

**标准 LoRA 推理不增加延迟**——前提是进行「权重合并」（weight merging）。

**原理**：推理前将 A、B 合并到原始权重：**W = W$_0$ + $\alpha$/r $\cdot$ BA**，合并后模型结构与原始模型完全相同，推理时无任何额外计算开销。

**什么情况下会增加延迟？**

- **未合并（动态加载）**：多 LoRA 切换场景（如 vLLM 的 multi-LoRA serving），保留 A/B 矩阵并在推理时动态计算 BAx，会引入约 5~15% 的延迟增加；
- **量化场景**：QLoRA 中原始权重被量化（4bit NF4），合并时需反量化再合并，会损失一定精度；
- **超大秩**：r 非常大时 BAx 的计算量增大，但一般 r $\leq$ 64 时影响可忽略。

**结论**：生产部署时通常先合并权重再导出，推理零开销。

</details>

**13. PEFT 训练完后如何合并权重？**

<details>
<summary>💡 查看答案</summary>

PEFT 方法训练完成后，根据方法的结构特点，合并（merge）权重的方式有所不同：

**1. LoRA / QLoRA 的合并**

LoRA 的更新量为 ΔW = (alpha/r)·B·A，与原始冻结权重 W₀ 是**加法关系**且维度相同，因此可以直接计算：

W_merged = W₀ + (alpha/r)·B·A

合并步骤：
- 加载原始基座模型权重 W₀（如果是 QLoRA，需要先将量化的权重反量化回浮点精度）；
- 加载训练好的 LoRA 权重 A、B；
- 对每个应用了 LoRA 的权重矩阵，计算 ΔW = (alpha/r)·B·A，并与 W₀ 相加得到 W_merged；
- 将 W_merged 替换模型中对应的原始权重，得到一个**结构与原始模型完全一致**的标准模型权重文件；
- 主流框架（如 HuggingFace PEFT 库）通常提供 `merge_and_unload()` 等便捷接口实现这一过程。

注意：QLoRA 中如果基座模型是 4-bit 量化的，合并时通常需要先将基座权重反量化为更高精度（如 FP16/BF16），再与 LoRA 权重相加。

**2. Prompt Tuning / Prefix Tuning / P-Tuning v2 的"合并"**

这类方法本质上是**新增的连续向量参数**，并不是对原模型权重矩阵的加法更新，因此**不存在"合并到原权重矩阵"的操作**，部署时需要将训练好的提示向量与原始模型权重一起保存和加载。

**3. Adapter 的合并**

Adapter 模块是**串行插入**在模型结构中的新增子模块，与原模型权重不是简单的加法关系，因此通常**无法**像 LoRA 一样合并成一个与原模型结构完全相同的权重文件，部署时需要保留 Adapter 模块的结构和权重。

</details>

**14. 还知道其他的矩阵分解方法吗？为什么 LoRA 不直接使用 SVD 进行分解？**

<details>
<summary>💡 查看答案</summary>

**常见矩阵分解方法**：

- **SVD**（奇异值分解）：W = U $\Sigma$ V$^T$，精确分解，广泛用于降维和推荐系统；
- **PCA**（主成分分析）：本质上是对协方差矩阵做 SVD，用于数据降维；
- **NMF**（非负矩阵分解）：约束元素非负，常用于文本主题分析；
- **Tucker 分解 / CP 分解**：张量分解方法，用于多维数据；
- **Cholesky 分解**：适用于正定矩阵，用于数值线性代数。

**为什么 LoRA 不直接用 SVD？**

1. **SVD 是「分析」工具而非「学习」工具**：SVD 对固定矩阵求解，无法在训练中通过反向传播更新；而 LoRA 的 A、B 是可学习参数，随梯度不断优化。
2. **初始化策略不同**：LoRA 将 A 随机初始化（高斯分布）、B 初始化为 0，保证训练初期 $\Delta$W = BA = 0，不干扰预训练权重；SVD 分解得到的初值则携带原权重信息。
3. **计算成本**：对大规模权重矩阵（如 4096$\times$4096）做 SVD 开销极高，而 LoRA 的参数规模很小，更新成本低。

\begin{quote}
	注：AdaLoRA 引入了 SVD 形式的参数化（P $\Lambda$ Q$^T$），并动态调整各层的秩，是 SVD 思想在 LoRA 框架中的实际应用。
\end{quote}

</details>

**15. 你在什么场景下使用过 LoRA？具体微调的是什么模型？**

<details>
<summary>💡 查看答案</summary>

LoRA 广泛用于以下场景：

- **垂直领域适配**：如法律、医疗、金融文本问答，基座模型通常为 LLaMA-2/3、Qwen、ChatGLM、Baichuan 等；
- **指令遵循微调**：基于通用指令数据（Alpaca、BELLE 等）对 7B/13B 模型进行 SFT，使其具备更好的对话能力；
- **风格迁移与写作**：让模型学习特定写作风格、品牌语气；
- **多模态场景**：对 Stable Diffusion、FLUX 等图像生成模型的 U-Net/attention 层注入 LoRA 权重，实现特定角色或风格的生成。

**实践举例**：在 LLaMA-3-8B 上使用 LoRA（r=16, alpha=32）微调领域知识问答数据集，仅训练 Query/Value 投影矩阵，4 块 A100 下约 3 小时收敛，效果接近全量微调。

</details>

**16. LoRA 与全量微调相比，在显存消耗、训练速度和最终效果上有什么差异？**

<details>
<summary>💡 查看答案</summary>

**① 显存消耗**：全量微调需要存储所有参数的梯度和优化器状态（Adam 下约为参数量的 3 倍），而 LoRA 仅对低秩矩阵 A/B 求梯度，可冻结原始权重，显存消耗大幅降低（通常降低 60%~80%）。以 7B 模型为例，全量微调 bf16 约需 80GB+，LoRA 可降至 16~24GB。

**② 训练速度**：LoRA 可训练参数量仅为全量的 0.1%~1%，反向传播计算量更小，配合梯度检查点后每步用时更短；若使用 gradient_checkpointing，全量微调的前向重计算会显著增加耗时，LoRA 的速度优势更明显。

**③ 最终效果**：在数据充足的情况下，全量微调效果上限更高；LoRA 在数据量有限时具备更好的泛化性，不容易过拟合，且可保留预训练知识。对于大多数垂直领域任务，LoRA 的效果与全量微调相差不大（< 1~2%）。

</details>

**17. LoRA 微调与全参数微调效果有什么差异？**

<details>
<summary>💡 查看答案</summary>

LoRA 微调与全参数微调（Full Fine-tuning）的效果差异主要体现在以下方面：

**1. 任务适配的"上限"**

- 对于大多数常见的下游任务（分类、常规指令微调、风格调整、中等程度的领域适配），**LoRA（在合适的秩 r 和应用位置下）的效果可以非常接近全参数微调**，差距通常在几个百分点以内；
- 对于需要**大幅改变模型行为或注入大量新知识**的任务，全参数微调理论上的表达能力上限更高，可能取得比 LoRA 更好的效果。

**2. 过拟合风险**

- LoRA 由于可训练参数量小，在**数据量较小**的场景下通常比全参数微调**更不容易过拟合**，效果可能反而优于全参数微调；
- 在数据量充足的场景下，这一差异会减小。

**3. 灾难性遗忘**

- LoRA 由于原模型参数完全冻结，**对模型原有能力的破坏更小**，在多任务/持续学习场景下遗忘问题相对较轻；
- 全参数微调更容易导致模型在未涉及的任务/领域上的能力下降。

**4. 训练成本与资源需求**

- LoRA 显著降低显存需求，训练速度更快，可以在资源有限的环境下完成微调；
- 全参数微调需要为所有参数维护梯度和优化器状态，资源需求高得多。

**5. 部署与维护**

- LoRA 训练产物体积很小，便于存储和管理多个任务/版本的适配器，灵活切换；
- 全参数微调每个任务/版本都需要保存一份完整的模型权重，存储和管理成本高。

**总结**：在**大多数主流场景**下，LoRA 凭借"效果接近、资源需求低、不易过拟合/遗忘、部署灵活"的综合优势，已经成为事实上的默认选择；只有在**任务与预训练分布差异巨大、需要注入大量新知识、且有充足数据和算力支持**的场景下，全参数微调才可能展现出明显优于 LoRA 的效果。

</details>

**18. 计算一个拥有 96 个 Transformer 块，且每个块有 12288 × 12288 权重矩阵的模型，使用秩为 8 的 LoRA 后，需要微调的参数量是多少？**

<details>
<summary>💡 查看答案</summary>

**单个 LoRA 模块的参数量公式**：

对于一个 d×k 的权重矩阵（这里 d=k=12288），秩为 r 的 LoRA 引入两个矩阵：
- A：维度为 r×k = 8×12288
- B：维度为 d×r = 12288×8

单个 LoRA 模块的参数量为：

$r \times k + d \times r = r \times (d+k) = 8 \times (12288+12288) = 8 \times 24576 = **196,608**$

**情况一：每个 Transformer block 只有 1 个这样的权重矩阵应用 LoRA**

总参数量 = 196,608 × 96 = **18,874,368 ≈ 1887 万**

**情况二：对 Wq 和 Wv 应用 LoRA（LoRA 论文中最常见的默认设置）**

每个 block 的 LoRA 参数量 = 196,608 × 2 = 393,216

总参数量 = 393,216 × 96 = **37,748,736 ≈ 3775 万**

**情况三：对 Wq、Wk、Wv、Wo 全部应用 LoRA**

每个 block 的 LoRA 参数量 = 196,608 × 4 = 786,432

总参数量 = 786,432 × 96 = **75,497,472 ≈ 7550 万**

**总结**：核心计算公式为 **总参数量 = r × (d + k) × (每个 block 中应用 LoRA 的矩阵数量) × block 数量**，体现了 LoRA 在参数效率上的巨大优势。

</details>

**19. 如果在使用 LoRA 微调时发现模型出现了严重的"灾难性遗忘"，你会怎么排查和解决？**

<details>
<summary>💡 查看答案</summary>

**排查方向**：

- 训练数据是否过于单一，与预训练数据分布差异过大；
- 学习率过高，LoRA 参数更新步幅太大；
- 秩 r 设置过大，LoRA 退化为接近全量微调；
- 训练轮数过多，严重过拟合到微调数据；
- target_modules 范围过广，微调层数越多遗忘越严重。

**解决方案**：

\begin{table}[h]

	\caption{灾难性遗忘解决方案}


| **方法** | **说明** |
| --- | --- |
| 数据回放 | 混入通用数据（如 SlimPajama），与领域数据按 1:3~1:5 比例混合训练 |
| 降低学习率 | 从 2e-4 降至 5e-5，配合 warmup 调度 |
| 降低 r | 从 32 降到 8 或 4，减少可修改参数空间 |
| EWC 正则 | 在 loss 中加惩罚项，约束重要参数的变化幅度 |
| 缩小 target_modules | 仅微调 q_proj/v_proj，保留 MLP 权重不变 |
| 早停 | 在验证集通用指标开始下降时停止训练 |


\end{table}

**20. 什么是 LoRA 和 QLoRA？**

<details>
<summary>💡 查看答案</summary>

**LoRA（低秩适应）**是一种微调方法，通过添加少量额外参数来调整预训练语言模型，使其适应新的任务。它不更新模型的所有参数，而是通过引入低秩矩阵来降低微调过程中的内存和计算成本。优势在于不需要重新训练整个模型，能够高效地完成适应。

**QLoRA（量化 LoRA）**是 LoRA 的一个变种，通过量化模型权重（例如使用 4 位量化）来进一步减少内存占用和计算需求。它特别适合在资源有限的硬件上运行大型模型。

</details>

**21. 了解过 QLoRA 吗？它和普通的 LoRA 有什么区别？**

<details>
<summary>💡 查看答案</summary>

QLoRA（Quantized LoRA，Dettmers et al. 2023）是 LoRA 的量化增强版，核心贡献三点：

1. **NF4 量化（4-bit NormalFloat）**：将冻结的基础模型权重量化为 4bit，利用正态分布的信息论最优量化格式，相比 INT4 精度损失更小；
2. **双量化（Double Quantization）**：对量化常数（scale factors）再次量化，额外节省约 0.37 bits/参数；
3. **分页优化器（Paged Optimizers）**：利用 NVIDIA 统一内存，在 GPU 显存不足时将优化器状态 page 到 CPU，避免 OOM。

**与普通 LoRA 的区别**：

\begin{table}[h]

	\caption{QLoRA 与普通 LoRA 对比}


| **维度** | **普通 LoRA** | **QLoRA** |
| --- | --- | --- |
| 基础模型精度 | bf16/fp16 | 4bit NF4 |
| 显存需求 | 较高（如 65B 需多卡） | 极低（65B 可在单张 24GB GPU 微调） |
| 训练速度 | 快 | 慢约 20~30%（反量化开销） |
| 精度损失 | 无 | 极小，效果可匹配全精度 LoRA |
| 推理部署 | 合并后零延迟 | 需反量化合并或用量化推理引擎 |


\end{table}

![普通 LoRA 与 QLoRA 技术对比](https://img.pricenode.uk/llm_interview_questions/zhongw/chapter4/fig_qlora_vs_lora.png)

</details>

**22. QLoRA 相比 LoRA 有什么改进？**

<details>
<summary>💡 查看答案</summary>

**QLoRA** 在 LoRA 基础上引入了量化技术，进一步降低显存占用：
- 将基础模型量化为 **4-bit NormalFloat（NF4）** 精度存储，显存降低约 4 倍
- 引入**双重量化（Double Quantization）**，对量化常数再次量化，进一步节省显存
- 使用**分页优化器（Paged Optimizer）**，防止 GPU 显存峰值溢出
- LoRA 适配器仍以 BF16 精度训练，保证训练精度
效果：使得在单张消费级显卡（如 RTX 3090）上微调 65B 模型成为可能。

</details>

**23. QLoRA 中量化与 LoRA 结合的原理是什么？**

<details>
<summary>💡 查看答案</summary>

QLoRA（Quantized LoRA）的核心思想是：**将预训练模型的权重量化为极低比特（如 4-bit）以大幅降低显存占用，同时在量化后的模型上添加 LoRA 适配器进行微调**，使得在显存有限的单卡上也能微调超大规模模型。其关键技术组成包括：

**1. 4-bit NormalFloat（NF4）量化**

- QLoRA 提出了一种专门针对神经网络权重（通常近似服从零均值正态分布）设计的 4-bit 数据类型 NF4，相比普通的 4-bit 整数量化，NF4 的量化级别分布更贴合正态分布权重的实际取值分布，能在相同比特数下保留更多信息、减少量化误差。

**2. 双重量化（Double Quantization）**

- 量化过程本身需要为每个量化块存储一个缩放因子，这些缩放因子通常以 FP32 存储；QLoRA 对这些缩放因子**再做一次量化**（如量化为 8-bit），进一步压缩存储开销。

**3. 分页优化器（Paged Optimizers）**

- 利用 NVIDIA 统一内存特性，当 GPU 显存不足时，自动将优化器状态等数据**分页**转移到 CPU 内存，避免训练过程中因显存峰值瞬间超出而导致 OOM。

**4. 量化模型 + LoRA 的训练流程**

- **基座模型权重**：以 4-bit NF4 格式量化并冻结；
- **LoRA 适配器**：以较高精度（如 BF16）添加在量化后的权重之上，只有 LoRA 的 A、B 矩阵是可训练参数；
- **前向计算**：4-bit 量化的权重会被"反量化"回较高精度进行矩阵乘法计算，LoRA 部分的计算正常以 BF16 进行；
- **反向传播**：梯度只反向传播给 LoRA 的 A、B 矩阵（量化的基座权重不需要计算梯度），这是显存节省的核心来源。

</details>

**24. QLoRA 中的分块量化如何解决了普通量化导致的信息损失问题？**

<details>
<summary>💡 查看答案</summary>

**普通（全局）量化的信息损失问题**：

朴素的量化方法通常对整个权重张量使用**统一的缩放因子**进行量化。这种"全局量化"存在的问题是：如果权重张量中存在**少数数值幅度特别大的"离群值"（outliers）**，全局缩放因子会被这些离群值"拉大"，导致大多数（数值较小的）权重在量化后被映射到量化级别中非常密集、分辨率很低的区域，造成量化误差显著增大。

**分块量化（Block-wise Quantization）的解决方案**：

QLoRA 采用**分块量化**：将权重张量**切分成多个较小的块（block，如每 64 个元素为一个块）**，**每个块独立计算自己的缩放因子**进行量化。

这样做的好处是：
- **将离群值的影响范围限制在其所在的块内**，不会影响张量中其他块的量化精度；
- 大多数块内的数值分布更"集中"（动态范围较小），可以用相对更精细的缩放因子进行量化，整体的量化误差显著降低；
- 相当于用"更细粒度的局部自适应缩放"替代"粗粒度的全局统一缩放"，更好地适配权重张量内部数值分布的不均匀性。

</details>

**25. 社区后来提出了很多 LoRA 变体，能挑一个讲讲它解决了什么痛点吗？**

<details>
<summary>💡 查看答案</summary>

以 **DoRA（Weight-Decomposed Low-Rank Adaptation，Liu et al. 2024）** 为例：

**LoRA 的痛点**：固定秩的低秩矩阵只能进行「方向+幅度」的混合调整，容易偏向「幅度变化」而忽略「方向调整」，某些任务效果不如全量微调。

**DoRA 的核心思想**：将权重矩阵 W 分解为「幅度」向量 m 和「方向」矩阵 V 两个部分：

\begin{verbatim}
	W = m · (V / ||V||)
\end{verbatim}

再用 LoRA 更新方向矩阵 V：V = W$_0$ + BA

**优势**：
- 方向和幅度解耦，模型可以独立调整「权重的大小」和「权重的方向」，表达能力更强；
- 在多个任务上显著优于 LoRA，可训练参数量仅略多于 LoRA；
- 与 QLoRA 兼容，可在量化场景下使用。

\begin{quote}
	**AdaLoRA 补充**：AdaLoRA 将 LoRA 参数化为 P $\Sigma$ Q$^T$（类 SVD 形式），并基于奇异值的重要性动态裁剪各层的秩，解决了「所有层用同一秩」不合理的问题，实现参数预算的自适应分配。
\end{quote}

</details>

<details>
<summary>💡 查看答案</summary>

\begin{table}[h]

	\caption{PEFT 方法对比}


| **方法** | **核心思路** | **优点** | **缺点** |
| --- | --- | --- | --- |
| Adapter Tuning | 在 FFN/Attention 后插入小型瓶颈模块 | 参数少，灵活 | 推理时无法合并，增加延迟 |

**27. Adapter 结构的基本原理是什么？**

<details>
<summary>💡 查看答案</summary>

Adapter 是早于 LoRA 提出的一类参数高效微调方法，其核心思想是：**在预训练模型的每个（或部分）Transformer 层中插入小型的、新增的可训练模块（Adapter 模块），原始模型参数保持冻结，只训练这些新增模块**。

**结构设计**：

一个典型的 Adapter 模块通常是一个**瓶颈结构（Bottleneck）的小型前馈网络**：
- 先通过一个**降维的线性层**（将隐藏维度 d 投影到一个较小的瓶颈维度 m，m << d）；
- 经过一个非线性激活函数（如 ReLU/GeLU）；
- 再通过一个**升维的线性层**（将维度从 m 投影回 d）；
- 通常还会加上一个**残差连接**：Adapter 的输出 = 输入 + Adapter(输入)，使得 Adapter 初始化为接近恒等映射。

**与 LoRA 的对比**：

- **结构差异**：Adapter 是**串行插入**的新模块（前向计算路径中增加了额外的层），会增加推理时的计算路径长度；而 LoRA 是**并行的低秩分支**，在推理时可以与原权重合并，不改变原模型结构、不增加推理延迟。
- **推理效率**：LoRA 合并后零额外推理开销；Adapter 在推理时保留串行结构，有额外延迟。

</details>

**28. Prefix Tuning 的原理是什么？**

<details>
<summary>💡 查看答案</summary>

Prefix Tuning 是一种针对生成任务（尤其是基于 Transformer 的自回归/Encoder-Decoder 模型）设计的参数高效微调方法，其核心思想是：**在 Transformer 每一层的 Attention 计算中，为 Key 和 Value 添加一段可训练的"虚拟前缀"（prefix），原始模型参数保持冻结，只训练这些前缀向量**。

**原理细节**：

1. **不是在输入文本前面拼接真实的 token**，而是在每一层 Attention 的 Key 矩阵和 Value 矩阵前面，拼接上一段**长度固定（如 p 个位置）、可训练的连续向量（prefix vectors）**，这些向量不对应任何真实的词表 token，是直接在连续向量空间中学习得到的"虚拟 token 表示"。
2. 经过这样处理后，Attention 的计算变为：query 向量会与"prefix 的 Key 向量 + 真实输入的 Key 向量"做注意力计算，从而使每一层的输出都会受到这些可训练 prefix 向量的影响，相当于通过 prefix 向量为模型的每一层注入了一种"任务特定的上下文/指令"。
3. **每一层都有独立的一组 prefix 向量**，这使得 prefix 能够在模型的不同层级上、以不同的方式影响模型的中间表示和注意力模式，提供比"只在输入端添加 prompt"更强的调控能力。
4. **重参数化（Reparameterization）**：直接优化 prefix 向量有时训练不稳定，原论文提出通过一个小型 MLP 网络，从一组更低维的可训练参数生成最终的 prefix 向量。

**与传统 Prompt（离散文本提示）的区别**：

Prefix Tuning 中的"前缀"是**连续向量空间中的可训练参数**，而不是真实存在于词表中的离散 token，因此称为"软提示"（soft prompt）；这使得优化可以通过梯度下降直接进行。

</details>

**29. Prompt Tuning 的原理是什么？**

<details>
<summary>💡 查看答案</summary>

Prompt Tuning 是比 Prefix Tuning 更简化的一种软提示方法，其核心思想是：**只在模型的输入嵌入层（embedding layer）前面拼接一段可训练的连续向量（soft prompt），模型的其他所有参数（包括所有 Transformer 层）保持完全冻结**。

**原理细节**：

1. 给定输入文本，先将其转换为词嵌入序列（embedding sequence）；
2. 在这个嵌入序列的最前面，拼接上一段长度为 p 的**可训练嵌入向量**，形成新的输入序列：[soft prompt embeddings] + [原始输入 embeddings]；
3. 将拼接后的序列正常输入到（完全冻结的）Transformer 模型中，进行前向计算；
4. 训练时，梯度只反向传播到这些 soft prompt 向量，模型本身的所有参数都不更新。

**与 Prefix Tuning 的关键区别**：

- **作用位置**：Prompt Tuning 只在**输入层（embedding 层）**添加可训练向量；Prefix Tuning 在**每一层 Attention 的 K、V**都添加独立的可训练前缀，对模型每一层的中间计算都有直接、独立的影响。
- **表达能力**：Prompt Tuning 的效果**在模型规模足够大（如数十亿参数以上）时才能接近全参数微调的效果**；在中小模型上，Prompt Tuning 的效果往往明显不如 Prefix Tuning 或全参数微调。

</details>

**30. P-Tuning、Prompt-tuning 和 Prefix-tuning 区别是什么？**

<details>
<summary>💡 查看答案</summary>

- **Prefix-tuning 对比 P-tuning**：Prefix-Tuning 是将额外的 embedding 加在开头，看起来更像模仿 Instruction 指令，而 P-Tuning 位置不固定；Prefix-Tuning 通过在每个层都添加可训练参数，通过 MLP 初始化，而 P-Tuning 只在输入的时候加入 embedding，并通过 LSTM 或 MLP 初始化。
- **Prefix-tuning 对比 Prompt-tuning**：Prompt Tuning 方式可以看做是 Prefix Tuning 的简化，只在输入层加入 prompt tokens，并不需要加入 MLP 进行调整来解决难训练的问题。
- **P-tuning 和 Prompt-tuning 的区别**：P-Tuning 在输入的时候加入 embedding，并通过 LSTM 或MLP 初始化，且位置不固定；而 Prompt-tuning 只在输入加上虚拟的 token 来学习，还不是自由参数形式。

</details>

**31. P-Tuning v2 的原理是什么？**

<details>
<summary>💡 查看答案</summary>

P-Tuning v2 可以看作是**将 Prefix Tuning 的思想系统化并应用到更广泛任务（尤其是 NLU 任务）和更小规模模型上**的改进方法，旨在解决 Prompt Tuning 在中小模型和复杂 NLU 任务上效果不佳的问题。

**核心改进点**：

1. **在每一层都添加可训练的连续提示（类似 Prefix Tuning）**：P-Tuning v2 在 Transformer **每一层的输入（或 K、V）中都加入独立的可训练连续向量**，使得模型每一层都能受到任务特定信号的直接调控，显著增强了表达能力，使其在中小模型上也能取得接近全参数微调的效果。
2. **去除重参数化编码器**：P-Tuning v2 发现直接优化连续提示向量本身即可，简化了结构。
3. **针对不同任务采用不同的输出层设计**：P-Tuning v2 回归更传统的做法：**为不同任务（分类、序列标注等）添加对应的任务特定输出层（如线性分类头）**，使得 P-Tuning v2 可以更自然地适配各种 NLU 任务格式（包括序列标注等 token-level 任务）。

**与 Prefix Tuning 的关系**：

P-Tuning v2 在结构上与 Prefix Tuning 非常相似，可以视为 Prefix Tuning 思想在 NLU 任务上的系统化验证和工程改进，论文的主要贡献在于证明了"深层提示"（deep prompt，每层都有提示）这一范式在**各种规模的模型和各种 NLU 任务**上都能稳定地达到接近全参数微调的效果。

</details>

**32. 几种常见 PEFT 方法对比各有什么优劣？**

<details>
<summary>💡 查看答案</summary>

| 方法 | 核心思路 | 参数量 | 推理开销 | 优点 | 缺点 |
| --- | --- | --- | --- | --- | --- |
| **LoRA** | 用低秩矩阵 B·A 近似权重更新量 ΔW，并行加在原权重旁 | 较小（与秩 r 和应用位置数相关） | 可合并，**零额外推理开销** | 效果接近全参数微调；推理无延迟；多任务切换灵活 | 需要选择 r 和应用位置；对极度复杂的能力迁移可能仍有上限 |
| **QLoRA** | LoRA + 基座模型 4-bit 量化 | 与 LoRA 相近（可训练参数） | 推理时需反量化，略增加计算但显存大幅降低 | 显存需求极低，可在单卡微调超大模型 | 量化引入一定精度损失；实现相对复杂 |
| **Adapter** | 在 Transformer 层内插入瓶颈结构的小型 FFN 模块 | 较小（与瓶颈维度和插入位置数相关） | **串行结构，增加推理延迟** | 灵活插入、多任务隔离性好 | 推理有额外延迟，不能像 LoRA 一样无缝合并 |
| **Prefix Tuning** | 每层 Attention 的 K、V 前拼接可训练前缀向量 | 中等（与层数、prefix 长度相关） | 占用部分有效上下文长度，增加少量计算 | 对生成任务效果好；每层独立调控 | prefix 长度需要调优；占用上下文窗口 |
| **Prompt Tuning** | 只在输入 embedding 层拼接可训练向量，模型完全冻结 | **最小**（仅与 prompt 长度和 hidden size 相关） | 几乎无额外开销（仅增加序列长度） | 参数量极小，多任务切换极轻量 | 效果对模型规模敏感，小模型上效果较差 |
| **P-Tuning v2** | 每层都加入可训练连续提示（深层提示）+ 任务特定输出层 | 中等 | 类似 Prefix Tuning | 在各种规模模型和 NLU 任务上效果稳定，接近全参数微调 | 参数量比 Prompt Tuning 大；结构相对复杂 |



**综合对比维度**：

1. **效果上限**：全参数微调 > LoRA（在合适的 r 和位置下接近全参数） ≈ P-Tuning v2 ≈ Prefix Tuning > Adapter ≈ Prompt Tuning（在小模型上）；
2. **推理效率**：LoRA（合并后零开销）> QLoRA（量化反量化有一定开销）> Prompt Tuning（仅增加少量 token）> Prefix Tuning/P-Tuning v2（占用部分上下文+少量计算）> Adapter（串行结构，延迟最明显）；
3. **显存效率（训练时）**：QLoRA（最优，基座量化）> LoRA > Prompt Tuning/Prefix Tuning > Adapter（取决于瓶颈大小）；
4. **实现复杂度与生态支持**：LoRA 由于其结构简单且可合并，在主流框架中支持最为完善，是当前事实上的"默认选择"。

**总结**：**LoRA（及其量化版本 QLoRA）由于综合了"效果接近全参数微调"和"推理零额外开销"两大优势，并有完善的工具链支持，是目前最主流和实用的 PEFT 方法**。

</details>

**33. 轻量级微调（例如 LoRA）的经验有哪些？**

<details>
<summary>💡 查看答案</summary>

不建议采用轻量级微调方法，更推荐租用更多的计算资源进行全参数训练。尽管 LoRA 在特定领域可能有效，但它可能会限制模型的性能上限并引入新的问题。

</details>

**34. 哪些因素会影响内存使用？**

<details>
<summary>💡 查看答案</summary>

内存使用受到模型大小、批量大小、LoRA 参数数量以及数据集特性的影响。例如，使用较短的训练序列可以节省内存。
