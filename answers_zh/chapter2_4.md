# 2.4 ICL 示例选择、顺序与格式 — 题目与答案
> [⬅ 返回目录](../README_ZH.md) · 第 2 章：提示与上下文工程（Prompt & Context Engineering） · 共 24 题

**1. 什么是 prompt 的"格式"（format）？它对 ICL 的影响有多大？**

<details>
<summary>💡 查看答案</summary>

格式指 prompt 的结构化呈现方式，包括示例的排布方式、分隔符、标签的表示形式（`Label: X` vs `Answer: X`）、输入输出的对齐方式等。影响非常大：\begin{enumerate}
- 格式不一致会导致模型误解任务结构，输出格式错乱；\item  同一任务不同格式下，准确率差异可达 10–20%；\item  格式直接影响模型"从哪里读取标签"的理解；\item  好的格式：清晰的分隔符（`###`、`<input>`/`<output>` 标签）、一致的对齐方式、每个示例结构相同。格式的重要性甚至高于示例内容本身的质量。

</details>

**2. ICL 中 query 和 demonstration 的格式是否需要保持一致？**

<details>
<summary>💡 查看答案</summary>

必须保持一致。query 和 demonstration 应该使用完全相同的格式模板，只是 query 缺少输出部分（模型需要填充的部分）。如果格式不一致：\begin{enumerate}
- 模型可能误判任务结构，不知道"输出应该出现在哪里"；\item  格式差异会被模型解读为不同任务，导致输出偏差；\item  分隔符、标签名称（"Input:"/"Question:"）需要在所有示例和 query 中完全一致。最佳实践：用统一的模板生成所有示例和 query，避免手工组合时的格式不一致。

</details>

**3. 什么是"任务描述"（task description）？它在 ICL 中是否必须？**

<details>
<summary>💡 查看答案</summary>

任务描述是在示例之前对任务的自然语言说明（"请将以下英文句子翻译为中文："、"判断以下评论的情感倾向，输出正面/负面："）。是否必须：\begin{enumerate}
- **Zero-shot**：没有示例时，任务描述是关键的唯一信号，对效果影响很大；\item  **Few-shot**：有充分示例时，任务描述的重要性下降，模型可以从示例中推断任务；\item  **复杂任务**：任务有特殊约束时，任务描述用于补充示例无法展示的细节；\item  一般建议：始终提供任务描述，即使有示例，任务描述能消除歧义，降低输出不稳定性。

</details>

**4. ICL 适合处理哪些类型的 NLP 任务？**

<details>
<summary>💡 查看答案</summary>

**适合**：\begin{enumerate}
- 文本分类（情感分析、主题分类）；\item  命名实体识别（NER）；\item  文本摘要；\item  机器翻译；\item  问答（知识已在模型中）；\item  文本生成（风格迁移、续写）；\item  代码生成（模式固定的任务）；\item  格式转换（JSON 结构化抽取）。**效果有限的任务**：
- 需要实时知识的问答（知识不在模型中）；\item  复杂数值计算（需要结合代码执行）；\item  需要大量专业知识的深度推理；\item  极度个性化（需要大量用户数据适配）。

</details>

**5. Few-shot 示例的选择对 ICL 效果影响有多大？有哪些选择原则？**

<details>
<summary>💡 查看答案</summary>

影响非常大，不同示例集合可以导致 5–20% 的准确率差异。选择原则：

1. **多样性**：覆盖不同的输入模式、类型和难度，避免高度相似的示例；
2. **代表性**：示例应来自目标任务的真实数据分布，而非特意挑选的极端案例；
3. **质量**：示例的输入输出必须正确且格式规范；
4. **相关性**：与当前查询（query）语义相近的动态选择示例，效果优于固定随机示例约 5%–10%；
5. **难度梯度**：示例应包含从简单到困难的层次，以帮助模型理解任务边界；
6. **标签均衡**：在分类任务中，各类别示例数量应尽量保持均衡。

</details>

**6. 什么是静态示例和动态示例？各自的优缺点是什么？**

<details>
<summary>💡 查看答案</summary>

**静态示例**：为所有 query 使用固定的同一套示例。优点：实现简单，推理稳定，无额外计算开销。缺点：对于与示例分布差异大的 query 效果差，示例相关性不保证。**动态示例**：根据当前 query 从示例池中实时检索最相关的示例（通常用 Embedding 相似度）。优点：示例与 query 高度相关，效果更好；适应性强。缺点：需要额外的检索步骤（延迟增加、实现复杂）；检索质量影响最终效果。经验：数据分布相对均匀时静态示例够用；分布差异大或对效果要求高时用动态示例，通常提升 5–10%。

</details>

**7. 什么是 KATE（KNN-Augmented in-conText Example selection）？它的核心思路是什么？**

<details>
<summary>💡 查看答案</summary>

KATE（Liu et al. 2021）：用 K 近邻算法为每个测试 query 选择最相似的训练样本作为 ICL 示例，而不是随机选择。核心思路：\begin{enumerate}
- 将所有候选示例用 Sentence Embedding 向量化；\item  对当前 query 做 embedding；\item  计算 query 与所有候选示例的余弦相似度；\item  选取 top-k 相似的样本作为示例；\item  按相似度降序排列（最相关的放最后，靠近 query，利用近因效应）。效果：相比随机示例选择，KATE 在多个 NLP 任务上提升 3–10%。局限：需要预先对候选池做 embedding，有一定计算和存储开销。

</details>

**8. 如何为 ICL 构建一个高质量的示例候选池（demonstration pool）？**

<details>
<summary>💡 查看答案</summary>

1. **来源多样化**：从不同数据源、不同用户、不同场景收集样本，确保覆盖全面；\item  **质量标注**：人工或用强 LLM 对每个候选示例的输入输出对进行质量审核，去除低质量样本；\item  **去重处理**：去除高度相似的示例（相似度 > 0.9），保证池内多样性；\item  **均衡采样**：分类任务确保每个类别有足够数量的高质量样本；\item  **难度分层**：维护简单、中等、困难三个层次的示例，便于按需选取；\item  **持续更新**：随业务数据积累，定期更新示例池，加入新模式，移除过时示例；\item  **规模建议**：每个类别至少 20–50 个高质量样本，总池大小 200–1000。

</details>

**9. 示例的多样性和相关性之间如何权衡？**

<details>
<summary>💡 查看答案</summary>

两者都重要，但方向不同：**相关性**（KATE 方向）：确保示例与当前 query 匹配，模型更容易迁移；**多样性**（覆盖方向）：确保示例覆盖任务的不同输入模式，模型理解任务全貌。权衡策略：\begin{enumerate}
- **任务分布均匀时**：优先相关性，每个 query 选最相似的示例；\item  **任务分布不均匀时**：先按多样性选基础示例集，再用相关性筛选；\item  **MMR 算法**：Maximal Marginal Relevance，在选择时同时考虑与 query 的相关性和与已选示例的差异性，取得平衡；\item  经验：通常 4 个示例中，2 个高相关 + 2 个多样性覆盖，效果优于 4 个全相关或全多样。

</details>

**10. 如何选择适合当前 query 的最相关示例（Selective ICL）？**

<details>
<summary>💡 查看答案</summary>

主流方法：\begin{enumerate}
- **Embedding 相似度**：对 query 和候选示例做 embedding，按余弦相似度选 top-k（KATE）；\item  **BM25 检索**：关键词匹配选相似示例，速度快，适合有大量精确术语的任务；\item  **混合检索**：Embedding 相似度 + BM25 的融合，兼顾语义和词汇匹配；\item  **LLM 评分**：让 LLM 对 query-示例对的相关性打分，精度最高但成本高；\item  **EPR（Efficient Prompt Retrieval）**：专门训练一个示例检索模型，以 ICL 最终效果作为训练信号；\item  实践建议：大多数场景 Embedding 相似度 + 简单 BM25 即可满足需求。

</details>

**11. 示例中的难度梯度（从易到难）对 ICL 效果有什么影响？**

<details>
<summary>💡 查看答案</summary>

从易到难的示例排列通常优于随机顺序：\begin{enumerate}
- **学习曲线模拟**：先展示简单案例让模型理解基本模式，再展示复杂案例扩展边界；\item  **难度感知**：模型能感知任务的复杂程度范围，不会因为只看到简单示例而低估任务复杂度；\item  **近因效应叠加**：将最复杂（与难 query 最相似）的示例放最后，既满足难度梯度又利用近因效应；\item  注意：如果所有示例都是简单案例，模型对复杂 query 的泛化效果差；反之，全是复杂示例可能让模型过度复杂化简单问题。

</details>

**12. 如何处理候选示例池中的重复或高度相似的样本？**

<details>
<summary>💡 查看答案</summary>

1. **预处理去重**：在构建示例池时，计算所有样本对的 Embedding 相似度，相似度 > 0.9 的样本只保留一个（质量更高的那个）；\item  **MinHash LSH**：对于大规模示例池，用 MinHash 局部敏感哈希快速检测近似重复，比全量两两比较效率高；\item  **聚类去重**：对示例池做聚类（K-Means），每个聚类只保留离中心最近的代表性样本；\item  **在线去重**：动态示例选择时，已选的示例不再参与后续选择，避免选出高度相似的多个示例；\item  **多样性约束**：选示例时加 MMR 约束，自然减少相似示例入选。

</details>

**13. 当任务数据非常少时（如 3–5 个样本），如何最大化 ICL 效果？**

<details>
<summary>💡 查看答案</summary>

1. **精心设计格式**：格式的影响在数据极少时更大，花时间优化 prompt 结构；\item  **优化任务描述**：补充详细的任务说明，弥补示例数量不足；\item  **数据增强**：用 LLM 生成更多伪标注示例扩充示例池（让 GPT-4 生成类似格式的更多示例）；\item  **选最有代表性的示例**：手工挑选涵盖不同输入模式的示例，最大化多样性；\item  **CoT 示例**：如果任务涉及推理，在少量示例中加入推理步骤，效果往往优于纯输入输出示例；\item  **Self-Consistency**：多次采样取投票，减少少量示例带来的不稳定性；\item  **结合 Zero-shot CoT**：数据太少时，Zero-shot CoT（"Let's think step by step"）有时比少量低质量示例效果更好。

</details>

**14. 如何自动化评估示例选择策略的质量？**

<details>
<summary>💡 查看答案</summary>

1. **构建评估集**：从目标任务数据中划出验证集（不用于示例池），标注标准答案；\item  **基线对比**：分别运行随机示例选择和目标选择策略，在验证集上计算准确率/F1；\item  **Leave-one-out 评估**：对验证集每个样本，选取其余样本中的示例，评估预测准确率；\item  **检索质量指标**：如果是检索式选择，额外评估检索到的示例与 query 的相关性分数分布；\item  **稳定性测试**：多次运行评估（不同随机种子），计算准确率的方差，方差小说明策略稳定；\item  **成本-效果曲线**：对比不同 k 值下的效果和 token 消耗，找最优 k。

</details>

**15. 示例的顺序会影响 ICL 的输出结果吗？研究结论是什么？**

<details>
<summary>💡 查看答案</summary>

会显著影响，这是 ICL 的已知脆弱性之一。主要研究结论：\begin{enumerate}
- **近因偏见（Recency Bias）**：最后几个示例对模型影响最大，应把最重要的示例放在靠近 query 的位置（Lu et al. 2021）；\item  **顺序敏感性**：不同顺序导致的准确率差异可达 10–20%（小模型更敏感，大模型相对稳定）；\item  **最优顺序难以预测**：不存在普遍最优顺序，不同任务和模型的最优顺序不同；\item  缓解方法：Self-Consistency（多次采样不同顺序后投票）；专门的示例排序优化算法（GlobalE、METAICL）。

</details>

**16. 什么是"近因效应"（recency bias）？在 ICL 中如何应对？**

<details>
<summary>💡 查看答案</summary>

近因效应：模型对 prompt 末尾（靠近 query）的示例赋予更高权重，而忽视开头的示例，导致最终预测偏向最后几个示例的标签。应对方法：\begin{enumerate}
- **策略性排序**：将与当前 query 最相关或最重要的示例放在最后；\item  **多样性平衡**：如果标签有分布不均，把少数类别的示例放在后面补偿；\item  **Self-Consistency**：多次运行不同顺序的 prompt，投票取多数结果，稀释近因效应；\item  **Calibration**：用 PMI 或无内容 prompt 的基线校正各标签的先验偏见；\item  **更大的模型**：大模型对近因效应相对不那么敏感。

</details>

**17. 示例标签分布（如正负样本比例）对 ICL 有什么影响？**

<details>
<summary>💡 查看答案</summary>

标签分布对 ICL 效果有显著影响，称为"多数标签偏见"：\begin{enumerate}
- **正样本偏多**：模型会偏向预测正标签，即使输入更像负类；\item  **标签不均衡可以被利用**：故意构造不均衡的示例分布，可以引导模型偏向特定标签（但不推荐用于生产）；\item  **理想状态**：各标签在示例中均匀分布（2分类任务各50%，多分类任务各均等）；\item  **实验发现**：即使标签是随机分配的（错误标签），模型的标签分布偏见依然存在，说明这不仅是学习效果，也是先验偏见问题；\item  **校准修正**：使用 Calibration（PMI 归一化）可以在一定程度上纠正多数标签偏见。

</details>

**18. 如何缓解 ICL 中的"多数标签偏见"（majority label bias）？**

<details>
<summary>💡 查看答案</summary>

1. **均衡示例**：构建标签分布均匀的示例集，从源头避免偏见；\item  **Calibration（校准）**：用无内容的 null input 测量模型对各标签的先验概率，在预测时减去这个先验（PMI 归一化）；\item  **Contextual Calibration（CC）**：Zhao et al. 2021 提出，用 "N/A" 或空格替换输入，获取每个标签的上下文先验，然后在预测时用这个先验校正；\item  **Domain-Context Calibration（DC）**：用与测试分布相似但无标注的样本估计先验，比 CC 更准确；\item  **Self-Consistency**：多次采样时不同随机性自然分散偏见；\item  **明确的任务描述**：在任务描述中强调"请根据输入内容判断，不要偏向任何特定标签"。

</details>

**19. 输入输出的分隔符设计对 ICL 效果有影响吗？有哪些最佳实践？**

<details>
<summary>💡 查看答案</summary>

有明显影响，清晰的分隔符帮助模型准确解析 prompt 结构。最佳实践：\begin{enumerate}
- **明确分隔符**：使用清晰的标签（`Input:` / `Output:`，`Question:` / `Answer:`，`###`）而不是纯空格分隔；\item  **一致性**：所有示例和 query 使用完全相同的分隔符；\item  **XML/Markdown 标签**：对于复杂 prompt，使用结构化标签（`<input>`/`</input>`）更清晰；\item  **示例间分隔**：不同示例之间用明显分隔（如 `---` 或双换行）；\item  **避免歧义**：分隔符本身不应出现在输入内容中（否则模型可能误解结构）；\item  实验表明，换用不同风格的分隔符（`Q:` vs `Question:`），准确率可能差 2–5%。

</details>

**20. 示例的长度对 ICL 有什么影响？过长的示例有什么风险？**

<details>
<summary>💡 查看答案</summary>

**示例过短**：不提供足够的上下文，模型可能无法准确理解任务的复杂性和期望输出的详细程度。**示例过长**：\begin{enumerate}
- 占用过多上下文窗口，减少可用的示例数量；\item  关键信息被稀释，模型注意力分散；\item  生成速度变慢，成本增加；\item  模型可能过拟合到示例的特定格式而非任务本身。**经验值**：对于分类任务，示例长度通常 50–200 token 足够；生成任务的示例可以更长（200–500 token），但尽量控制总示例 token 数在 1000–2000 以内；\item  如果单个示例很长，考虑减少示例数量，保证关键示例的完整性。

</details>

**21. 什么是"对齐噪声"（calibration）问题？如何用 PMI 等方式缓解？**

<details>
<summary>💡 查看答案</summary>

对齐噪声（Calibration 问题）：LLM 对不同标签有内置的先验偏好（如倾向输出"正面"而不是"负面"），这个偏好在 ICL 中叠加到学习效果上，导致预测偏差。PMI（Pointwise Mutual Information）缓解方法：\begin{enumerate}
- 用无意义输入（如 "N/A"）测量模型输出各标签的先验概率 P(label | null)；\item  实际预测时计算 `P(label | input) / P(label | null)`（PMI 归一化）；\item  这样消除了先验偏差，只保留与输入相关的判断。其他方法：Contextual Calibration（CC）、Batch Calibration（BC）、Domain-Calibration。实践意义：在标签有明显先验偏差的任务（如情感分析）上，校准可提升 3–8%。

</details>

**22. 如何设计 ICL 中的输出格式（结构化 vs. 自由文本）？**

<details>
<summary>💡 查看答案</summary>

选择原则：\begin{enumerate}
- **下游是否需要解析**：如果答案需要被程序处理（提取字段、数值），必须用结构化格式（JSON/YAML/固定模板）；\item  **任务复杂度**：简单分类用单词/短语输出；解释性任务用自由文本；需要中间步骤的用 CoT 结构；\item  **结构化输出设计**：在示例中展示完整的 JSON 模板，包括所有字段；在任务描述中说明"只输出 JSON，不要任何解释"；\item  **自由文本输出**：适合摘要、翻译、创意写作，但需要在示例中展示期望的详细程度和语气；\item  **混合格式**：先输出推理过程（自由文本），再输出结构化结论（如 CoT + 最终答案标签）；\item  统一格式：query 和所有示例必须使用完全相同的输出格式。

</details>

**23. 将 query 放在示例之前 vs. 之后，哪种方式更好？**

<details>
<summary>💡 查看答案</summary>

通常**将 query 放在示例之后**效果更好。原因：\begin{enumerate}
- **近因效应**：query 放最后，模型在回答时对其关注度最高；\item  **示例引导**：先看示例后看 query，模型按示例格式回答的一致性更高；\item  **少数情况相反**：当 query 非常长或复杂时，先展示 query 让模型"带着问题"看示例，有时帮助更好理解任务；\item  **标准位置**：绝大多数 few-shot prompt 设计都将 query 放在示例末尾，这也是预训练数据中更常见的格式。结论：默认将 query 放在所有示例之后，必要时根据任务特点实验调整。

</details>

**24. 如何测试 ICL prompt 对示例顺序变化的鲁棒性？**

<details>
<summary>💡 查看答案</summary>

1. **随机顺序测试**：对同一组示例生成多个随机排列（如 20 种不同顺序），分别运行，统计准确率的均值和方差；\item  **最大/最小差异**：找出最优和最差顺序，分析导致差异的示例特征；\item  **近因效应测试**：保持示例集不变，只改变最后一个示例（换入不同类别），观察对预测的影响程度；\item  **鲁棒性评分**：方差越小 = 对顺序越鲁棒；\item  **改进策略**：如果方差大，使用 Self-Consistency（多顺序采样 + 投票）提升鲁棒性；\item  **目标**：在 20 种顺序下，准确率方差 <3% 认为鲁棒性可接受；方差 >5% 需要重新设计示例或使用 Self-Consistency。

</details>
