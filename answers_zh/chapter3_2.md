**1. 大模型训练需要设置温度系数吗？**

<details>
<summary>💡 查看答案</summary>

在大模型的训练阶段，温度系数（Temperature）通常固定为 $T = 1$，即不对 logits 进行任何缩放，等价于不设置温度系数。而温度系数的核心作用体现在**推理阶段**的采样控制中。以下从原理、训练与推理两个阶段分别展开说明。

#### 温度系数的数学定义

在语言模型中，给定第 $t$ 步的 logits 向量 $\mathbf{z} \in \mathbb{R}^{|V|}$（$|V|$ 为词表大小），带温度系数的 softmax 定义为：


$$
	P(w_i \mid \mathbf{z}, T) = \frac{\exp(z_i / T)}{\sum_{j=1}^{|V|} \exp(z_j / T)}
$$


其中 $T > 0$ 为温度系数。其行为特性如下：
- 当 $T = 1$ 时，退化为标准 softmax，概率分布不受额外干预；
- 当 $T \to 0^+$ 时，分布趋向于 one-hot，模型趋于**贪心解码**（greedy decoding）；
- 当 $T \to +\infty$ 时，分布趋向于均匀分布，输出**随机性增大**。

#### 训练阶段：温度系数固定为 1

在标准的自回归语言模型训练中，损失函数为交叉熵损失：


$$
	\mathcal{L} = -\sum_{t=1}^{T} \log P(w_t \mid w_{<t})
$$


此时 softmax 取 $T = 1$，原因如下：

1. **梯度的一致性**：若训练时引入 $T \neq 1$，相当于对所有 logits 做了等比缩放，模型可以通过调整权重幅度来"抵消"温度的影响，温度本身并不提供额外的学习信号。
2. **训练目标的纯粹性**：训练的目标是让模型学习真实数据分布 $P_{data}$，使用 $T=1$ 的标准 softmax 可以保证损失函数直接衡量模型分布与真实分布之间的 KL 散度，不引入额外偏置。
3. **知识蒸馏中的例外**：在**知识蒸馏**（Knowledge Distillation）场景下，温度系数会在训练中被显式使用。教师模型和学生模型的 softmax 均使用同一较高温度 $T > 1$，使软标签（soft labels）携带更丰富的类间相似度信息：

    $$
    \mathcal{L}_{KD} = T^2 \cdot KL\!\left(P^{(T)}_{teacher} \,\|\, P^{(T)}_{student}\right)
    $$

    但这属于特殊训练范式，并非标准预训练或微调流程。

#### 推理阶段：温度系数用于采样控制

推理阶段的解码策略直接影响生成文本的质量与多样性，温度系数在此发挥关键作用：

- **贪心解码**（$T \to 0$）：每步选取概率最高的 token，生成结果确定但可能陷入重复；
- **温度采样**（$0 < T < 1$）：压缩分布，提高高概率 token 的相对权重，生成更保守、流畅；
- **高温采样**（$T > 1$）：拉平分布，增加低概率 token 被选中的机会，生成更具多样性与创造性，但可能引入噪声；
- **与 Top-$k$ / Top-$p$ 结合**：实际工程中，温度采样常与 Top-$k$ 采样或 Nucleus（Top-$p$）采样联合使用，以在多样性与连贯性之间取得平衡。

典型推理调用示例（以 OpenAI API 风格为例）：

\begin{lstlisting}[style=promptstyle]
	{
		"model": "gpt-4",
		"messages": [{"role": "user", "content": "请写一首关于秋天的诗"}],
		"temperature": 0.8,
		"top_p": 0.95,
		"max_tokens": 256
	}
\end{lstlisting}

#### 小结

\begin{table}[h]



| **阶段** | **温度系数取值** | **作用** |
| --- | --- | --- |
| 预训练 / 微调 | $T = 1$（固定） | 不干预，保证损失函数语义正确 |
| 知识蒸馏 | $T > 1$（显式设置） | 软化标签，传递类间关系信息 |
| 推理采样 | $T \in (0, +\infty)$（可调） | 控制生成多样性与确定性的平衡 |


	\caption{温度系数在不同阶段的使用情况}
\end{table}

综上，**训练阶段无需设置温度系数**（默认 $T=1$），温度系数是推理阶段的解码超参数，用于在生成质量与多样性之间进行权衡调节。

</details>

**2. LLM 预训练阶段有哪几个关键步骤？**

<details>
<summary>💡 查看答案</summary>

LLM预训练大致包括以下关键步骤：

1. **数据收集与清洗**：从网页（如Common Crawl）、书籍、代码库、百科、论坛问答等多种来源收集海量原始文本，并进行去重、过滤低质量内容、去除有害/隐私信息等清洗工作（参考第463、464题）。

2. **数据混合与配比设计**：将不同来源/领域的数据按一定比例混合，构建最终的预训练数据集（参考第466题）。

3. **Tokenizer训练/选择**：基于（或参考）预训练语料训练分词器（如BPE/SentencePiece），确定词表大小和覆盖范围（参考第477题）。

4. **模型架构设计**：确定模型结构（层数、隐藏维度、注意力头数、位置编码方式、激活函数等）和参数规模。

5. **训练基础设施搭建**：搭建分布式训练环境（数据并行/张量并行/流水线并行/ZeRO等并行策略，参考第十三章），配置混合精度训练等。

6. **超参数设定**：学习率（及调度策略，如warmup+cosine decay）、batch size、优化器（如AdamW的beta、weight decay）、梯度裁剪等。

7. **大规模训练执行**：以语言建模损失（CLM或MLM，参考第460、461题）为目标，在数据上进行长时间的分布式训练，期间持续监控loss、梯度范数、吞吐量等指标，处理训练过程中的稳定性问题（如loss spike）。

8. **Checkpoint管理与评估**：定期保存checkpoint，在中间阶段用评测基准（如MMLU等）评估模型能力的发展趋势，必要时调整数据配比/超参数。

9. **退火/学习率衰减阶段（可选）**：训练末期常进行学习率退火，有时会结合高质量数据的"退火数据集"进一步提升模型在退火阶段的表现。

**总结**：预训练流程整体是"**数据准备（收集、清洗、配比）→ Tokenizer与架构设计 → 分布式基础设施和超参数配置 → 大规模训练（含持续监控与稳定性处理）→ Checkpoint评估与必要的迭代调整**"的端到端工程流程，数据相关的工作往往占据了整个流程中工作量和重要性的核心地位。

![大语言模型预训练的完整生命周期与关键步骤流程图](https://img.pricenode.uk/llm_interview_questions/zhongw/chapter3/fig_pretrain_pipeline.png)

</details>

**3. 大模型预训练的核心目标是什么？**

<details>
<summary>💡 查看答案</summary>

大模型预训练的核心目标是：**通过在海量、多样化的文本（及其他模态）数据上进行自监督学习（最常见的是"预测下一个token"），让模型学习到语言的统计规律、语法结构、语义关系，以及隐含在文本中的世界知识、常识和推理模式，从而获得一个具有广泛通用能力的"基座模型"，为后续的微调和对齐提供良好的起点**。

具体而言，核心目标可以从几个层面理解：

1. **学习语言本身的规律**：词汇、语法、句法结构、上下文依赖关系等——这是语言模型最基础的能力。

2. **学习世界知识**：通过海量文本中包含的事实性陈述、百科知识、常识等，模型在参数中"压缩存储"了大量关于世界的信息（参考第481题"Next Token Prediction为什么能学到世界知识"）。

3. **学习推理与模式识别能力**：文本中包含大量的逻辑推理、因果关系、数学计算等模式，模型通过预测这些模式，逐渐发展出一定的推理能力。

4. **形成可迁移的通用表征**：预训练得到的模型参数（尤其是中间层的表征）对各种下游任务都具有良好的初始化作用，大幅降低下游任务所需的标注数据量和训练成本（这是"预训练-微调"范式相比"从头训练每个任务模型"的核心优势）。

5. **隐含的"压缩"视角**：从信息论角度，"预测下一个token"这一目标，本质上是在学习数据的概率分布，一个能够更好地预测数据的模型，相当于对数据进行了更好的"压缩"——而"压缩能力"与"智能/理解能力"之间存在深刻的理论联系（更好的压缩需要更深刻的对数据生成过程的"理解"）。

**总结**：核心目标是**通过自监督的语言建模任务，从海量数据中学习语言规律、世界知识和推理模式，形成具有强大通用能力和良好可迁移性的基座模型**，为后续针对具体任务/场景的微调和对齐提供基础。

</details>

**4. 大模型预训练的损失函数是什么**

<details>
<summary>💡 查看答案</summary>

大模型预训练通常采用**自回归语言模型**的训练目标，核心损失函数为**交叉熵损失（Cross-Entropy Loss）**，具体形式为对序列中每个 token 的负对数似然求平均：


$$
	\mathcal{L} = -\frac{1}{T} \sum_{t=1}^{T} \log P(x_t \mid x_1, x_2, \ldots, x_{t-1}; \theta)
$$


其中：
- $T$ 为序列长度；
- $x_t$ 为第 $t$ 个 token；
- $\theta$ 为模型参数；
- $P(x_t \mid x_1, \ldots, x_{t-1}; \theta)$ 为模型在给定前缀条件下预测第 $t$ 个 token 的概率（由 softmax 输出层给出）。

**直觉理解：**该损失函数要求模型在看到前文 $x_1, \ldots, x_{t-1}$ 的情况下，尽可能提高对真实下一个 token $x_t$ 的预测概率，等价于最小化模型分布与数据真实分布之间的 KL 散度，也等价于最大化训练语料的对数似然（MLE）。

**与困惑度（Perplexity）的关系：**


$$
	PPL = e^{\mathcal{L}}
$$


困惑度常作为语言模型的评估指标，与训练损失直接对应。

</details>

**5. 为什么 BERT 里的 NSP 下一句预测任务后来被弃用？**

<details>
<summary>💡 查看答案</summary>

**NSP（Next Sentence Prediction）任务**：BERT预训练中除了MLM（掩码语言建模），还设计了NSP任务——给定两个句子A和B，判断B是否是A在原文中的下一句（二分类：是/不是，负例通常是从语料中随机抽取的句子）。

**NSP被后续工作（如RoBERTa）弃用的主要原因**：

1. **任务难度过低/信号质量不高**：
- NSP的负例是"从语料中随机抽取的句子"，这类负例与正例（真实的下一句）之间往往存在**非常明显的主题/话题差异**——模型很容易仅通过"两个句子是否讨论同一话题"这一**浅层的主题一致性特征**就能正确判断NSP任务，而不需要深入理解句子之间更细粒度的**连贯性/逻辑关系**（如指代关系、因果关系等）；
- 换言之，NSP任务实际上**混合了"主题预测"和"连贯性预测"两个不同难度的子任务**，而模型主要依赖的是更容易学习的"主题预测"信号，导致NSP任务对模型学习"句子间细粒度关系"的帮助有限。

2. **RoBERTa等工作的实验发现**：
- RoBERTa论文通过对比实验发现，**去除NSP任务（只保留MLM），模型在下游任务上的表现反而与保留NSP相当甚至更好**；
- 进一步地，RoBERTa尝试了"FULL-SENTENCES"（输入由连续的多个句子拼接而成，可以跨文档边界）和"DOC-SENTENCES"（输入来自单一文档的连续句子）等不同的输入构造方式，发现**即使不使用NSP损失，仅通过MLM在"更长的连续文本片段"上训练，效果就已经足够好甚至更优**；

3. **训练效率的考量**：
- NSP任务要求训练样本必须是"成对的句子"，这对数据的组织方式提出了额外的约束（需要构造正负样本对），相比直接将长文本切分成连续片段进行MLM训练，**数据处理流程更复杂**，且NSP本身贡献的有效信号有限，性价比不高。

4. **后续改进任务的提出**：
- 一些后续工作（如ALBERT）提出了**SOP（Sentence Order Prediction，句子顺序预测）**任务作为NSP的改进——SOP的负例是"将两个连续句子的顺序交换"（而不是"随机抽取不相关的句子"），这样负例与正例之间的**主题是一致的，差异仅在于顺序/连贯性**，从而**更聚焦于"连贯性"这一更有价值的信号**，避免了NSP中"主题差异"这一"容易的捷径"。这也从另一个角度印证了NSP任务设计本身的缺陷——其负例构造方式使得任务"过于容易"，未能有效驱动模型学习更深层次的句间关系。

**总结**：NSP被弃用的核心原因是**其负例构造方式（随机抽取不相关句子）使得任务可以通过"浅层的主题一致性判断"轻松解决，未能有效驱动模型学习句子间更深层的连贯性/逻辑关系，对预训练效果的实际贡献有限**；RoBERTa等工作的实验证明去除NSP、仅用MLM（配合更长的连续文本输入）效果相当或更好，因此后续模型普遍弃用了NSP，部分工作（如ALBERT的SOP）尝试改进任务设计以保留"句间关系建模"这一目标但避免NSP的缺陷。

![NSP 与 SOP 预训练任务中正负样本构造难度对比图](https://img.pricenode.uk/llm_interview_questions/zhongw/chapter3/fig_nsp_vs_sop.png)

</details>

**6. 因果语言建模（CLM）的训练目标是什么？**

<details>
<summary>💡 查看答案</summary>

**CLM（Causal Language Modeling，因果语言建模）**，也称为自回归语言建模（Autoregressive LM），是当前主流大模型（如GPT系列、LLaMA系列）采用的预训练目标。

**训练目标**：

给定一个token序列 $x_1, x_2, ..., x_T$，CLM的目标是最大化整个序列的（条件）联合概率，通过链式法则分解为：

$P(x_1,...,x_T) = \Pi_{t=1}^{T} P(x_t | x_1,...,x_{t-1})$

即模型需要根据**前面所有已出现的token（历史上下文）**，预测**下一个token**的概率分布。训练损失为负对数似然（NLL，即交叉熵损失）：

$L_{CLM} = -\Sigma_{t=1}^{T} \log P_\theta(x_t | x_1,...,x_{t-1})$

**关键特性**：

1. **单向（从左到右）的上下文依赖**：在预测第t个位置的token时，模型**只能"看到"位置1到t-1的信息，不能看到位置t及之后的内容**——这通过在自注意力（Self-Attention）计算中应用**因果掩码（Causal Mask / 下三角掩码）**来实现，确保每个位置的注意力计算只能关注到它自己以及之前的位置。

2. **天然适配生成任务**：由于训练目标本身就是"根据已有内容预测下一个token"，模型在推理时可以**自然地、逐token地自回归生成新内容**——训练目标与推理使用方式（生成）高度一致，这是CLM相比MLM（推理时需要特殊处理才能用于生成）的一个重要优势。

3. **单个序列内可以并行计算所有位置的损失**：尽管自回归生成是逐token顺序进行的，但在**训练阶段**，由于整个序列是已知的，可以通过因果掩码，**一次前向传播同时计算序列中所有位置的预测损失**（每个位置t的损失只依赖于1到t-1的信息，这些信息在训练时都是已知的），因此训练本身是高度并行化的。

**总结**：CLM的训练目标是**给定上文，最大化预测下一个token的概率（即最小化负对数似然/交叉熵损失）**，通过因果掩码确保每个位置只能利用其左侧的上下文信息，这种"单向、自回归"的建模方式与生成任务的使用方式天然一致，是当前主流大模型预训练的标准目标。

</details>

**7. 掩码语言建模（MLM）的训练目标是什么？**

<details>
<summary>💡 查看答案</summary>

**MLM（Masked Language Modeling，掩码语言建模）**，是BERT等模型采用的预训练目标，与CLM的"单向自回归"不同，MLM是一种**双向（bidirectional）**的预训练目标。

**训练目标**：

给定一个token序列，**随机选择其中一部分位置（如15%）进行"掩码"**（用特殊的[MASK]标记替换原始token，或替换为随机token，或保持不变——BERT中具体是80%替换为[MASK]、10%替换为随机token、10%保持原token），模型的目标是**根据被掩码位置的双向上下文（即该位置左侧和右侧的所有未被掩码的token），预测被掩码位置原本的token**。

训练损失只在**被掩码的位置**上计算：

$L_{MLM} = -\Sigma_{i \in masked positions} \log P_\theta(x_i | x_{masked})$

其中 $x_{masked}$ 表示除了被掩码位置之外的所有token（包括被掩码位置左侧和右侧的上下文）。

**关键特性**：

1. **双向上下文建模**：与CLM的因果掩码（只能看左侧）不同，MLM的自注意力**不需要因果掩码**——每个位置（包括被掩码的位置）的表示可以充分利用其**左右两侧**的所有上下文信息，这使得MLM学到的表征在需要"理解整个句子上下文"的任务（如分类、NER、句子相似度判断）上通常具有优势。

2. **预训练-推理之间的不一致（Train-Test Discrepancy）**：MLM训练时输入中包含[MASK]标记，但在**实际推理/微调使用时，输入中通常不包含[MASK]**（除非任务本身就是"填空"），这种"训练时见过[MASK]，推理时没有[MASK]"的不一致，是MLM的一个理论上的局限（BERT通过80/10/10的策略部分缓解，但不能完全消除）。

3. **不直接适配自回归生成**：由于MLM训练的是"根据双向上下文预测某个位置"，而**不是"根据左侧上下文预测下一个token"**，MLM预训练得到的模型**不能像CLM模型一样直接、自然地用于自回归文本生成**（虽然存在一些将MLM模型用于生成的特殊方法，但都不如CLM模型天然）。

4. **每个序列中只有被掩码的部分（如15%）参与损失计算**，相比CLM中序列的几乎所有位置（除第一个token外）都参与损失计算，**MLM对每个训练样本的"信息利用率"相对较低**（需要更多的训练样本/步数才能达到与CLM相当的"有效监督信号"总量）。

**总结**：MLM的训练目标是**随机掩盖输入序列中的部分token，根据双向上下文预测这些被掩盖的原始token**，通过去除因果掩码实现双向上下文建模，更适合需要"整体理解"的判别式任务（分类、NER等）；但存在"训练-推理输入不一致"以及"不直接适配自回归生成"等局限，这也是当前主流的大规模生成式LLM普遍采用CLM而非MLM作为预训练目标的重要原因。

</details>

**8. Scaling Law 在什么条件下会失效？有反例吗？**

<details>
<summary>💡 查看答案</summary>

**Scaling Law的基本内容**：

Scaling Law描述的是模型性能（通常以测试损失/困惑度衡量）与模型参数量N、训练数据量D、计算量C之间存在的**幂律（power-law）关系**——在一定范围内，增加N、D、C，模型损失会按照某种幂律规律持续下降，且这种关系在相当大的范围内表现出**良好的可预测性（可以根据小规模实验外推到大规模）**。

**Scaling Law可能失效/不再适用的条件**：

**1. 数据质量/数据量的瓶颈**

- Scaling Law的"数据维度"假设增加的数据具有一定的"信息增量"；如果**可用的高质量数据已经接近"耗尽"**（即继续增加"数据量D"，主要是通过增加重复次数/降低质量门槛来实现，而非真正"新的、有信息量"的数据），那么"数据量增加"对性能的提升会**明显偏离原有的幂律曲线，提升速度大幅放缓甚至饱和**——这是当前许多讨论"数据墙（data wall）"问题的核心，被认为是Scaling Law在"数据维度"上可能遇到的现实瓶颈。

**2. 评测指标的"饱和"**

- Scaling Law通常基于**预训练损失（loss）/困惑度**这类连续、平滑的指标来观察；但对于**下游任务的离散指标（如准确率）**，当模型在某个任务上的准确率已经接近100%（"饱和"）时，即使预训练loss继续按幂律下降，该下游任务的准确率也**无法继续提升（已经触及上限）**——即"loss的幂律下降"与"特定下游任务指标的提升"之间的对应关系，在**接近饱和区域**会失效。

**3. "涌现能力"的非连续性（争议中的反例）**

- 一些研究（如"Emergent Abilities of Large Language Models"）报告了某些能力（如多步算术、某些特定的few-shot任务）在模型规模**跨越某个阈值之前几乎为0（接近随机水平），跨越阈值之后突然显著提升**的现象——这种"涌现（emergence）"看起来像是**对"性能随规模平滑提升"这一Scaling Law直觉的偏离**（性能曲线呈现"阶跃"而非"平滑幂律"）；
- 但也有后续研究（如"Are Emergent Abilities of Large Language Models a Mirage?"）指出，**这种"涌现"现象很大程度上是评测指标选择的"假象"**——如果使用连续的指标（如对数似然/某种"部分正确"的度量）而非离散的（如"完全正确才算对"的准确率），底层的性能提升实际上**仍然是平滑、符合幂律的**，"涌现"只是离散指标在"平滑提升跨越某个判定阈值"时呈现出的视觉效果。这一点本身也是学术界存在争议、尚未完全达成一致的话题。

**4. 不同"配方"（架构、数据配比、训练方法）下Scaling Law的"系数"不同**

- Chinchilla等研究指出，Scaling Law中的具体"系数"（如最优的N/D比例）**依赖于具体的训练配方**——更换不同的架构、数据分布、优化器设置，幂律关系本身可能仍然成立，但**具体的曲线参数（如最优配比）会发生变化**；因此，"在某个特定配方下拟合出的Scaling Law"，**不能简单地、不加区分地推广到完全不同的配方**，这也是一种"失效"的体现（并非"幂律关系本身错误"，而是"具体参数的外推范围有限"）。

**5. 后训练（RL等）阶段的Scaling规律可能不同**

- Scaling Law最初主要是针对**预训练阶段**的损失/计算量关系建立的；对于**RL训练阶段**，"计算量投入"与"模型能力提升"之间的关系是否遵循类似的幂律形式，是一个相对较新且仍在探索的问题——已有一些工作开始研究RL阶段的"scaling"规律，但其形式、稳定性是否与预训练Scaling Law一致，尚无定论。

**总结**：Scaling Law可能在"**高质量数据接近耗尽（数据墙）、下游离散指标接近饱和上限、不同训练配方之间的外推、以及RL等后训练阶段是否遵循类似规律**"等条件下表现出"失效"或"不再直接适用"；所谓"涌现能力"是否构成对Scaling Law的"反例"，目前学术界存在争议（部分研究认为这更多是评测指标离散化导致的"假象"，底层规律仍是平滑的）——总体而言，Scaling Law在"模型规模、数据规模、计算量都在某个'合理范围'内，且训练配方相对固定"的条件下表现出较好的预测能力，但在这些条件被打破时（数据瓶颈、指标饱和、配方剧变、新的训练范式如大规模RL），其适用性需要重新审视。

</details>

**9. 如果预算固定，应该训更大模型还是用更多数据？Chinchilla vs LLaMA 给出了什么不同答案？**

<details>
<summary>💡 查看答案</summary>

**Chinchilla的结论**：

DeepMind的Chinchilla论文（"Training Compute-Optimal Large Language Models"）系统研究了"在固定计算预算（FLOPs）下，模型参数量N和训练数据量（token数）D应该如何分配，才能使最终的预训练损失最小"这一问题。其核心结论是：

- 在此之前（如GPT-3等模型），业界普遍倾向于"**优先增大模型参数量，数据量相对不足**"——模型规模增长很快，但训练数据的token数增长相对缓慢，导致很多大模型实际上是"**训练不足（under-trained）**"的，即在给定的参数规模下，如果用更多的数据训练，损失还能进一步下降；
- Chinchilla通过大量实验拟合出"计算最优"的N和D的缩放关系，发现**N和D应该大致按"相同的比例"随计算量C增长**（即"参数量每增大一倍，训练数据量（token数）也应该增大一倍"，两者的增长速度大致相当）；
- 基于这一结论，Chinchilla模型（700亿参数，但用了远超此前同等规模模型的训练token数）在相同的训练计算量下，**性能显著优于参数量更大但训练数据相对不足的Gopher（2800亿参数）**——即"用同样的计算预算，训练一个'更小但用更多数据训练得更充分'的模型，效果优于'更大但训练不足'的模型"。

**LLaMA的实践**：

LLaMA系列论文的一个重要观察/论点是：**Chinchilla的"计算最优"分析，关注的是"在给定计算预算下，达到最低预训练损失"这一目标，但实际应用中，模型的"推理成本"同样是一个需要考虑的重要因素**：

- 一个"按Chinchilla最优比例"训练的较大模型，可能在"训练计算量"上是最优的，但其**推理成本（参数量决定的推理延迟、显存占用）也相应更高**；
- LLaMA的策略是：**选择相对较小的模型规模（如7B、13B等，参数量小于"严格按Chinchilla最优比例对应该计算量"所建议的规模），但用远超"Chinchilla最优比例"所建议的、数量更多的训练数据（更多的token数）来训练**——即"**在'训练计算最优'的意义上，这种配置可能不是N/D比例最优的，但LLaMA团队认为，对于一个'将被广泛部署、需要在各种硬件上进行大量推理'的模型，用'更小的参数量+更长的训练（更多数据/更多token）'，能在'最终能力水平相近或更优'的同时，显著降低部署后的推理成本，这是更具实际价值的权衡**"；
- 实验结果显示，LLaMA-13B在多项基准测试上的表现可以与（参数量大得多的）GPT-3-175B相当甚至更优，这表明"**继续增加训练数据（即使超出'Chinchilla最优'对应的D/N比例），对于较小模型而言，仍然能持续带来能力的提升**"。

**两者给出的不同"答案"——本质是优化目标的不同**：

- **Chinchilla的视角**：在"固定的训练计算预算"下，求"预训练损失最小"的N、D最优分配——给出了一个关于N和D"按比例同步增长"的缩放关系；
- **LLaMA的视角**：考虑到**"训练成本"和"推理成本"的综合权衡**，认为对于"会被大量部署使用"的模型，**适度"牺牲"训练阶段的"计算最优性"（即不严格按照Chinchilla比例增大模型规模，而是保持较小的参数量并投入更多的数据/训练时间），可以换来"推理成本"的显著降低，而模型能力（在实践范围内）仍可以通过"更多数据训练较小模型"来达到很高的水平**；
- 两者并不是"互相矛盾"的关系，而是**在"是否将推理成本纳入优化目标"这一前提下，对"训练计算预算如何分配"给出了不同的实践建议**——Chinchilla关注"训练效率"，LLaMA关注"训练效率+推理效率的综合最优"。

**总结**：固定预算下"训更大模型 vs 用更多数据"的问题上，**Chinchilla给出的答案是"按一定比例同步增大模型和数据规模，以最小化训练计算量下的预训练损失"（纠正了此前"模型增长过快、数据相对不足"的失衡）；而LLaMA的实践则在Chinchilla结论的基础上，进一步考虑了"推理成本"这一额外维度，倾向于"保持相对较小的模型规模，但投入远超Chinchilla比例所建议的训练数据量"，以在"能力水平相近"的前提下大幅降低部署后的推理成本**——两者的差异本质上反映了"仅优化训练阶段的计算效率"和"综合考虑训练与部署/推理的整体成本"这两种不同优化目标下的不同最优策略。

</details>

**15. 预训练语料的领域配比如何影响模型的下游能力？**

<details>
<summary>💡 查看答案</summary>

从数据分布角度分析：

预训练语料的领域配比直接决定了模型的"知识结构"，不同领域数据的比例会深刻影响模型在下游任务中的表现。

#### 配比的核心影响机制
语言模型本质上是在拟合训练数据的分布。若某领域数据占比高，模型对该领域的语言模式、知识结构、推理方式的建模能力就更强。反之，占比极低的领域在模型中几乎处于"欠拟合"状态。

#### 典型领域及其作用
- **网页文本（如 Common Crawl）**：覆盖面广，有助于通用语言能力，但噪声大、质量参差不齐。
- **书籍（Books）**：长文本、逻辑连贯，有助于长程依赖建模和叙事推理能力。
- **代码（Code）**：显著提升模型的逻辑推理、结构化输出和数学能力，即使是非代码任务也有正迁移效应（如 Chain-of-Thought 能力）。
- **学术论文（如 ArXiv）**：提升科学推理和专业知识密度。
- **对话数据**：增强模型的指令跟随和交互能力。

#### 配比失衡的后果
- 代码数据过少：模型在编程任务和逻辑推理上表现明显弱于同量级模型。
- 低质量网页数据过多：模型容易产生重复、冗余、偏见性输出。
- 单一领域过度集中：下游泛化能力下降，出现领域过拟合。

#### 实践中的配比策略
实践中通常不是按原始爬取比例混合，而是经过人工上采样（upsampling）高质量数据源。例如 GPT-3 对 Books 和 Wikipedia 进行了大幅上采样；LLaMA 则引入了大量代码数据以提升推理能力。最优配比往往需要通过小规模消融实验（ablation study）来确定，目前尚无统一的理论指导。

</details>

**16. 为什么大模型通过训练很少的 epoch？**

<details>
<summary>💡 查看答案</summary>

从数据规模与过拟合角度分析：

#### 核心原因：数据量远大于模型所需
大模型预训练使用的数据集规模通常达到万亿（Trillion）token 级别，而模型参数量即便达到千亿级别，相对于数据量而言仍然"吃不完"。在这种情况下，只需训练 1 个 epoch 甚至不到 1 个 epoch，模型就已经见过了海量多样的样本，继续重复训练的边际收益极低。

#### Chinchilla 定律的指导
Hoffmann 等人提出的 Chinchilla Scaling Law 指出，在计算预算固定的情况下，最优策略是让模型参数量和训练 token 数保持大致 1:20 的比例。这意味着对于一个 70B 的模型，最优训练量约为 1.4T token，而非反复在同一数据上多次训练。

#### 重复训练带来的危害
- **过拟合**：模型开始记忆训练数据中的具体样本，泛化能力下降。
- **数据记忆与隐私风险**：多次重复训练会使模型更容易逐字背诵训练文本，引发隐私泄露风险。
- **多样性降低**：模型输出趋向于训练集中的高频模式，创造性和多样性下降。

#### 与小模型的对比
传统小模型（如 BERT）由于数据量有限，通常需要训练多个 epoch。而大模型的数据规模本身就构成了天然的正则化，无需依赖多 epoch 迭代来充分学习。

</details>

**17. 预训练模型的参数初始化策略有哪些？随机初始化的方差设置有何讲究？**

<details>
<summary>💡 查看答案</summary>

从数值稳定性角度分析：

#### 常见初始化策略
- **Xavier 初始化（Glorot）**：将权重方差设为 $\frac{2}{n_{in} + n_{out}}$，适用于 sigmoid/tanh 激活函数，目标是保持前向传播和反向传播时激活值的方差一致。
- **He 初始化（Kaiming）**：将权重方差设为 $\frac{2}{n_{in}}$，专为 ReLU 类激活函数设计，考虑到 ReLU 将负半轴置零导致方差减半的问题。
- **小方差正态分布初始化**：在 GPT 系列中常见，使用均值为 0、标准差为 0.02 的正态分布初始化所有线性层权重。
- **残差缩放初始化**：对残差连接中的输出投影层（如 Attention 的 $W_O$ 和 FFN 的第二层）进行额外缩小，标准差缩放为 $\frac{0.02}{\sqrt{2L}}$，其中 $L$ 为层数，防止深层网络中残差累积导致方差爆炸。

#### 方差设置的核心讲究
- **防止梯度消失/爆炸**：初始化方差过大，前向传播中激活值会指数增长；过小则信号逐层衰减，梯度无法有效传播。
- **与网络深度相关**：模型越深，残差路径上的方差累积越严重，需要对特定层进行额外的方差压缩。
- **Embedding 层的特殊处理**：词嵌入层通常使用较小的标准差（如 0.02）初始化，避免初始 logits 方差过大导致 softmax 饱和。

</details>

**18. 词表大小的选择对模型训练和推理有什么影响？**

<details>
<summary>💡 查看答案</summary>

从计算效率与表达能力角度分析：

#### 词表大小的基本权衡
词表大小（Vocabulary Size）是 tokenizer 设计的核心超参数，直接影响模型的输入表示、计算开销和语言表达能力。

#### 词表过小的问题
- 同一个词被拆分成更多 token，导致序列长度增加，attention 计算开销增大。
- 对于低频词、专业术语、多语言字符，tokenization 粒度过细，模型难以学习完整的语义单元。
- 上下文窗口被低效占用，有效信息密度下降。

#### 词表过大的问题
- Embedding 矩阵和 LM Head（输出投影层）参数量随词表线性增长，占用大量显存。
- 稀有 token 在训练中出现频率极低，对应的 embedding 向量训练不充分，质量差。
- Softmax 计算开销增大（尽管可用并行 softmax 缓解）。

#### 主流模型的选择
当前主流大模型词表大小通常在 32k 到 128k 之间：GPT-3 使用约 50k，LLaMA 2 使用 32k，LLaMA 3 扩展至 128k 以增强多语言和代码能力。词表扩大配合更高效的 tokenizer（如 tiktoken）可以在不显著增加推理开销的前提下提升表达能力。

</details>

**19. 预训练阶段的 Dropout 通常设为 0，这是为什么？**

<details>
<summary>💡 查看答案</summary>

从数据规模与正则化需求角度分析：

#### Dropout 的本质作用
Dropout 是一种正则化手段，通过在训练时随机丢弃神经元，防止模型对训练数据过拟合。其核心假设是：训练数据相对于模型容量较为有限，模型有过拟合风险。

#### 大模型预训练中为何不需要 Dropout
- **数据量极大**：预训练数据达到万亿 token 级别，模型几乎不可能在如此海量的数据上过拟合，天然具备正则化效果。
- **训练 epoch 极少**：通常只训练不到 1 个 epoch，每个样本只见过一次，过拟合风险极低。
- **Dropout 带来训练不稳定**：在大模型中，Dropout 会引入额外的随机性，干扰梯度估计的准确性，可能导致训练不稳定或收敛变慢。
- **降低训练效率**：Dropout 在训练时需要生成随机 mask，增加计算和内存开销，而其带来的正则化收益在大规模预训练场景下几乎可以忽略。

#### 微调阶段的不同处理
在下游任务微调阶段，由于数据量通常较少，过拟合风险上升，此时会重新引入 Dropout（通常设为 0.1）作为正则化手段。

</details>

**20. 大模型预训练中如何判断模型是否已经充分收敛？有哪些判断标准？**

<details>
<summary>💡 查看答案</summary>

从训练动态监控角度分析：

#### 核心指标：训练 Loss 与验证 Loss
- **训练 Loss 趋于平稳**：当训练 loss 的下降速率接近零，且长时间（如数万步）内无明显下降趋势，可认为模型在当前数据分布下接近收敛。
- **验证 Loss 不再下降**：在留出的验证集上，perplexity 或 cross-entropy loss 不再改善，是收敛的重要信号。
- **训练 Loss 与验证 Loss 的差距**：若两者差距持续扩大，说明出现过拟合；若两者同步平稳，则收敛状态良好。

#### 补充判断标准
- **梯度范数（Gradient Norm）**：收敛时梯度范数应趋于稳定的小值，若持续剧烈波动则说明训练尚不稳定。
- **下游任务评估**：定期在标准 benchmark（如 MMLU、HellaSwag）上评测，若性能不再提升则可认为收敛。
- **学习率调度的终点**：大多数大模型采用 cosine decay 学习率调度，训练到学习率衰减至最小值附近时，通常也意味着训练接近尾声。

#### 实践中的挑战
大模型训练成本极高，不可能无限等待收敛。实践中往往依据 Scaling Law 预先计算最优训练 token 数，在达到该数量后即停止训练，而非等待 loss 完全平台。

</details>

**21. 多语言预训练时，低资源语言和高资源语言之间会产生怎样的相互影响？**

<details>
<summary>💡 查看答案</summary>

从跨语言迁移角度分析：

#### 正向迁移：低资源语言受益于高资源语言
- **跨语言知识共享**：不同语言在语义空间中存在对齐关系，高资源语言（如英语）学到的语法结构、世界知识可以迁移到低资源语言，使后者即使训练数据稀少也能获得较好的理解能力。
- **多语言对齐**：共享的 subword 词表（如 SentencePiece BPE）使不同语言的 token 空间产生部分重叠，促进跨语言表示对齐。
- **零样本跨语言迁移**：在英语上训练的推理能力可以零样本迁移到其他语言，如 mBERT、XLM-R 所展示的。

#### 负向影响：诅咒与竞争
- **多语言诅咒（Curse of Multilinguality）**：固定模型容量下，语言数量增多会导致每种语言分配到的参数表达能力下降，高资源语言性能可能因此下滑。
- **数据不均衡导致欠拟合**：低资源语言数据量过少，即便上采样，模型对其语言特性的建模仍然不充分。
- **词表竞争**：共享词表中高资源语言占据了大量 token 槽位，低资源语言的字符/词素往往被拆分成更多 token，降低了 token 效率。

#### 缓解策略
通过温度采样（temperature sampling）对低资源语言进行上采样，平衡各语言的训练频率；增大模型容量以缓解多语言诅咒；为低资源语言设计专属词表扩展。

</details>

**22. 预训练中使用的 Attention Mask 有哪几种形式？各自适用于什么训练目标？**

<details>
<summary>💡 查看答案</summary>

从注意力机制设计角度分析：

#### 1. Causal Mask（因果掩码 / 自回归掩码）
- **形式**：下三角矩阵，每个 token 只能 attend 到自身及其左侧的 token，未来 token 被遮蔽。
- **适用目标**：自回归语言模型（CLM），如 GPT 系列、LLaMA。训练目标为 Next Token Prediction，天然要求模型不能看到未来信息。

#### 2. Bidirectional Mask（双向掩码 / 无掩码）
- **形式**：全 1 矩阵，所有 token 之间可以相互 attend，无方向限制。
- **适用目标**：掩码语言模型（MLM），如 BERT。模型需要利用上下文双向信息来预测被 mask 的 token，因此不能施加因果约束。

#### 3. Prefix Mask（前缀掩码）
- **形式**：前缀部分（prompt）内部使用双向 attention，生成部分使用 causal attention。
- **适用目标**：PrefixLM 架构（如 T5 的 Decoder、GLM），兼顾编码前缀的双向理解能力和生成部分的自回归特性，适合 seq2seq 和条件生成任务。

#### 4. Padding Mask（填充掩码）
- **形式**：对序列中的 padding token 位置施加掩码，使其不参与 attention 计算。
- **适用目标**：所有训练场景中处理变长序列时的通用辅助 mask，通常与上述三种 mask 叠加使用。

#### 5. Pack Mask（文档内掩码）
- **形式**：在 Pack 训练策略中，同一序列内不同文档的 token 之间相互遮蔽，只允许同一文档内部的 token 互相 attend。
- **适用目标**：将多个短文档拼接训练时，防止跨文档的信息污染，保证每个文档的语义独立性。

</details>

**23. 为什么大模型预训练通常不使用 LSTM 而选择 Transformer 架构？**

<details>
<summary>💡 查看答案</summary>

从计算效率与建模能力角度分析：

#### LSTM 的核心局限
- **序列依赖，无法并行**：LSTM 的隐状态 $h_t$ 依赖于 $h_{t-1}$，训练时必须按时间步串行计算，无法在序列维度上并行，GPU 利用率极低。
- **长程依赖退化**：尽管 LSTM 通过门控机制缓解了梯度消失问题，但在超长序列（数千 token）上，信息仍会逐步被压缩遗忘，难以建模远距离依赖。
- **隐状态信息瓶颈**：所有历史信息被压缩进固定维度的隐状态向量，表达能力有上限。

#### Transformer 的核心优势
- **完全并行训练**：Self-Attention 对序列中所有 token 对的计算相互独立，可在序列维度完全并行，充分利用现代 GPU/TPU 的大规模并行计算能力，训练效率远超 LSTM。
- **直接建模任意距离依赖**：任意两个 token 之间的注意力权重只需一次矩阵运算，不受序列长度限制，长程依赖建模能力从根本上优于 RNN。
- **可扩展性强**：Transformer 在增大模型规模（参数量、层数、宽度）时性能持续提升，符合 Scaling Law，而 LSTM 的扩展性相对有限。
- **工程生态成熟**：围绕 Transformer 的优化工具（Flash Attention、Tensor Parallelism 等）已高度成熟。

</details>

**24. 预训练数据去重的必要性是什么？重复数据会带来哪些具体危害？**

<details>
<summary>💡 查看答案</summary>

从数据质量与模型行为角度分析：

#### 去重的必要性
大规模网络爬取数据中存在大量重复内容，包括：完全重复的页面（exact duplicates）、近似重复的段落（near duplicates）、以及跨文档的段落级重复。若不加处理直接训练，模型会对这些内容进行隐式过度学习。

#### 重复数据的具体危害
- **训练数据记忆（Memorization）**：模型对高频重复内容进行逐字记忆，在推理时可能原文输出训练数据，造成隐私泄露和版权风险。研究表明，数据重复次数与被记忆的概率呈正相关。
- **分布偏移**：重复数据使训练分布偏离真实语言分布，模型对重复出现的文本模式赋予过高概率，导致生成内容出现重复和单调。
- **浪费计算资源**：对相同或相似内容反复训练，既不带来新知识，又占用了宝贵的训练算力和 token 预算。
- **评测数据污染**：若训练集中包含与测试集重叠的内容，模型在 benchmark 上的表现会虚高，无法真实反映泛化能力。

#### 常用去重方法
- **精确去重**：基于 MD5/SHA 哈希对文档或段落进行精确匹配去重。
- **模糊去重**：使用 MinHash + LSH 算法检测近似重复文档，是目前大规模数据去重的主流方法（如 C4、The Pile 等数据集均采用此方法）。
- **n-gram 重叠检测**：计算文档间的 n-gram 重叠率，过滤高度相似的文档对。

</details>

**25. 预训练中使用 Pack 策略有什么好处？有没有潜在问题？**

<details>
<summary>💡 查看答案</summary>

从训练效率与数据处理角度分析：

#### Pack 策略的定义
Pack 策略（也称 Sequence Packing）是指将多条长度不一的训练样本拼接成固定长度的序列进行训练，而非对短序列进行 padding 补零。

#### 核心优势
- **消除 padding 浪费**：传统方案中，短于最大序列长度的样本需要用 padding token 填充，这些 padding 位置不携带任何有效信息，却占用了计算资源。Pack 策略通过拼接完全消除了 padding，将 GPU 算力全部用于真实 token 的计算。
- **提升硬件利用率**：在使用 Flash Attention 等高效注意力实现时，Pack 策略可以保证每个 batch 的 token 数固定且饱满，显著提升训练吞吐量。
- **训练效率提升显著**：实践中，Pack 策略可将训练速度提升 20%--50%，具体取决于原始数据集的平均序列长度与最大序列长度的比值。

#### 潜在问题
- **跨文档注意力污染**：若不加特殊处理，拼接后的序列中，后一个文档的 token 可以 attend 到前一个文档的内容，造成语义污染，影响模型对文档边界的正确建模。
- **解决方案**：引入文档内 Attention Mask（Pack Mask），确保每个 token 只能 attend 到同一文档内的 token，完全隔离跨文档信息。但这会引入额外的 mask 计算开销，且在某些 attention 实现中不易高效处理。
- **位置编码的处理**：拼接后需要对每个文档独立重置位置编码（position id 从 0 重新开始），否则模型会接收到错误的位置信息。

</details>

**26. 预训练完成后如何评估基座模型的能力？常用的 Benchmark 有哪些局限性？**

<details>
<summary>💡 查看答案</summary>

从模型评估体系角度分析：

#### 常用评估方式
- **困惑度（Perplexity）**：在留出测试集上计算语言模型的 perplexity，衡量模型对自然语言的建模质量。数值越低，说明模型对语言分布的拟合越好。
- **标准化 Benchmark**：在统一的评测框架（如 lm-evaluation-harness）下，对多个公开 benchmark 进行零样本或少样本（few-shot）评测。
- **生成质量评估**：通过人工评估或 GPT-4 作为 Judge，对模型生成内容的流畅度、准确性、有用性进行打分。

#### 常用 Benchmark
- **MMLU**：涵盖 57 个学科的多选题，测试模型的广泛知识储备。
- **HellaSwag**：常识推理和句子续写任务。
- **ARC（Challenge/Easy）**：科学问答，测试推理能力。
- **GSM8K / MATH**：数学推理能力评测。
- **HumanEval / MBPP**：代码生成能力评测。

#### Benchmark 的核心局限性
- **数据污染（Contamination）**：预训练数据中可能包含 benchmark 的测试题目或答案，导致模型在评测时实质上是在"背题"，成绩虚高，无法反映真实泛化能力。
- **饱和问题**：随着模型能力提升，许多 benchmark（如 HellaSwag）已接近人类水平甚至被超越，区分度越来越低。
- **静态与窄域**：多数 benchmark 基于固定题库，覆盖的能力维度有限，难以全面反映模型在开放场景下的实际表现。
- **评测与应用脱节**：benchmark 成绩高不等于实际应用体验好，用户真实使用场景的复杂性远超标准化测试。
- **格式敏感性**：同一道题用不同的 prompt 格式提问，模型得分可能差异显著，说明 benchmark 评分对 prompt 工程敏感，稳定性存疑。

</details>

**27. 预训练中的 Token Dropping 策略是什么？会对模型质量产生哪些影响？**

<details>
<summary>💡 查看答案</summary>

从计算效率优化角度分析：

#### Token Dropping 的定义
Token Dropping 是一种训练加速策略，其核心思想是在前向传播的中间层选择性地丢弃部分"不重要"的 token，使其不参与后续层的计算，从而减少计算量。被丢弃的 token 通常在最终层前被重新加入（通过恢复机制），以保证输出序列的完整性。

#### 代表性工作
Google 提出的 EfficientViT 和 LLM 领域的相关研究（如 TR-BERT、CoLT5）均探索了不同形式的 token 丢弃机制。其核心判断依据通常是 attention score 的大小：attention 权重低的 token 被认为对当前语境贡献小，优先被丢弃。

#### 对模型质量的影响
- **正面影响**：在丢弃率适中（如 10%--20%）的情况下，模型性能损失极小，但训练速度可提升 20% 以上，是一种较为实用的加速手段。
- **负面影响**：
    - 丢弃率过高时，被丢弃的 token 可能携带重要的语义信息，导致模型在需要精细语义理解的任务上性能下降。
    - 丢弃策略基于中间层的 attention score，而中间层的表示在训练初期不稳定，早期训练阶段的丢弃决策可能不准确。
    - 对长尾知识和低频 token 的学习可能受到更大影响，因为这些 token 原本就出现频率低，再被额外丢弃会进一步减少学习机会。

</details>

**28. 绝对位置编码和相对位置编码在长文本泛化上有何本质差异？**

<details>
<summary>💡 查看答案</summary>

从位置信息建模角度分析：

#### 绝对位置编码
- **原理**：为序列中的每个位置分配一个固定的位置向量，直接加到 token embedding 上。包括 Transformer 原始论文中的 sinusoidal 编码和 BERT/GPT 系列使用的可学习位置 embedding。
- **长文本泛化的根本缺陷**：绝对位置编码为每个绝对位置学习一个表示，当推理时序列长度超过训练时的最大长度时，模型遇到了从未见过的位置索引，无法外推，性能急剧下降。即便使用 sinusoidal 编码理论上可以外推，实践中超出训练长度后性能仍显著退化。

#### 相对位置编码
- **原理**：不编码 token 的绝对位置，而是编码 token 之间的相对距离，在 attention 计算中引入相对位置偏置。代表方法包括 T5 的 relative bias、RoPE（Rotary Position Embedding）和 ALiBi。
- **长文本泛化的优势**：
    - **RoPE**：通过旋转矩阵将相对位置信息编码进 query 和 key 的内积中，理论上可以外推到任意长度。但实践中超出训练长度后性能仍会下降，需要配合 YaRN、LongRoPE 等插值方法进行长度扩展。
    - **ALiBi**：在 attention score 上添加与相对距离成线性关系的负偏置，距离越远惩罚越大。这种设计使模型天然倾向于关注近距离 token，在训练长度内外推能力较强。
- **本质优势**：相对位置编码建模的是 token 间的相对关系而非绝对位置，模型在短序列上学到的位置关系可以更自然地迁移到长序列，具有更好的长度泛化性。

</details>

**29. 预训练数据中的有害内容如何在训练阶段进行过滤和缓解？**

<details>
<summary>💡 查看答案</summary>

从数据治理与模型安全角度分析：

#### 有害内容的主要类型
预训练数据（尤其是网络爬取数据）中常见的有害内容包括：仇恨言论、歧视性内容、色情内容、暴力内容、虚假信息、个人隐私数据（如身份证号、电话号码）等。

#### 过滤方法

**1. 基于规则的过滤**
- 使用关键词黑名单过滤包含敏感词汇的文档。
- 基于正则表达式过滤个人身份信息（PII），如邮箱地址、电话号码、身份证号。
- 设置文本质量阈值，过滤低质量（如乱码、纯广告）文档。

**2. 基于分类器的过滤**
- 训练专门的毒性分类器（如基于 fastText 或 BERT 的分类器）对文档进行打分，过滤高毒性内容。
- 使用内容安全 API（如 Perspective API）对批量数据进行毒性评分和过滤。

**3. 数据来源白名单策略**
- 优先使用经过人工审核的高质量数据源（如 Wikipedia、学术论文、书籍），降低对原始爬取数据的依赖。
- 对不同来源的数据设置不同的信任级别和采样权重。

#### 局限性与残留风险
过滤方法无法做到完全清除：关键词过滤会误伤正常内容（如历史研究相关文本）；分类器本身存在假阳性和假阴性；隐式偏见（如性别偏见、种族偏见）难以通过规则识别。因此预训练数据过滤通常与后续的 RLHF/安全微调结合使用，形成多层防护。

</details>

**30. 连续预训练和从头预训练相比有哪些优势和风险？**

<details>
<summary>💡 查看答案</summary>

从模型复用与知识保留角度分析：

#### 连续预训练（Continual Pre-training）的定义
连续预训练是指在一个已完成预训练的基座模型基础上，使用新的数据（如特定领域数据、新语言数据、更新的语料）继续进行预训练，而不是从随机初始化重新开始。

#### 核心优势
- **显著节省计算资源**：无需从头学习通用语言能力，可以在已有知识基础上快速适应新领域，训练成本远低于从头预训练。
- **知识迁移**：基座模型已经具备的通用语言理解、推理能力可以迁移到新领域，即使新领域数据量不足，也能获得较好的起点性能。
- **快速领域适配**：对于医疗、法律、金融等垂直领域，连续预训练可以在相对少量的领域数据上快速提升模型的领域专业性。

#### 主要风险
- **灾难性遗忘（Catastrophic Forgetting）**：这是连续预训练最核心的风险。当新数据与原有预训练数据分布差异较大时，模型在学习新知识的同时会快速遗忘原有的通用能力，导致在原有任务上性能大幅下滑。
- **学习率设置敏感**：连续预训练通常需要使用远小于从头训练的学习率，过大的学习率会破坏原有参数结构，过小则学习效果不佳。
- **数据配比问题**：若新数据中不混入一定比例的原始通用数据（即 replay 机制），遗忘问题会更加严重。

#### 缓解遗忘的常用策略
- **数据混合（Data Replay）**：在新数据中混入一定比例的原始预训练数据，维持对原有分布的记忆。
- **较小的学习率**：使用 warmup + cosine decay 调度，学习率峰值通常为从头训练的 1/5 到 1/10。

</details>

**31. 模型深度和宽度对预训练效果的影响有何不同？如何在两者之间做权衡？**

<details>
<summary>💡 查看答案</summary>

从模型架构设计角度分析：

#### 深度的影响
- **层次化特征提取**：更深的模型可以学习更高层次的抽象特征，底层捕捉语法和局部语义，高层捕捉推理和全局语义。
- **表达能力提升**：理论上，深度增加使模型可以表达更复杂的函数。
- **训练难度增加**：层数过多时，梯度在反向传播中需要经过更长的路径，即使有残差连接，也更容易出现训练不稳定（如梯度消失/爆炸、loss spike）。
- **推理延迟增大**：深度增加意味着串行计算的层数增多，推理时延线性增长。

#### 宽度的影响
- **表示容量增加**：更宽的模型（更大的隐层维度 $d_{model}$）可以在每一层存储更多信息，有利于知识密集型任务。
- **并行计算友好**：宽度增加主要体现在矩阵乘法维度上，可以通过 Tensor Parallelism 高效并行，推理延迟增加相对较小。
- **参数效率**：同等参数量下，宽度增加的参数效率通常低于深度增加，因为宽度平方增长的矩阵乘法可能引入冗余。

#### 权衡原则
- 根据 Scaling Law 研究，在计算预算固定时，深度和宽度需要协同增长，通常遵循经验上的深宽比（如 GPT-3 的 96 层、12288 维，LLaMA 的 32 层、4096 维）。
- 推理延迟敏感场景（如在线服务）倾向于减小深度、增大宽度，以利用 Tensor Parallelism 降低延迟。
- 训练稳定性优先时，适当控制深度，避免极深网络带来的训练困难。

</details>

**32. 预训练阶段的 Batch Size 调度策略有什么理论依据？**

<details>
<summary>💡 查看答案</summary>

从优化动力学角度分析：

#### 常见策略：从小到大的 Batch Size 调度
大模型预训练中常采用逐步增大 batch size 的调度策略：训练初期使用较小的 batch size，随着训练进行逐步增大到目标 batch size。

#### 理论依据

**1. 训练初期需要"嘈杂"的梯度**

训练初期，模型参数距离最优解较远，损失曲面粗糙。此时小 batch size 引入的梯度噪声有助于模型跳出局部极小值和鞍点，探索更广泛的参数空间，起到隐式正则化的作用。

**2. 训练后期需要精确的梯度方向**

训练后期，模型已接近收敛区域，损失曲面趋于平滑。此时需要更精确的梯度估计来稳定收敛，大 batch size 可以降低梯度方差，使参数更新方向更准确，有助于精细调整。

**3. 与学习率的联动**

根据线性缩放规则（Linear Scaling Rule），batch size 翻倍时学习率也应相应翻倍，以保持梯度更新的有效步长不变。因此 batch size 调度通常与学习率调度协同设计。

**4. 计算效率考虑**

小 batch size 在训练初期可以更快地进行参数更新（每步计算量少），在参数空间中快速移动到较好区域；大 batch size 在后期提升硬件利用率，加快训练吞吐量。

</details>

**33. 训练数据的顺序对预训练结果是否有影响？有哪些相关实验结论？**

<details>
<summary>💡 查看答案</summary>

从课程学习与数据调度角度分析：

#### 随机打乱的基准做法
大多数大模型预训练采用对训练数据进行充分随机打乱（shuffle）的方式，消除数据顺序带来的偏差，保证每个 batch 的数据分布尽量均匀，减少训练过程中的分布漂移。

#### 数据顺序影响的实验结论

**1. 课程学习（Curriculum Learning）的正向效果**

受人类学习规律启发，课程学习按照"由易到难"的顺序安排训练数据。部分研究（如在数学推理和代码任务上的实验）表明，先训练简单样本再引入复杂样本，可以加快收敛速度，并在某些任务上带来轻微的性能提升。

**2. 领域课程调度**

在多阶段预训练中，先在通用数据上预训练，再逐步引入高质量专业数据（如代码、数学），已被证明优于从一开始就混合所有数据的策略。LLaMA 3 等模型在训练后期增大高质量数据的比例，以强化特定能力。

**3. 数据顺序影响有限的结论**

另一些研究则表明，对于足够大的模型和足够多的训练数据，数据顺序对最终性能的影响相对有限，充分随机打乱已经足够。数据质量和配比的影响远大于顺序的影响。

#### 综合结论
数据顺序对预训练结果存在影响，但影响幅度相对于数据质量、配比和规模而言较小。课程学习在特定任务（数学、代码）和训练后期数据调度上具有实用价值，但并非普遍适用的银弹。

</details>
