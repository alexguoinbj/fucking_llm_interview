# 11.2 Efficient Training and Model Compression — Questions & Answers

**1. What Are the Technical Routes for Efficient Small Model Training?**

<details>
<summary>💡 Show Answer</summary>

Main technical routes for efficient small model training:

1. **Knowledge Distillation**: Use a large model (teacher) to guide small model (student) training, transferring soft labels, intermediate features, and reasoning paths (e.g., Distil-BERT, TinyLLaMA);
2. **Data-Efficient Training**: Meticulously curate high-quality small datasets (e.g., the Phi series using "textbook-quality" synthetic data), proving that data quality is far more important than quantity;
3. **Neural Architecture Search (NAS)**: Automatically search for optimal small model architectures given specific deployment constraints (e.g., transferring MobileNet and EfficientNet concepts to LLMs);
4. **Structured Pruning**: Evaluate the importance of attention heads, layers, and neurons in large models post-training and prune them, followed by fine-tuning to recover performance;
5. **Quantization-Aware Training (QAT)**: Simulate low-bit quantization during the training phase to make the model robust to quantization errors, enabling INT4/INT8 inference during deployment;
6. **Pre-training Curriculum Design**: Apply curriculum learning that transitions data from simple to complex, improving the training efficiency of small models;
7. **Task Specialization**: Forego general-purpose capabilities to focus on specific domains (e.g., code, dialogue, translation), trading breadth for specialization.

</details>

**2. What Are the Emerging Directions for Model Compression in the Future?**

<details>
<summary>💡 Show Answer</summary>

Frontier directions in model compression:

1. **Ultra-Low Bit Quantization (1--2 bit)**: BitNet b1.58 explores 1.58-bit quantization training by restricting weights to {-1, 0, +1}, drastically reducing storage and inference costs while maintaining performance;
2. **Scaling Quantization-Aware Training (QAT)**: Extend QAT to tens of billions of parameters so that quantization errors are fully compensated for during the training phase;
3. **Structured Sparsity**: Hardware-friendly N:M sparsity (e.g., 2:4 sparsity), which can be hardware-accelerated on Ampere architecture GPUs;
4. **Knowledge Distillation + Data Synthesis**: Distill small models using high-quality synthetic data generated by large models, reducing reliance on real annotated data (the success of the Phi series validated this route);
5. **Joint Optimization of Layer Pruning and Width Pruning**: Simultaneously optimize the number of layers and hidden dimensions to find the Pareto-optimal size-performance boundary;
6. **Dynamic Computational Graphs (Early Exit)**: Adaptively determine the computation depth based on input difficulty, exiting early for simple inputs while completing full computation for complex ones;
7. **Joint Design of Neural Architecture Search (NAS) and Compression**: Integrate compression constraints starting from the architecture design phase, rather than compressing post-hoc.

</details>

**3. Is Unsupervised Fine-Tuning Feasible?**

<details>
<summary>💡 Show Answer</summary>

Unsupervised fine-tuning (fine-tuning without annotated data) is an active research direction:

**Existing Feasible Solutions:**
1. **Continued Pre-training with Self-Supervised Objectives**: Use self-supervised objectives such as MLM and Next Token Prediction to continue training on domain data without annotations (Domain-Adaptive Pretraining);
2. **Contrastive Learning Fine-Tuning**: Perform contrastive learning on unannotated data to learn better representations (e.g., SimCSE uses Dropout to create positive samples);
3. **Self-Play and Self-Instruct**: The model generates instruction-response pairs by itself and then fine-tunes on them;
4. **Unsupervised Reward Modeling**: Utilize human behavioral data (clicks, dwell time) as implicit feedback to replace explicit annotations.

**Challenges:**
- Unsupervised signals may not align with downstream task objectives;
- Quality control is difficult: self-generated data may introduce noise and bias;
- Performance gains have an upper bound: unable to break through the model's knowledge boundaries.

**Conclusion:** Unsupervised fine-tuning is feasible for domain adaptation and representation learning, but still requires the assistance of supervised signals for task specialization and alignment.

</details>

**4. How Is Knowledge Distillation Applied in Large Model Training?**

<details>
<summary>💡 Show Answer</summary>

The basic idea of Knowledge Distillation is to use the output (soft labels/logits distribution or intermediate layer features) of a large model (Teacher) to guide the training of a small model (Student), enabling the Student to approximate the capabilities of the Teacher with a significantly smaller parameter count.

**Common Forms in Large Model Scenarios:**
1. **Output-Layer Distillation**: Train the Student to match the Teacher's output probability distribution (e.g., by minimizing the KL divergence between them), which contains more "dark knowledge" (relative relationships between different classes/tokens) compared to pure one-hot labels;
2. **Data Distillation**: Use the Teacher model to generate a large volume of high-quality training data (including detailed reasoning steps), and then perform SFT on the Student using this data. This is currently the most commonly used and engineering-wise simplest and most direct approach in LLM distillation;
3. **Intermediate-Layer / Attention Distillation**: Align the hidden states or attention distributions of the Teacher and Student, commonly used in compression scenarios with identical architectures and clear layer-to-layer correspondences.

**Challenges:** When the Student's capacity is limited, it cannot fully replicate all capabilities of the Teacher. The domain coverage and diversity of the distillation data directly determine the upper bound of the Student's capabilities.

**5. What Are LoRA / QLoRA? How Do They Reduce Fine-Tuning Costs?**

<details>
<summary>💡 Show Answer</summary>

**LoRA (Low-Rank Adaptation):** Freezes the pre-trained weights $W$ and introduces low-rank decomposition matrices $\Delta W = BA$ ($B \in \mathbb{R}^{d\times r}$, $A \in \mathbb{R}^{r\times k}$, $r \ll d, k$) in a side path. Only $A$ and $B$ are updated during training, significantly reducing the number of trainable parameters (typically down to 0.1%--1% of original parameters).

**Advantages:**
- VRAM footprint is drastically reduced as there is no need to store gradients and optimizer states corresponding to the original weights;
- During inference, $BA$ can be merged back into the original weights without introducing extra inference latency;
- Multiple independent sets of LoRA weights can be trained for different tasks and loaded/swapped on demand, facilitating multi-task/multi-tenant scenarios.

**QLoRA:** Building upon LoRA, it further quantizes the base model to 4-bit (e.g., the NF4 data type) and combines Double Quantization with Paged Optimizers to further reduce VRAM consumption, making it possible to fine-tune multi-billion-parameter models on a single consumer-grade GPU.

**Limitations:** The choice of rank $r$ affects the performance upper bound; when task differences are large or fundamental model capabilities need to be altered, LoRA's expressiveness may be insufficient, still requiring full-parameter fine-tuning.

**6. What Is the Difference Between Structured Pruning and Unstructured Pruning?**

<details>
<summary>💡 Show Answer</summary>

**Unstructured Pruning:** Zeroes out individual weights independently based on their importance (e.g., magnitude). It offers fine pruning granularity and high theoretical compression ratios, but produces irregular sparse matrices that are difficult to accelerate on general-purpose hardware (GPUs), requiring specialized sparse computing libraries to achieve performance gains.

**Structured Pruning:** Removes entire structural units such as channels, attention heads, or layers. The pruned model remains a dense matrix, directly yielding inference speedup and memory savings, which makes engineering deployment much easier.

**Trade-offs:**
- Structured pruning has a coarser granularity, and its accuracy loss is usually larger than that of unstructured pruning at the same compression ratio;
- In practice, the two are often combined, or pruning is followed by a small amount of continued training (fine-tuning / knowledge distillation) to recover accuracy;
- In large model scenarios, structured pruning is preferred (e.g., pruning attention heads, MLP intermediate dimensions, or even entire layers) because it is more hardware-friendly for inference, directly translating into actual latency and memory benefits.

</details>

**7. What Are the Core Ideas of Current Mainstream Quantization Schemes (GPTQ / AWQ / FP4, etc.)?**

<details>
<summary>💡 Show Answer</summary>

Model quantization compresses weights (and sometimes activations) from FP16/BF16 into lower-bit representations (INT8/INT4/FP4) to reduce memory footprint and memory access overhead.

- **GPTQ**: A layer-by-layer quantization method based on second-order information (approximate Hessian). When quantizing the weights of a given layer, it utilizes the gradient information of unquantized weights to compensate for the error introduced by quantized weights, achieving minimal accuracy loss under Post-Training Quantization (PTQ) without requiring retraining;
- **AWQ (Activation-aware Weight Quantization)**: Observes that not all weights are equally important to accuracy; rather, weight channels multiplied by larger activation magnitudes are more critical. Thus, AWQ analyzes activation distributions to perform protective scaling on a small subset of "salient weight channels" prior to uniform quantization, thereby preserving critical accuracy with almost no added computational overhead;
- **FP4 / MXFP4 and Other Emerging Low-Precision Formats**: Compared to traditional INT4 which uses a uniform integer quantization step size, floating-point formats retain exponent bits within a small dynamic range, better representing the long tail of numerical distributions. Supported by corresponding hardware Tensor Cores (such as the Blackwell architecture), they yield lower accuracy loss at similar bit widths.

**Common Trade-off:** Lower quantization bit-widths provide greater memory and bandwidth benefits, but cause more pronounced damage to model capabilities (especially complex reasoning and long-chain tasks). It is usually necessary to combine calibration datasets with layer-by-layer sensitivity analysis to decide which layers can be quantized to lower precision and which layers must retain higher precision.

</details>

**8. What Are the Advantages and Risks of FP8 Mixed-Precision Training Compared to BF16 Training?**

<details>
<summary>💡 Show Answer</summary>

**Advantages:** Compared to BF16, FP8 further reduces the storage bit-width of each numerical value, theoretically offering nearly a 2x boost in computational throughput and memory savings. In pre-training at the scale of thousands or tens of thousands of GPUs, this efficiency improvement directly translates into substantial cost reductions (the significant training cost reduction of models like DeepSeek-V3 is related to such technologies).

**Risks and Mitigation:**
- FP8 has a much smaller dynamic range than FP32/BF16, making it prone to numerical overflow or underflow during training, especially since gradients and optimizer states are more sensitive to precision;
- Common mitigation strategies include: using fine-grained, per-tensor or per-block dynamic scaling factors for different tensors (weights, activations, gradients); and maintaining higher precision for critical paths (such as optimizer states, normalization layers, and loss computation);
- Training stability requires additional monitoring mechanisms (e.g., overflow detection and automatic fallback to high-precision recomputation) as a safety net, resulting in significantly higher engineering complexity than pure BF16 training.

</details>

**9. What Are the Advantages of ZeRO Series Optimizer State Sharding Compared to Traditional Data Parallelism?**

<details>
<summary>💡 Show Answer</summary>

In traditional Data Parallelism (DP), every GPU maintains a complete copy of model parameters, gradients, and optimizer states, leading to high memory redundancy. As model scale grows, this redundancy waste becomes increasingly severe (in particular, the momentum and variance states of Adam-like optimizers often exceed twice the parameter count).

**Core Idea of ZeRO:** Progressively shard optimizer states, gradients, and parameters across different GPUs in stages:
1. **ZeRO-1**: Shards only optimizer states; each GPU stores and updates only its assigned partition of the states;
2. **ZeRO-2**: Further shards gradients on top of ZeRO-1;
3. **ZeRO-3**: Shards the model parameters themselves; during forward/backward passes, each GPU temporarily fetches the required layer parameters via All-Gather and releases them immediately after use.

**Cost:** A higher degree of sharding leads to greater memory savings, but also increases communication overhead (All-Gather / Reduce-Scatter). Therefore, ZeRO-3 typically requires high-bandwidth interconnects (such as NVLink) to prevent communication from becoming a new bottleneck. In practice, it is often combined with Tensor Parallelism and Pipeline Parallelism, selecting an appropriate sharding combination based on the cluster topology.

**10. How Does Activation Checkpointing Balance Memory and Computation During Training?**

<details>
<summary>💡 Show Answer</summary>

Saving all intermediate activation values during the forward pass for use in the backward pass consumes a massive amount of memory, especially when models are deep and sequences are long. The idea of Activation Checkpointing is to save activations only at a few key "checkpoints", while re-computing the remaining activations via **an extra forward pass** when needed during the backward pass, trading computation for memory.

- **Selective Recomputation**: Not all sub-layers are worth recomputing. Typically, operations with light computation but heavy memory footprint (such as intermediate tensors in Attention) are prioritized for recomputation, while activations of heavy computational operations (such as large matrix multiplications) are retained, achieving a better trade-off between added compute overhead and saved memory;
- **Typical Cost**: Full recomputation usually increases training time by approximately 20%--30% in exchange for a several-fold savings in memory. This trade-off enables training larger models or using larger batch sizes on given hardware.

</details>

**11. What Is the Value of Curriculum Learning in Large Model Training?**

<details>
<summary>💡 Show Answer</summary>

Curriculum Learning refers to organizing training data or tasks in order from easy to hard and simple to complex, rather than randomly shuffling them.

**Applications in Large Model Training:**
- **Data Difficulty Curriculum**: As in the aforementioned method of "evaluating data difficulty and value using small validation models," high-quality and moderately difficult data are prioritized during the early pre-training stage, while harder and more long-tailed data are gradually introduced in later stages;
- **Sequence Length Curriculum**: Long-context training typically adopts a progressive "short-to-long" strategy, first training on shorter sequences to build baseline capabilities before gradually extending to the target length. This both improves training efficiency (shorter sequences train faster) and contributes to the stability of long-sequence training;
- **Task Difficulty Curriculum**: In reasoning capability training (the RL phase), transitioning progressively from simple problems to high-difficulty problems helps prevent the model from failing to learn effectively in early training due to overly sparse reward signals (nearly all attempts failing).

**Caveats:** Curriculum design requires reliable difficulty assessment methods. If the difficulty evaluation itself is biased, curriculum learning may backfire (e.g., exposing the model prematurely to samples beyond its current capability, causing training instability).

</details>

**12. What Are the Risks of Training Large Models on Synthetic Data? What Is "Model Collapse"?**

<details>
<summary>💡 Show Answer</summary>

As high-quality real data becomes increasingly scarce, more and more training pipelines introduce synthetic data generated by the model itself (or by other models).

**Mechanism of Model Collapse:** If the output of one generation of models is extensively used as training data for the next generation, and this process iterates repeatedly, the model will gradually "forget" low-probability tail information in the real data distribution, retaining and reinforcing only high-probability regions. After multiple iterations, the diversity of generated content collapses while errors are continuously amplified and cemented. This phenomenon is known as model collapse.

**Mitigation Methods:**
- Maintain a hybrid training mix of synthetic data and real data, rather than completely replacing real data;
- Apply strict quality filtering and diversity control to synthetic data (such as evaluating value using small validation models mentioned earlier), rather than using it indiscriminately;
- Introduce external verification signals (e.g., execution results of runnable code, answer validation of math problems) to ensure the correctness of the synthetic data itself, rather than relying purely on a closed loop of self-generation and self-training.

</details>

**13. What Is Test-Time Training (TTT)? How Does It Differ from Test-Time Compute?**

<details>
<summary>💡 Show Answer</summary>

Test-Time Compute (such as multiple sampling + verifier selection) performs only **forward inference** at test time without updating any model parameters; in contrast, **Test-Time Training** temporarily adapts the model (or a subset of parameters, such as LoRA adapters) for the current input sample during the inference phase using a few gradient update steps, fitting the model better to the distribution characteristics of the current sample. Once inference is complete, these temporary updates are typically discarded or reset.

**Applicable Scenarios:** For tasks with significant distribution shift or strong intra-sample local patterns (e.g., specific in-context patterns in long texts, structured data reasoning), TTT can achieve better in-sample adaptation than pure in-context learning.

**Cost:** Every sample incurs extra forward and backward propagation overhead, making inference latency and cost significantly higher than standard inference. Currently, it is mostly used in latency-insensitive, accuracy-critical scenarios rather than low-latency online services.

</details>

**14. What Is Model Merging? What Are Its Advantages Compared to Ensemble Learning?**

<details>
<summary>💡 Show Answer</summary>

Model Merging refers to directly combining the parameters of multiple models trained from the same base model with different capability focuses (e.g., versions fine-tuned separately on code, mathematics, and dialogue) via weighted averaging or more complex interpolation methods, obtaining a single model that fuses multiple capabilities without retraining.

- **Simple Weighted Averaging (Model Soup)**: Directly takes the (weighted) average of parameters across multiple models with near-zero cost, achieving better generalization than a single model in many scenarios;
- **Task Vectors Addition and Subtraction**: Treats "fine-tuned model parameters minus base model parameters" as a maneuverable vector, combining vectors of different tasks through addition and subtraction to create models with multi-task capabilities or to eliminate specific unwanted behaviors;
- **Advantages Over Ensemble**: Ensembling requires running multiple models simultaneously during inference, causing costs to scale linearly with the number of models; in contrast, Model Merging produces only a single model, keeping inference costs identical to a single model. The trade-off is that merging efficacy depends on the compatibility of parameter spaces across models (typically requiring them to be fine-tuned from the same base model without excessive parameter drift).

**15. Besides LoRA, What Are Other Mainstream Parameter-Efficient Fine-Tuning (PEFT) Methods? What Are Their Respective Core Ideas?**

<details>
<summary>💡 Show Answer</summary>

- **Prefix Tuning**: Prepends a trainable "virtual prefix" vector to the Key/Value at each Attention layer while freezing the main model parameters and training only these prefix parameters, equivalent to injecting a learnable soft prompt into the model;
- **Adapter**: Inserts small bottleneck structures (a two-layer MLP that first projects down and then up) after each Transformer sub-layer, training only these newly added Adapter modules while keeping original parameters frozen;
- **Prompt Tuning**: Prepends trainable soft prompt tokens only at the input embedding layer. It has the smallest parameter count among these methods but heavily relies on model scale (matching full-parameter fine-tuning performance only on massive models);
- **BitFit**: Fine-tunes only the bias parameters in the model while freezing everything else. It has an extremely tiny parameter count with a relatively limited performance upper bound, but excels in being exceptionally lightweight;
- **Comparison with LoRA**: LoRA approximates weight updates via low-rank matrix decomposition without introducing additional inference latency (since low-rank matrices can be merged directly back into original weights). This is a major advantage over Adapter/Prefix Tuning (which introduce extra forward computation paths) and is why LoRA is currently the most widely adopted PEFT method in industry.

</details>
